# Thai per-frame render overhead in `_sanitize_and_invalidate_sara_am`, `_patched_copy_body`, and Visual Block `_thai_selection_range_at_line`

**Category:** performance / rendering · **Area:** `vith/thai/patches.py` · **Found at:** Round 10 deep performance audit (2026-11-22, `v0.15.1` / rev 392) · **Fix status:** open

## Summary

Profiling a 50×160 Thai wrapped viewport shows three hot loops in `vith/thai/patches.py` consuming ~40%+ of frame time (in addition to `TabsProcessor` in [156](156.md)):[^src-patches]

1. **`_sanitize_and_invalidate_sara_am` (`vith/thai/patches.py:365-410`):**
   - Copies `list(new_row.items())` on every row (unnecessary: assigning `new_row[x] = ...` for an existing key never alters dict size/keys) and eagerly allocates `sara_am_xs: set[int] = set()` even on rows without SARA AM.
   - Re-scans every cell of `prev_row` on every frame (11,392 `_cell_has_sara_am` function calls/frame) even though `previous_screen` was already scanned as `new_screen` on the prior frame.
2. **`_patched_copy_body` (`vith/thai/patches.py:564-610`):**
   - Whenever any visible row has a non-ASCII character touching the right margin, copies the entire `rowcol_to_yx` dict (~8,000 cells) via `list(rowcol_to_yx.items())` and performs `data_buffer.get(sy, {}).get(sx)` + `isinstance(..., dict)` for every column of `candidate_rows` **before** checking `sx == right_x` / `sx == right_x - 1`.
3. **`_thai_selection_range_at_line` & `_document_tabstop` (`vith/thai/patches.py:119-145, 935-973`):**
   - On every visible row during Visual Block selection, calls `orig(self, row)` (45% of time, discarded except for an EOL check), `translate_index_to_position` 8×/row, `_document_tabstop` 1×/row, and `_cell_columns` 5×/row.
   - `_document_tabstop` calls `get_app()`, which instantiates a full `DummyApplication` (~5 ms each) whenever called outside a running `Application` (e.g., standalone `Document` calls or unit tests).

## Evidence

Measured on `Python 3.15.2` / `prompt_toolkit 3.0.53` (50×160 viewport):

| Hot spot | Current | Optimized / Baseline | Speedup |
| :--- | ---: | ---: | :--- |
| `_sanitize_and_invalidate_sara_am` (50×160 Thai) | **1.640 ms/frame** (23.1% of Thai frame) | **0.372 ms/frame** | **4.41× faster** |
| `_patched_copy_body` overhead (50×160 Thai wrapped) | **+1.39 ms/frame** (`8.68` vs `7.29 ms`) | near-zero overhead | **>5×** |
| `_thai_selection_range_at_line` (50 Thai+tab rows, in `set_app`) | **1.166 ms/frame** (5k calls: 40k `translate_index`, 25k `_cell_columns`) | single `_cell_columns` + cached bounds | **~8–10×** |
| `_thai_selection_range_at_line` (50 rows, outside `set_app`) | **261–729 ms** (`DummyApplication` per `get_app()`) | < 1 ms | **>250×** |

## Fix Direction

1. In `_sanitize_and_invalidate_sara_am`: iterate `new_row.items()` directly without `list()`, lazily create `sara_am_xs`, inline the ASCII/`\u0e33`/`\u0eb3` check, and store per-row SARA AM columns on `new_screen._vith_sara_am_rows` so the next frame reads `prev_row`'s SARA AM columns in $O(1)$ without re-scanning `prev_row` (falling back to scanning `prev_row` if `previous_screen` was not previously processed).[^src-patches]
2. In `_patched_copy_body`: iterate `rowcol_to_yx.items()` without copying into `list()`, filter `if (sx == right_x or (width >= 2 and sx == right_x - 1)) and sy in candidate_rows:` **first**, collect only the ≤ `height` candidate `(lineno, col, sy, sx)` hits, and perform the right-margin merge and `rowcol_to_yx` re-insertion over those hits only.[^src-patches]
3. In `_document_tabstop`: use `get_app_or_none()` instead of `get_app()` (avoiding `DummyApplication` construction). In `_thai_selection_range_at_line` and `_thai_selection_ranges`: cache `(from_line, to_line, v_low, v_high, ts)` on the immutable `Document` (using a weak/cache slot on `self._cache`), skip `orig(self, row)` for `SelectionType.BLOCK` (reproducing the EOL-space condition directly), and call `_cell_columns(line, ts)` at most once per row.[^src-patches]
