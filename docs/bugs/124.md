# No `:next` / `:previous` commands to cycle files

**Category:** Vim semantics · **Area:** `vith/commands/commands.py`, `vith/commands/grammar.py` · **Found at:** user field report, 2026-11-09 · **Fix status:** fixed

## Summary

Opening many files (`vith -p file1 file2 ...`) leaves no `:next` / `:previous` (Vim arglist navigation) to step through them. Only `:bn` / `:bp` exist.

## Evidence

* `vith/commands/commands.py:203-219`[^src-cmd] registers `:bn` / `:bp` only; no `next` / `previous` / `n` / `N` / `prev` handler exists in `COMMANDS_TO_HANDLERS`.
* The grammar generic branch (`vith/commands/grammar.py:44`[^src-grammar]) parses `:next` fine, but `handle_command()` reports `Not an editor command: next`.
* The completer is dynamic (`create_command_completer()` lists `get_commands()`), so registering handlers is sufficient for completion.

## Impact

* Multi-file workflows force `:bn` / `:bp` / `:b <pattern>`; Vim users expect `:n` / `:N`.

## Fix

* `vith/commands/commands.py` registers `:next` / `:n` (forward) and `:previous` / `:prev` / `:N` (backward) with `accepts_force=True`, reusing the `:bn` / `:bp` unsaved-changes guard and buffer-list cycling. No grammar change was needed (generic branch parses them; completion is dynamic).
* Regression tests in `tests/test_quit_and_goto.py`: forward/backward cycling with wrap-around and alias coverage, dirty-buffer guard plus `:next!` override.
