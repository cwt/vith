# Visual highlight crossing rows crashes (`v` + `j`): line-relative ↔ absolute mix-up in `selection_range_at_line`

**Category:** wrong logic / coordinate-space confusion · **Area:** `vith/thai.py` (`_thai_selection_range_at_line`) · **Found at:** user bug report 2026-11-08, hg rev 266 · **Fixed at:** hg rev 267

## Summary

`prompt_toolkit.layout.processors.HighlightSelectionProcessor` renders the selection highlight per row:

```python
selection_at_line = document.selection_range_at_line(lineno)   # LINE-RELATIVE columns
if selection_at_line:
    from_, to = selection_at_line
    to = source_to_display(to)   # ← KeyError: `to` must be a key of the row's mapping
```

`Document.selection_range_at_line` (prompt_toolkit, `document.py:954`) returns **line-relative columns** `(from_column, to_column)`, while `Document.selection_ranges` returns **absolute indices** — two different coordinate spaces. Vith's Thai-aware wrapper `_thai_selection_range_at_line` honored the first contract with the second:

```python
start, end = res            # relative columns
last_idx = end - 1
r, col = self.translate_index_to_position(last_idx)      # treated `end` as absolute → wrong row
...
new_end = self.translate_row_col_to_index(r, cluster_end_col)
end = new_end              # ABSOLUTE substituted for a LINE-RELATIVE column
```

* On **row 0** line-relative == absolute, so the wrapper behaves correctly — “highlight to the right is OK” exactly as reported.
* On **any later row** (`v` then `j`) the extension is computed on the wrong row and the returned `end` may leave the row's `position_mappings` key range → `KeyError` in `processors.py:744 source_to_display` (traceback: `HighlightSelectionProcessor.apply_transformation` → merged processor → `source_to_display`).

## Evidence

* [`vith/thai.py` (`_thai_selection_range_at_line`, pre-fix)](../../vith/thai.py) — `last_idx = end - 1` / `translate_index_to_position` / `translate_row_col_to_index` on relative inputs.
* prompt_toolkit `document.py:954-1005` — returns `from_column, to_column` (row-relative); `document.py:904` `selection_ranges` — yields absolute indices.
* prompt_toolkit `layout/processors.py:287-292` — consumer that does `source_to_display(to)` directly on the returned columns.
* User report: `v` + horizontal highlight OK; `v` + `j` crash with a `KeyError` inside the renderer redraw.

## Fix

The wrapper now works purely in line-relative coordinates: snap the *last selected cell* (`end - 1`, bounded by `len(line)`) forward to the end of its enclosing cell cluster via `next_cell_offset(line, cursor_col, 1)` when it sits on a combining mark; everything stays inside the row. `_thai_selection_ranges` (the absolute-contract wrapper used by `y`/delete) was audited and kept as-is.

## Tests

* `tests/test_thai.py::test_selection_range_at_line_is_line_relative` — row-1 cluster `[ปั้]` extension over the trailing `้` stays line-relative `(0, 3)`; the vi-EOL row `(0, len+1)` passes through unchanged (no absolute mangling); the relative bounds hold for every covered row.
* Full real-render sweep (prompt_toolkit `HighlightSelectionProcessor` chain, gate latched, 3 selection types × all corner/cursor pairs) — zero crashes (was: crash on any row > 0 with CHARACTERS selection).
