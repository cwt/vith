# Visual mode (`v`) slices Thai/Lao cell clusters in half and ignores cell-cluster motions

**Category:** wrong logic / Thai support · **Area:** `vith/thai.py`, `vith/key_bindings.py` · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

In `prompt_toolkit`, entering Visual mode (`v`, `V`, `<C-v>`) sets `app.current_buffer.selection_state`, which makes `vi_selection_mode()` `True` and `vi_navigation_mode()` `False`. Two separate assumptions in the Thai cell-cluster implementation break Visual mode on Thai/Lao text:

1. `Document.selection_ranges` (`prompt_toolkit/document.py:1012-1013`) and `Document.selection_range_at_line` (`prompt_toolkit/document.py:1058-1059`) implement Vi inclusive selection by adding `+ 1` codepoint (`to += 1` / `to_column += 1`) instead of advancing to the end of the cell cluster (`next_cell_offset(line, to_col, 1)`), and neither method is wrapped by `install_prompt_toolkit_thai_patches()`[^src-thai].
2. Both `_kp_fix_vi_cursor_position` (`vith/thai.py:845`)[^src-thai] and the custom `$`, `e`, `E` bindings (`vith/key_bindings.py:283, 304, 311`)[^src-kb] are gated solely on `vi_navigation_mode()`, so in Visual mode cursor snapping is disabled and `$`, `e`, `E`, `ge`, `gE` fall back to upstream `prompt_toolkit/key_binding/bindings/vi.py` handlers that land on combining marks.

## Evidence

* **Live probe (`v` then `d` on `"ที่ดิน"` at column 0)**:
  ```text
  Initial buffer: "ที่ดิน" (['ท', '◌ี', '◌่', 'ด', '◌ิ', 'น']), cursor_position = 0
  Keys fed:       'v', 'd'
  Result buffer:  "ี่ดิน" (['0xe35', '0xe48', '0xe14', '0xe34', '0xe19'])
  ```
  `Document.selection_ranges()` computes `[0, 1)`, deleting only the base consonant `'ท'` (`U+0E17`) and leaving the combining marks `'◌ี'` (`U+0E35`) and `'◌่'` (`U+0E48`) orphaned at the start of the line.
* **Post-handler cursor snap skips Visual mode** ([`vith/thai.py:842-860`](../../vith/thai.py)[^src-thai]):
  ```python
  def _kp_fix_vi_cursor_position(self) -> None:
      """Snap the cursor off any combining mark and off the EOL newline in
      Vi navigation mode (replaces upstream `cursor_position -= 1` clamp).
      """
      if not vi_navigation_mode():
          return
  ```
* **Motion overrides exclude `vi_selection_mode`** ([`vith/key_bindings.py:283, 304, 311`](../../vith/key_bindings.py)[^src-kb]):
  * `$` (`line_end_cell`), `e` (`word_end_forward`), and `E` (`bigword_end_forward`) use `filter=vi_navigation_mode & ~vi_waiting_for_text_object_mode`.
  * In `vi_selection_mode`, pressing `v` then `e` on `"ที่ดิน น้ำ"` runs upstream `prompt_toolkit/key_binding/bindings/vi.py:1286` (`cursor_position += end - 1`), placing the cursor on `'◌่'` (index 2), and `Document.selection_ranges` then adds `+ 1` codepoint instead of the full cell cluster.

## Impact

Visual selection (`v`/`V`/`<C-v>`) coupled with any operator (`d`, `c`, `y`, `x`) or motion (`l`, `e`, `E`, `ge`, `gE`, `$`) corrupts Thai and Lao text by slicing base consonants away from their upper/lower vowels and tone marks.

## Fix direction

1. In `vith/thai.py`, wrap `Document.selection_ranges` and `Document.selection_range_at_line` (when `_THAI_GATE.value` is active and the line is non-ASCII) so the inclusive upper bound advances to `next_cell_offset(line, col, 1)` rather than `to + 1` / `to_column + 1`.
2. In `_kp_fix_vi_cursor_position`, snap combining marks when `vi_navigation_mode() or vi_selection_mode()` (while keeping the EOL clamp for `vi_navigation_mode()`).
3. Include `vi_selection_mode` (or convert `$`, `e`, `E` to `@text_object` / motion handlers active in both navigation and selection modes) in `vith/key_bindings.py`.
