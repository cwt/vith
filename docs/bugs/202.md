# `HttpIO.read` unbounded network call

**Category:** I/O / http · **Area:** `vith/io/backends.py` · **Found at:** Round 17 read-only re-audit (2026-11-23, `v0.16.4`) · **Fix status:** open

## Summary

`HttpIO.read()` does `urllib.request.urlopen(location)` with no `timeout`, no `User-Agent`/headers, and no `URLError`/`HTTPError` → message translation.[^src] A slow or black-holed host blocks the TUI indefinitely (no cancellation path), and DNS/404 failures raise raw stdlib exceptions instead of the editor's `E484`-style message used by the file backends.

## Evidence

* `vith/io/backends.py:204-210` — bare `urlopen(location)` in a `with` block, then `_auto_decode`.
* No `timeout=` parameter, no `Request(...)` headers, no `try/except URLError` in the module.

## Fix Direction

1. Add a finite timeout (e.g. `timeout=10`) and a `User-Agent` request header.
2. Catch `urllib.error.URLError`/`HTTPError` and surface via `editor.show_message`/buffer error state instead of propagating.
3. Regression tests with mocked `urlopen` asserting timeout use and error mapping.
