# Unguarded None-invariants: empty `TabPage` and `current_editor_buffer`

**Category:** wrong logic / invariant by convention · **Area:** `vith/window_arrangement.py`, `vith/editor.py`, `vith/key_bindings.py`, `vith/layout.py` · **Found at:** deep review, hg rev 87de3a3 (2026-11-08) · **Re-validated:** 2026-11-08 at hg rev 251 (tip; code identical to the audit revision)

## A. `TabPage` can be left empty (`VSplit([])`, `active_window = None`)

### Summary

`TabPage.close_active_window` deletes the active window from its split and sets `active_window = None` when the root split empties ([`vith/window_arrangement.py:169-194`](../../vith/window_arrangement.py)[^src-wa], `:186`). The invariant “a `TabPage` is never empty” is enforced only by `WindowArrangement.close_window` (`:257-273`: window-count check → `close_tab` or `E444: Cannot close last window`). Other callers bypass it:

* `WindowArrangement.close_buffer` (`:485`) calls `self.active_tab.close_active_window()` directly.
* `TabPage.cycle_focus` (`:196-202`) does `windows.index(self.active_window)` → `ValueError` when `None` (reachable via `C-w C-w`, `key_bindings.py:147-150`).
* `EditorLayout.update` will build a prompt_toolkit `VSplit([])` for the empty root (`layout.py:619-630`).

Residual fragility from [040](040.md)/[041](041.md), both fixed at the `WindowArrangement` layer, not the `TabPage` layer. Additionally, `close_buffer`'s tab-removal bookkeeping iterates the snapshot `self.tab_pages[:]` while mutating the live list, comparing the snapshot index `i` against the live `active_tab_index` (`:488-496`, `i <= active_tab_index → max(0, active_tab_index - 1)`) — correct by accident for single-tab closes, fragile for multi-tab multi-window closes.

### Validated failure trace (strengthened, 2026-11-08)

Tabs `[T0, T1, T2]`, active index `2`, the wiped buffer visible in `T0` and `T2` (`:bd` maps to `close_buffer` via `commands.py:290-300`):

* `i=0`: `T0` emptied → removed, `0 <= 2` → `active_tab_index = 1`.
* `i=1`: `T1` untouched.
* `i=2`: `T2` emptied → removed, but `2 <= 1` is false → **no decrement**.
* End state: `tab_pages == [T1]`, `active_tab_index == 1` → the `active_tab` property (`:228-232`, `self.tab_pages[self.active_tab_index]`) raises `IndexError` on the next access.

## B. `current_editor_buffer` returns `None` unguarded

### Summary

[`vith/editor.py:225-241`](../../vith/editor.py)[^src-ed] — the property resolves `self.application.current_buffer` (`:230`), takes the fast path `active_editor_buffer` when it matches (`:232-235`), otherwise linear-searches `window_arrangement.editor_buffers` (`:238-240`) and **implicitly returns `None`** on no match (transient focus on the command/search buffer, layout mid-update). `key_bindings.open_path` (file-explorer `<Enter>`, [`key_bindings.py:188-201`](../../vith/key_bindings.py)[^src-kb]) reads `editor.current_editor_buffer.location` with no guard, and the sibling `to_parent_directory` (`:203-208`) too — while `layout.ReportMessageToolbar` explicitly guards the same situation (`layout.py:347-351`, `if eb is None: return []`).

### Validation refinements (2026-11-08)

* The `<Enter>` crash claimed in the original finding is **not reachable today**: both file-explorer bindings carry `filter=in_file_explorer_mode` (`key_bindings.py:182-186`), and that filter is written as `bool(editor.current_editor_buffer and ...)`. Prompt_toolkit evaluates binding filters immediately before dispatching the handler in the same pass (`key_processor.py:130`), so `open_path` never runs while the property is `None`. The unguarded body remains a contract for *future* callers.
* The `commands.compression` caller named in the original finding does not exist (cold-text compression is a configuration attribute, `editor.py:67`) — removed.
* `commands.substitute` (`commands.py:757-761`) does dereference the property unguarded, but the command accept handler calls `leave_command_mode(...)` *before* executing handlers (`editor.py:103-112`), restoring pane focus, so `:s` resolves the fast path today.

## Impact

* **A:** closing the last window of a tab via `:bd`/`:bw` (or `close_editor_buffer` across tabs) can raise `ValueError` from focus cycling or the validated `IndexError` from tab bookkeeping (order-dependent), and `EditorLayout.update` can render an empty split.
* **B:** no known crash path today; the `None` fall-through is an undocumented contract that any future caller (including the unguarded `open_path`) inherits.

## Fix direction

Move the invariant into `TabPage`: `close_active_window` returns whether the tab became empty (or refuses to empty it), and `cycle_focus` no-ops on empty/singleton. Rewrite `close_buffer`'s tab-removal loop to iterate reversed (or track tab *objects*, not snapshot indices). Make `open_path`/`to_parent_directory` early-return on `None` (and audit other `current_editor_buffer` callers), or have the property document/raise a descriptive `NoActiveBufferError`.

## Fix record (2026-11-08, hg rev 256)

* **A:** `TabPage.close_active_window` now returns whether the tab emptied, `cycle_focus` no-ops on an empty tab, and `close_buffer` rewrites its tab-removal bookkeeping to track the active tab as an *object* (with an index clamp for the removed-active-tab case) instead of snapshot-index arithmetic — the traced `IndexError` scenario now lands on the correct surviving tab.
* **B:** `open_path` and `to_parent_directory` early-return when `current_editor_buffer` is `None`.
