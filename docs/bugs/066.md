# Legacy `DocumentLexer` fallback leaks `ClassNotFound` and rebuilds the lexer per frame

**Category:** wrong logic + unoptimized · **Area:** `vith/lexer.py` (`DocumentLexer.lex_document`) · **Found at:** deep review, hg rev 87de3a3 (2026-11-08)

## Summary

`_STREAMING_AVAILABLE` requires prompt_toolkit ≥ 3.0.35, but `pyproject.toml` permits `prompt_toolkit>=3.0.0,<3.1.0`. On older prompt_toolkit the lexer takes the fallback branch, which (1) lets `ClassNotFound` escape to the renderer for unknown extensions, and (2) constructs a fresh `PygmentsLexer` on every `lex_document` call (i.e. every frame), paying a registry scan per keystroke.

The streaming branch caches (`_cached_location`, `_ensure_lexer`) and degrades to `SimpleLexer`; the fallback does neither.

## Evidence

* [`vith/lexer.py:110-120`](../../vith/lexer.py)[^src-lexer]:
  ```python
  if not _STREAMING_AVAILABLE:
      return PygmentsLexer.from_filename(location, ...).lex_document(document)  # no try, no cache
  if self._cached_location != location or ...:
      if not self._ensure_lexer(location): return SimpleLexer()...
  ```

## Impact

* Crash (not fallback) on `prompt_toolkit < 3.0.35` for any file type Pygments cannot guess.
* ~0.6 ms registry scan per frame (the exact cost [030](030.md) fixed for the directory lexer) for all normal files on the fallback path.

## Fix direction

Unify both branches through `_ensure_lexer` + cache; wrap `from_filename` with `try/except ClassNotFound → SimpleLexer`, or cache the directory-lexer style (`_get_directory_lexer`).
