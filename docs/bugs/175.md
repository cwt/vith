# Bare `:%s` reuses the wrong pattern

**Category:** commands / substitute · **Area:** `vith/commands/substitution.py`, `vith/commands/global_cmd.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** fixed
> **Resolution note (2026-11-23):** Added `editor.last_substitute_pattern` so a bare `:s` repeats the last substitution regardless of intervening `/` searches or `:g`.


## Summary

When no pattern is supplied, `substitute()` reads
`search = search_state.text`,[^src-sub] and `_record_substitute_state()` writes
the last substitute pattern into that same shared slot.[^src-sub] The `/` search
binding, `*`/`#` ([168](168.md)), and `:g`/`:v`[^src-global] all assign
`current_search_state.text`, clobbering the substitution history. Vim keeps the
last substitute pattern/replacement separate from the last search pattern, so
a bare `:s` must repeat the *substitution*, not the latest search.

## Evidence

Probe on a buffer containing `aaa bbb aaa`:

1. `:s/a/X/` → `Xaa bbb aaa` (substitute state recorded: pattern `a`, replacement `X`).
2. Set the search state to `b` (equivalent to pressing `/b`).
3. `:%s` → vith produces `Xaa Xbb aaa` — it reused pattern `b` with old
   replacement `X`. Vim would reuse pattern `a` (and replacement `X`), leaving
   the `bbb` cell untouched.

The same happens after `:g/foo/d`, which also writes the shared search state.

## Fix Direction

1. Introduce a dedicated last-substitute state (pattern, replacement, flags)
   on the editor or `EditorBuffer`, updated by `_record_substitute_state()` and
   read by the no-pattern path. Keep `search_state.text` for `/` and `:g` only.
2. Restore the `*` / `#` history feature's sharing via an explicit copy where
   intended, rather than a shared mutable slot ([122](122.md) intent).
3. Add end-to-end tests for `:s/a/X/` → `/b`/`:g/b/…` → bare `:%s` asserting the
   correct text and that search state is unchanged by the substitution.
