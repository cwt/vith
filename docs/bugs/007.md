# `:wq` exits even when `:w` failed

**Category:** correctness · **Area:** `vith/commands/commands.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Summary

`write_and_quit` performs the write and then always `application.exit()`,
including all failure paths of `:w` (write to existing file without `!`,
unwritable directory, unknown-location fallthrough of [006](006.md)).

## Evidence

* [`vith/commands/commands.py:329-335`](../../vith/commands/commands.py):
  `write(editor, location, force=force)` discards its result and
  `editor.application.exit()` runs unconditionally.
* Failure modes that display a message *without* writing:
  [`vith/commands/commands.py:319-327`](../../vith/commands/commands.py)
  (`File exists (add ! to overriwe)` — see [034](034.md) for the typo itself),
  `EditorBuffer.write` catching `Exception`
  ([`vith/editor_buffer.py:167-172`](../../vith/editor_buffer.py)).

## Impact

`:wq` with a typo'd filename or a blocked write silently exits and throws the
edits away — accidental data loss. Vim aborts `:wq` on a write error.

## Fix direction

Make `write()` return a boolean (or check `eb.has_unsaved_changes` after the
attempt) and skip `application.exit()` on failure so the error message and
open file state remain visible.
