# Per-frame `TabsProcessor` unconditionally explodes fragments and scans every character on tab-free lines

**Category:** performance / rendering · **Area:** `vith/thai/patches.py`, `vith/layout.py` · **Found at:** Round 10 deep performance audit (2026-11-22, `v0.15.1` / rev 392) · **Fix status:** open

## Summary

`EditorLayout._create_buffer_control` unconditionally attaches `TabsProcessor` to every buffer window.[^src-layout] Its visual-width replacement `_patched_apply_transformation` in `vith/thai/patches.py` executes the full tab-expansion pipeline on **every visible line of every frame** (~97 calls/frame on a 50-row wrapped window due to `_scroll_when_linewrapping` + `_copy_body`) even when the line contains **no `\t` characters**:[^src-patches]

1. Calls `tab_char2()` → `_try_char('\u2508', '.', get_app().output.encoding())`, running `.encode(encoding, 'replace')` on every line.
2. Calls `explode_text_fragments(ti.fragments)`, shattering ~20 syntax-highlighted tokens into ~100–200 single-character tuples.
3. Allocates two `dict[int, int]` mappings (`position_mappings` and `position_mappings_reversed`) and calls `get_cwidth(ch)` on every character.
4. Forces downstream processors and `Window._copy_body` (`copy_line`) to iterate exploded 1-character fragments instead of multi-character token runs.

## Evidence

Measured via `cProfile` and wall-clock timings on a 50×160 viewport (`Python 3.15.2`, `prompt_toolkit 3.0.53`):

| Workload (50×160 viewport) | Current | With tab-free fast path | Impact |
| :--- | ---: | ---: | :--- |
| ASCII `.py` (no tabs) full `write_to_screen` | **5.86 ms/frame** | **3.18 ms/frame** | **1.84× faster full frame** (`-45.7%`) |
| `_patched_apply_transformation` share in `cProfile` (ASCII `.py`) | **36.3%** (`0.223s / 0.615s`) | ~0% | 405,600 `get_cwidth` calls eliminated per 50 frames |
| `_patched_apply_transformation` share in `cProfile` (Thai wrapped) | **29.6%** (`0.202s / 0.683s`) | ~0% | — |

## Fix Direction

1. In `_patched_apply_transformation` (`vith/thai/patches.py`), scan `ti.fragments` first; if no fragment text contains `'\t'`, return `Transformation(ti.fragments)` immediately (identity `source_to_display` / `display_to_source`, zero explosion, zero dict allocation, zero `tabstop`/`char2` evaluation).[^src-patches]
2. On lines that *do* contain `'\t'`, fast-path printable ASCII (`' ' <= ch <= '~'` → width `1` without `get_cwidth`), and replace the two dicts + `display_to_source` backward linear scan with compact `list[int]` + `bisect_right` mapping.
3. Cache `_try_char` by `(character, backup, encoding)` in `vith/layout.py` so `tab_char2()` and `get_vertical_border_char()` do not re-encode on every call.[^src-layout]
