# Ex commands park Normal-mode cursor past EOL on whitespace-only lines

**Category:** commands / cursor placement · **Area:** `vith/commands/ranges.py`, `vith/commands/handler.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** fixed (hg rev 476)

## Summary

Interactive Normal-mode key presses pass through `KeyProcessor._fix_vi_cursor_position`, which clamps the cursor off EOL (`col == len(line)`) and snaps off combining marks. Ex commands execute inside `command_buffer`'s `accept_handler` after `leave_command_mode()`, bypassing `_fix_vi_cursor_position`.

Both `_commit_buffer_text` (shared by `:d`, `:pu`, `:m`, `:t`, `:j`, `:sort`, `:retab`, `:r`, `:[range]!`, `:s`) and `_go_to_line` (`:N`, `:$`, `:+1`) compute `first_non_blank` as `len(line_text) - len(line_text.lstrip())`:[^src-ranges][^src-goto]

* When `line_text` is non-empty whitespace (e.g. `"    "`, `len == 4`), `line_text.lstrip()` is `""`, placing the cursor at `col == 4 == len(line_text)` (past the last space in Normal mode; Vim parks on the last space at `col == 3`).
* In `_commit_buffer_text` with `first_non_blank=False`, `max(0, min(col, len(line_text)))` likewise allows `col == len(line_text)` on non-empty lines and does not snap off Thai/Lao combining marks via `snap_to_cell_start` / `prev_cell_offset`.

## Evidence

Live probe on `"hello\n    \nworld"`:

* `handle_command(ed, "1d")` → lands on `"    "` (`len == 4`) with `doc.cursor_position_col == 4` (at `\n`, past the last character).

## Fix Direction

1. Extract a shared Normal-mode line-column helper (used by `_commit_buffer_text` and `_go_to_line`) that clamps `target_col` to `[0, len(line_text) - 1]` on non-empty lines and runs `prev_cell_offset(line_text, len(line_text), 1)` when clamping from `>= len(line_text)` or `snap_to_cell_start(line_text, target_col)` otherwise.
2. Add regression tests for `:1d` and `:2` landing on `"    "` (`col == 3`) and on a line ending with a Thai combining mark (`"ก้"`, `col == 0`).
