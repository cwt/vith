# Duplicate `.py` gating between `EditorBuffer.run_reporter()` and `reporting.report()`

**Category:** duplication · **Area:** `vith/editor_buffer.py`, `vith/reporting.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Summary

The P0 optimization gave both `run_reporter` (to skip spawning background
work) and `report()` (inside the worker) their own `location.endswith('.py')`
check. They must stay in sync or the reporter silently changes behaviour.

## Evidence

* [`vith/editor_buffer.py:197`](../../vith/editor_buffer.py)
  — `if not self.location or not self.location.endswith('.py'): … return`.
* [`vith/reporting.py:42`](../../vith/reporting.py)
  — `if location.endswith('.py'): return report_pyflakes(document)`.

## Impact

Adding a new checkable extension (`.pyi`, notebook export, …) or renaming the
rule requires editing two call paths; missing the fast-path copy either
re-introduces the per-keystroke background tasks for non-Python files (the P0
regression) or suppresses valid reports.

## Fix direction

Make `reporting.report()` the single source of truth (e.g. export
`reporter_for_location(location)` returning a callable or `None`) and have
`run_reporter` probe through it.
