# Mouse click on a document tab crashes the editor

**Category:** crash · **Area:** `vith/layout.py` (`TabsControl`) · **Found at:** user field report, 2026-11-09 (`vith -p file1 file2` + tab click) · **Fix status:** fixed

## Summary

Clicking a document tab at the top of the screen kills the event loop with:

```text
File ".../prompt_toolkit/layout/controls.py", line 455, in mouse_handler
    return handler(mouse_event)
Exception TabsControl.__init__.<locals>.create_tab_handler.<locals>.handler()
    missing 1 required positional argument: 'mouse_event'
```

## Evidence

* `create_tab_handler()` in `vith/layout.py:86-96`[^src-layout] defines `handler(app, mouse_event)`, but `FormattedTextControl` fragment handlers are invoked as `handler(mouse_event)` (`controls.py:455`).
* The tab bar is the only fragment mouse handler in `vith/` (no other `mouse_handler`/`MOUSE_DOWN` call sites), so this is the single broken path.

## Impact

* Any mouse click on a tab with `:set mouse` (the default) crashes the session — HIGH: data loss risk for unsaved buffers.

## Fix

* `vith/layout.py` `create_tab_handler()` now defines the single-argument `handler(mouse_event)` contract that `FormattedTextControl` invokes (`controls.py:455`); `editor` stays closed over, so no `app` parameter is needed.
* Regression test in `tests/test_layout.py`: `MOUSE_DOWN` on the second tab selects it, `MOUSE_UP` returns `NotImplemented` without touching tab state.
