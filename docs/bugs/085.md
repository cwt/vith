# Charwise `v` highlight not cluster-aligned with yank/cut

**Category:** contract drift (stem: 079/077) · **Area:** `vith/thai.py` (`_thai_selection_range_at_line` non-block branch) · **Found at:** stem audit 2026-11-08 · **Fixed at:** hg rev 270

## Summary

`_thai_selection_range_at_line` (pre-fix) extended the highlight only when
`end - 1` was a combining mark; but vith's motion invariant parks the cursor on
cell **starts**, so a charwise selection ending on a base with attached marks
(`ที่ดิ` cursor on `ด`, cell `[ดิ]` cp 3-4) had `end - 1 = base` and never
extended — the highlight covered `ที่ด` while `yank`/`cut` through
`selection_ranges` covered `ที่ดิ` (probe: `selection_ranges → [(0, 5)]` vs
`selection_range_at_line → (0, 4)`).

## Fix

The non-block branch now extends whenever the inclusive upper bound falls
*inside* a cell-cluster's mark tail (via `next_cell_offset`), so `highlight ==
yank == cut` spans at cluster granularity. Test:
`tests/test_thai.py::test_charwise_highlight_matches_yank_cluster_boundaries`.
