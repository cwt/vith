# `<F1>` from Command/Search mode leaks previewer state and Insert mode

**Category:** key bindings / command preview · **Area:** `vith/key_bindings.py`, `vith/editor.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** open

## Summary

`@kb.add('f1')` is registered with no filter and calls `editor.show_help()` directly.[^src-kb] `Editor.show_help()` opens a read-only `[Help]` horizontal split and focuses it via `sync_with_prompt_toolkit()`, without checking whether `command_buffer` or `search_buffer` currently has focus.[^src-help]

When the user enters Command mode (`:`), types a previewed command such as `:set nonumber` or `:colo monokai`, and presses `<F1>`:

1. `leave_command_mode()` is never called, so `previewer.restore()` never runs and the unconfirmed preview mutation permanently sticks on `editor`.[^src-cmd]
2. `command_buffer` retains its partial text (`'set nonumber'`).
3. `application.vi_state.input_mode` remains `InputMode.INSERT` (set by `enter_command_mode()`) while focus moves to the `[Help]` window.

## Evidence

Live probe against shipped `Editor` + `KeyProcessor`:

1. `ed.show_line_numbers` is initially `True`.
2. `ed.enter_command_mode()`; `ed.command_buffer.text = "set nonumber"` (live preview sets `ed.show_line_numbers = False`).
3. Feed `Keys.F1`:
   * `ed.show_line_numbers == False` (preview leaked without `<Enter>`).
   * `ed.application.vi_state.input_mode == InputMode.INSERT`.
   * `ed.command_buffer.text == 'set nonumber'`.

## Fix Direction

1. In `show_help` (or `show_info` / the `f1` handler), if `application.layout.has_focus(self.command_buffer)`, call `self.leave_command_mode(append_to_history=False)` first; also ensure `vi_state.input_mode = InputMode.NAVIGATION` when focusing the info split.
2. Add a regression test pressing `<F1>` while previewing `:set nonumber` in `command_buffer` and asserting `show_line_numbers` restores to `True` and `input_mode == InputMode.NAVIGATION`.
