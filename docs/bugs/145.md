# `:cq` exits with status 0

**Category:** wrong logic / CLI exit status · **Area:** `vith/commands/commands.py` (`quit_nonzero`), `vith/entry_points/run_vith.py`, `vith/__main__.py` · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** fixed

## Summary

`:cq` (Vim's `:cquit`) is documented as "quit with error code" in the help
([`vith/help.py:22`](../../vith/help.py#L22)) and listed among the Ex commands
in the README. The implementation only calls:

```python
@cmd('cq')
def quit_nonzero(editor):
    editor.application.exit()
```

([`vith/commands/commands.py:1053-1061`](../../vith/commands/commands.py#L1053-L1061)).

`Application.exit()` without `result=` yields `None`; `run_vith.run()` then
returns normally and the process exits 0
([`vith/entry_points/run_vith.py:52-54`](../../vith/entry_points/run_vith.py#L52-L54);
`__main__.py` has the same shape). There is no `sys.exit` based on
`application.run()`'s result.

## Evidence

Probe:

```text
: cq -> application.exit() called with args=(), kwargs={}
```

No exit-status value is passed or read. Shell check of a real process
(`printf ':cq\n' | vith ...`) would show status 0; the intended Vim behavior
is status 1.

## Impact

* Shell pipelines and tests cannot distinguish `:cq` from a successful quit.
* The help text is actively wrong.
* `:cq` is commonly used by scripts/plugins to abort a batch edit.

## Fix direction

1. Call `application.exit(result=1)` in `quit_nonzero()` and have
   `Editor.run()` return the application result.
2. In `run_vith.run()`/`__main__.py`, `sys.exit(editor.run() or 0)` (preserving
   `0` for normal quit and `1` for `:cq`).
3. Keep `:qa!`/`:q!` at 0.
4. Add a subprocess test that runs `:cq` and asserts a non-zero return code.
