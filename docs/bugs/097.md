# Gate not latched by mass edits other than `:s` (081 incomplete)

**Category:** missed UI invalidation / incomplete fix · **Area:** `vith/editor_buffer.py`, `vith/commands/commands.py`, `vith/thai.py` · **Found at:** Round 5 audit, 2026-11-09, hg rev 256 · **Fix status:** open

## Summary

[081](081.md) correctly identified the root cause — *"buffer text coverage is airtight for the cursor line only"* — but fixed **one call site** (`substitute`) with `note_document_text(new_text)`. `_on_text_changed` still notes only `self.buffer.document.current_line`, and ptk fires it at `Document` assignment time with the synthetic cursor at the end of the new text.

Probes (`reset_thai_text_gate()` first, gate expected `True` after Thai appears):

| Mutation | Gate after | Note |
| :-- | :-- | :-- |
| `buffer.insert_text('ascii\nสวัสดี Thai\nlast ascii line')` (multi-line paste) | `False` | cursor line = `last ascii line` |
| `buffer.text = 'ascii first\nสวัสดี Thai\n'` | `False` | cursor row 0, Thai on row 1 |
| `save_to_undo_stack(); buffer.text='ascii'; buffer.undo()` | `False` | undo restores Thai on non-cursor rows |

```text
after multi-line paste with Thai on a NON-cursor row: gate = False
text = 'ascii\nสวัสดี Thai\nlast ascii line'
```

`081.md`'s Fix section claims *"the paste/undo paths re-latch through their own row-event bodies or are documented above"* — they do not.

## Evidence

* [`vith/editor_buffer.py:91-108`](../../vith/editor_buffer.py)[^src-eb] — `_on_text_changed`: `note_document_text(self.buffer.document.current_line)`.
* [`vith/commands/commands.py:729`](../../vith/commands/commands.py)[^src-cmd] — `substitute`: the sole `note_document_text(new_text)` full-text call.
* [`vith/thai.py:267-272`](../../vith/thai.py)[^src-thai] — `_ThaiTextGate.note` latches only on Thai in the string it is given.
* [`vith/thai.py:635-636`](../../vith/thai.py)[^src-thai] — wrapped `_output_screen_diff` skips the sanitizer entirely while `_THAI_GATE.value` is `False`.
* [`tests/test_substitute.py:210-222`](../../tests/test_substitute.py)[^src-test] — `test_substitute_latches_thai_gate` covers only `:s`; no paste/undo regression test.

## Impact

Reachable from a plain all-ASCII session: paste Thai text from the clipboard into a document, or undo back to Thai content. The SARA-AM neighbor refresh and stray-zero-width-cell cleanup ([002](002.md), [062](062.md)) stay disarmed while Thai renders — terminal-dependent visual corruption.

## Fix direction

Note the **newly inserted/replaced** text at each mutation site (paste, undo/redo `Document` replacement, programmatic `buffer.text = …`), not the whole buffer on every keystroke — that would undo [072](072.md)'s O(1) ASCII fast path. A shared helper that runs only when the `Document` object is replaced (rather than on every character edit) is the safest shape; then `substitute`'s special-case can be removed.
