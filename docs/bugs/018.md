# `PyvimScrollOffsets` is never used; `ScrollOffsets` already accepts callables

**Category:** dead code · **Area:** `vith/layout.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* The class: [`vith/layout.py:413-425`](../../vith/layout.py) — defines
  `__init__` (not calling super), plain `left`/`right`, property `top`/`bottom`;
  grep shows **no instantiation anywhere** in the project.
* prompt_toolkit 3.0.53 `ScrollOffsets` natively accepts
  `int | Callable[[], int]` for all four offsets and converts via `to_int`
  (`prompt_toolkit/layout/containers.py:1327-1350`).
* The live code already relies on that:
  [`vith/layout.py:539-542`](../../vith/layout.py) passes
  `top=(lambda: self.editor.scroll_offset), bottom=(lambda: …)` to plain
  `ScrollOffsets`.

## Impact

permissive `__init__` (no super call) is a future trap if the base class
grows state.

## Fix direction

Delete the class.
