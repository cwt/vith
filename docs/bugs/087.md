# `:ls` pager numbering/naming inconsistent with `:b <n>`

**Category:** wrong rendering (stem: 067 residual) · **Area:** `vith/commands/commands.py` (`buffer_list`) · **Found at:** stem audit 2026-11-08 · **Fixed at:** hg rev 270

## Summary

`': %3i %s %s line %i' % (info.index, ...)` printed the raw 0-based
`list_open_buffers` index while the 067 fix aligned `:b <n>`, `BufferListOverlay`
and the digit filter on a **1-based** numbering — `:ls` was the one remaining
surface. `repr(None)` additionally leaked for untitled buffers (no location) —
the completer/overlay paths show names; the pager did not.

## Fix

The pager rows are built by module-level `buffer_list_lines(editor)`
(1-based index + 1 and `eb.get_display_name()` → `[New file]`), invoked from the
pager handler and directly testable (`:ls` output runs through
`run_in_terminal`, which is untestable in pytest). Test:
`tests/test_quit_and_goto.py::test_ls_pager_one_based_and_no_name`
(`'  1 %  [New file]  ...  line 1'`).
