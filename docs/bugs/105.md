# `build/` + `dist/` duplicate the whole package

**Category:** hygiene / duplicated source · **Found at:** Round 5 audit, 2026-11-09, hg rev 256 · **Fix status:** open

## Summary

| Path | Contents | Status |
| :-- | :-- | :-- |
| `build/lib/vith/` | 32 `.py` files, **byte-identical** to `vith/` (verified: 32/32 differ/missing = 0) | ignored by `.hgignore` / `.gitignore` |
| `build/bdist.linux-x86_64/` | empty build dir | ignored |
| `dist/vith-0.11.1-py3-none-any.whl`, `dist/vith-0.11.1.tar.gz` | release artifacts from 2026-11-09 11:19 | ignored |
| `vith.egg-info/` | packaging metadata | ignored |

[074](074.md) fix record (hg rev 264) states: *"`build/` and `dist/` deleted from the working tree (soft-deleted …) — regeneration is `python -m build`"*. They were regenerated by the 0.11.1 release build.

## Evidence

* `diff -q build/lib/vith/commands/preview.py vith/commands/preview.py` → no difference; a scripted comparison of all 32 `.py` files reports **0 differing/missing**.
* `hg status --all build dist` → all entries `I` (ignored); `.hgignore:7-9` lists `build/`, `dist/`, `*.egg-info/`.
* Repo-wide AST/definition scans (used during this audit) returned **every** function/class definition twice — once from `vith/`, once from `build/lib/vith/`.

## Impact

Unlike the pre-rebrand stale snapshot described in [074](074.md), the current copies are not drifted — but they are a complete duplicate of the source tree that doubles grep/AST hits, pollutes tool output, and can mislead an auditor into editing the wrong copy. The documentation claims they are absent.

## Fix direction

Remove `build/`, `dist/` and `vith.egg-info/` from the working tree after release; regenerate with `python -m build` only when packaging. Add a note to `CONTRIBUTING`/release instructions so the deletion is not silently undone by the next build. Update [074](074.md)'s fix record to reflect that regenerated artifacts are expected post-release.

## Fix

Removed `build/`, `dist/`, and `vith.egg-info/` directories from the working tree, clearing duplicate source files and build artifacts. Both directories remain properly ignored in `.hgignore` and `.gitignore`.
