# `tests/test_cd.py` suite-order-dependent cwd leak

**Category:** test hygiene (surfaced during the stem scan while probing test-order flakes) · **Area:** `tests/test_cd.py` · **Found at:** stem audit 2026-11-08 · **Fixed at:** hg rev 271

## Summary (machine repro)

`pytest tests/test_cd.py tests/test_startup_io.py -q` → `1 failed`
(`python -m vith --help` subprocess: "No module named vith"); the reverse order
passes; the full suite reported `2 failed, 184 passed` before the 070-tests
(`test_python_m_vith_help_smoke`, `test_vith_flags_mutual_exclusion_error`).
Root cause: the test's comment `# restore` ran `os.chdir(home)` — restoring to
the user's HOME instead of the workspace cwd the rest of the suite expects.

## Fix

The test now uses a `cwd_restored` fixture (round-trips to the cwd at test
start), and `:cd`'s no-argument target is resolved against a *fake* `$HOME`
inside tmp via `monkeypatch.setenv` — the real home directory is never entered
during tests.
