# Multi-line error messages corrupt preview line bookkeeping

**Category:** live render / lexer · **Area:** `vith/render.py`, `vith/lexer.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`_apply_error()` renders a diagnostic as a single fragment spanning the whole
message: `styled = [[('ansired italic', message)]]`.[^src-render] Error messages
are routinely multi-line — external renderer `stderr` (via
`Renderer command failed ({err_msg})`) and wrapped library exceptions are the
main sources. `_update_preview_document()` then derives `_preview_line_starts`
from `styled_lines[:-1]`, i.e. from the number of *styled lines* rather than the
number of `\n` characters in `plain_text`.[^src-render]

## Evidence

Probe with a 3-line message:

| Observable | Expected | Actual |
| :--- | :--- | :--- |
| `len(prev.buffer.text.split('\n'))` | 3 | 3 |
| `len(prev._rendered_lines)` | 3 | **1** (one fragment with embedded `\n`) |
| `ctrl._preview_line_starts` | 3 offsets | **`[0]`** |
| `DocumentLexer.get_rendered_line(0)` | one styled fragment, no `\n` | `[('ansired italic', 'ERR line1\nERR line2\nERR line3')]` |
| `get_rendered_line(1)` / `(2)` | styled fragments | `[]` (no style) |

`DocumentLexer.lex_document()` returns `rendered_lines[i]` directly as a
line's token list,[^src-lexer] so a fragment containing `\n` violates
prompt_toolkit's per-line formatted-text contract; lines 1–2 render unstyled
and `sync_scroll()` clamps the preview cursor to row 0 because
`preview_lines = len(line_starts) == 1`.

## Fix Direction

1. Split the message into lines before building `styled_lines`, e.g.
   `styled = [[('ansired italic', line)] for line in message.split('\n')]`, so
   the invariant `len(styled_lines) == plain_text.count('\n') + 1` always holds.
2. Add a regression test using a multi-line error message that asserts the
   three observables above and that `sync_scroll()` can reach the last row.
