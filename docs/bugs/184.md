# Custom render command alias lookup is inconsistent

**Category:** live render / config · **Area:** `vith/render.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** fixed
> **Resolution note (2026-11-23):** `detect_render_format()` resolves custom command keys across canonical names and aliases in both directions.


## Summary

`detect_render_format()` checks `if ft in commands` / `if ext in commands`
against the **raw** option value, then falls through to the canonical
`_FT_TO_FORMAT` / `_EXT_TO_FORMAT` mapping.[^src-render] `render_document()`
only dispatches an external command when the *resolved* format is a key of
`custom_commands`.[^src-render] These two rules disagree across aliases:

* `[render.commands] md = "glow"` on `x.md` → ext `md` matches → command runs.
* Same config with `:set ft=markdown` on an untitled buffer → `markdown` is not
  a command key → mapped to built-in `markdown` format → Rich Markdown used.
* `[render.commands] rst = "…"` with `:set ft=restructuredtext` happens to work
  because the mapped format string equals the command key — inconsistent with
  the `md` case.

`docs/live_render.md` §4.1 states custom commands are checked first for explicit
filetypes, so the current alias-dependent behavior is only partially
honored.[^src-doc]

## Evidence

```
detect_render_format(None, 'markdown', 'hi', {'md': 'cat'})            == 'markdown'  # command bypassed
detect_render_format(None, 'restructuredtext', 'hi', {'rst': 'cat'})   == 'rst'       # command used
```

## Fix Direction

1. After resolving the canonical format via `_FT_TO_FORMAT`/`_EXT_TO_FORMAT`,
   also check whether that canonical name is a `custom_commands` key (and vice
   versa, normalize command keys through the same alias tables) so aliasing is
   uniform.
2. Add parametrized tests over the alias sets (`md`/`markdown`,
   `rst`/`rest`/`restructuredtext`) asserting the external command is selected
   regardless of which alias the user configured or set.
