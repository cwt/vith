# CRLF files are silently rewritten with LF line endings

**Category:** wrong logic / file fidelity · **Area:** `vith/editor_buffer.py` (`_read`, `write`) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** fixed

## Summary

`_read()` performs:

```python
text = text.replace('\r\n', '\n')
```

([`vith/editor_buffer.py:270-282`](../../vith/editor_buffer.py#L270-L282))
and stores only `_had_trailing_newline`. There is no `fileformat`/`ff`
attribute. `write()` then builds the payload as
`self.buffer.text + eol`, where `eol` is `'\n'` or `''`
([`:410-412`](../../vith/editor_buffer.py#L410-L412)).

As a result, every save converts a CRLF file to LF. Vim records
`fileformat=dos` on read and writes CRLF back; vith has no equivalent option
or state. This is a data-fidelity regression for Windows-origin files,
generated files, and repositories with mixed line endings.

## Evidence

Probe: file bytes `b'one\r\ntwo\r\n'`, open in vith, run `:w` without editing:

```text
loaded text: 'one\ntwo'
saved bytes: b'one\ntwo\n'
```

Vim comparison: opening and `:w` preserves `b'one\r\ntwo\r\n'` (the
`fileformat` option remains `dos`).

Related paths:

* `read_command()` normalizes `\r\n` for inserted text, so `:r` also
  contributes LF lines;
* `_write_append_file()` writes with `open(..., 'a')` and does not convert,
  so `:w >>` mixes LF into a CRLF file;
* the gzip backend inherits the same LF payload.

## Impact

* Silent whole-file diff after a trivial edit (every line appears modified).
* Build tools or tests that assert CRLF fail.
* APPEND writes can produce mixed line endings.

## Fix direction

1. Detect the dominant line ending in `_read` (`\r\n`, `\n`, or lone `\r`)
   and store it as a buffer option (`fileformat`/`ff`, Vim `dos`/`unix`/`mac`).
2. Use that separator in `write()` and in the partial/append/piped write paths.
3. Expose `:set fileformat=dos|unix|mac` (default `unix` for new buffers) and
   include it in `set_options_lines`.
4. Add byte-level tests for round-tripping CRLF, LF, no-EOL, and mixed files;
   include `:w >>` and `:sav`.
