# Quit semantics count buffers, not windows (`:q` over-blocks, `:wqa` under-delivers)

**Category:** wrong logic / Vim semantics · **Area:** `vith/commands/commands.py` (`quit`, `write_and_quit_all`) · **Found at:** deep review, hg rev 87de3a3 (2026-11-08)

## Summary

Vim `:q` closes the current *window* and only exits when that was the last window — hidden buffers are fine. Vith counts `editor_buffers` (all hidden buffers):

```python
elif not all_ and len(ebs) > 1: show_message('%i more files to edit')
```

So `:q` with one window and two hidden buffers says “1 more file to edit” instead of exiting.

`:wqa` (`write_and_quit_all`) writes the current buffer, then calls `quit(editor, all_=True, force=False)`. With any other dirty buffer, `quit` blocks with “No write since last change” — the user gets two messages and no exit, despite the command name promising “write + quit all”.

## Evidence

* [`vith/commands/commands.py:325-352`](../../vith/commands/commands.py)[^src-cmd] — `quit` + `quit_all`.
* [`vith/commands/commands.py:390-399`](../../vith/commands/commands.py) — `write_and_quit_all` delegating with `force=False`.

## Impact

Daily-driver friction: `:q` appears to “not quit” after closing splits; `:wqa` appears broken whenever more than one buffer is dirty.

## Fix direction

Distinguish window-close vs app-exit as Vim does: `:q` closes the window when `active_tab.window_count() > 1`, exits only when it was the last window *and* no dirty buffers (or with `!`). For `:wqa`, either document the “abort if other buffers dirty” behavior in the message, or implement Vim’s “write current, then fail with E233-style abort” explicitly and test it.
