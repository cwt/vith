# Startup and I/O robustness: single-level `mkdir`, bare `assert` on `-p -o`, latin-1 write failure, unknown-location indistinguishability

**Category:** wrong logic / robustness (grouped lows) · **Area:** `vith/editor.py`, `vith/editor_buffer.py`, `vith/entry_points/run_vith.py`, `vith/io/backends.py` · **Found at:** deep review, hg rev 87de3a3 (2026-11-08) · **Re-validated:** 2026-11-08 at hg rev 251 (tip; code identical to the audit revision)

## Summary

Four small defects, grouped as in [054](054.md):

1. `Editor.__init__` uses `os.mkdir(config_directory)` (single level). A nested config path (`/tmp/a/b/c`) raises `FileNotFoundError`; the check-then-act also races to `FileExistsError` on concurrent launches.
2. `vith -p -o` (or `-p -O`, `-o -O`) reaches `assert in_tab_pages + hsplit + vsplit <= 1` in `load_initial_files` → bare `AssertionError`, no usage message.
3. `_auto_decode` falls back to latin-1 and records it as `self.encoding`. Typing Thai into that buffer then `:w` raises `UnicodeEncodeError` → “cannot write”, no utf-8 fallback.
4. `_read` returns `''` both for “file does not exist” (legit new file, silent) and for “unknown location scheme” (after showing a message but still creating a buffer with that location). The subsequent `:w` then fails with “Unknown location” — a two-step confusing UX. (Validated sibling of the same pattern: `HttpIO.exists` returns `NotImplemented`, treated as readable at `editor_buffer.py:119`; a fetch error yields `Cannot read %r: %r` → `return ''` — again indistinguishable from a legit new file by content.)

## Evidence

* [`vith/editor.py:84-85`](../../vith/editor.py)[^src-ed] — `if not os.path.exists(...): os.mkdir(...)`.
* [`vith/entry_points/run_vith.py:30-33, 51`](../../vith/entry_points/run_vith.py) — docopt flags assigned at `:30-32` and passed unvalidated at `:51`; `load_initial_files` has exactly one caller and nothing validates the mutual exclusion earlier. [`vith/editor.py:159`](../../vith/editor.py) — the bare `assert`.
* [`vith/io/backends.py:159-169`](../../vith/io/backends.py)[^src-io] — `_auto_decode` loop; latin-1 decodes any byte string so the second iteration always "succeeds" and the encoding is recorded (`vith/editor_buffer.py:123`); the write path has no encoding fallback (`vith/editor_buffer.py:179-184`, `show_message('%s' % e)` on any exception).
* [`vith/editor_buffer.py:137-143`](../../vith/editor_buffer.py) — missing file: `self.is_new = True; return ''` (silent) vs unknown scheme: `show_message('Cannot read: %r')` then `return ''`; the buffer is still created (`editor_buffer.py:40-43`) and the later `:w` fails with “Unknown location” (`editor_buffer.py:173-175`).

## Impact

Each is low-severity alone; together they are the remaining “first-run / save-path” paper cuts.

## Fix direction

`os.makedirs(..., exist_ok=True)`; validate `-p/-o/-O` mutual exclusion in `run()` with a friendly error; on `UnicodeEncodeError` at write time, offer utf-8 (or update `self.encoding` with a warning); distinguish “new file” (`is_new=True`, silent) from “unknown backend” (refuse to create a buffer or mark it read-only).

## Fix record (2026-11-08, hg rev 260)

1. `os.makedirs(config_directory, exist_ok=True)` (nested paths + race-safe).
2. `run_vith.run()` validates `-p/-o/-O` mutual exclusion with a friendly stderr message and exit code 2, *before* the `Editor` is constructed.
3. `EditorBuffer.write` retries with `utf-8` on `UnicodeEncodeError`, updates `self.encoding`, and records the downgrade in a message.
4. `_read` returns `None` (instead of `''`) for unknown backends and failed reads; unreadable buffers are created read-only (`read_only=self.isdir or unreadable`), and `reload()` keeps current contents instead of wiping them.

6 tests in `tests/test_startup_io.py`.
