# Per-keystroke $O(\text{file size})$ copy via `Document.current_line` and eager `Document.lines` split in `_on_text_changed`

**Category:** performance / per-keystroke latency · **Area:** `vith/thai/patches.py`, `vith/editor_buffer.py`, `vith/thai/words.py`, `vith/key_bindings.py` · **Found at:** Round 10 deep performance audit (2026-11-22, `v0.15.1` / rev 392) · **Fix status:** fixed

> **Resolution note (2026-11-22):** Added $O(\text{line length})$ `current_line_and_col(doc)` in `vith/thai/clusters.py` and `is_thai_gate_latched()` in `vith/thai/patches.py`. Replaced `doc.current_line` across cursor left/right/column patches, `_kp_fix_vi_cursor_position` (now short-circuiting Insert mode and ASCII text before any slice), `find_boundaries_of_current_word`, and `key_bindings.py` (`whitespace_before_cursor_on_line` is now $O(1)$). Guarded `EditorBuffer._on_text_changed` to skip `current_line` and `document.lines` when ASCII or already latched, using `text.count('\n') + 1` otherwise. Verified with regression tests in `tests/test_round10_perf.py`.

## Summary

Two compounding $O(\text{file size})$ operations execute on every single keystroke:

1. **Uncached full-file copy in `Document.current_line`:** In `prompt_toolkit`, `Document.current_line` computes `self.text[:pos].rpartition('\n')[2] + self.text[pos:].partition('\n')[0]`, copying **100% of `document.text`** into two temporary strings on every access. `vith` calls `doc.current_line` on the hottest keystroke paths:
   - `_kp_fix_vi_cursor_position` (`vith/thai/patches.py:214`) evaluates `line = doc.current_line` **before** checking `if (vi_navigation_mode() or vi_selection_mode())`, copying the entire file on every **Insert-mode** keystroke and throwing the string away.[^src-patches]
   - `_doc_get_cursor_left_position`, `_doc_get_cursor_right_position`, and `_doc_get_column_cursor_position` (`vith/thai/patches.py:99-201`) call `self.current_line` and `self.cursor_position_col` (triggering full `_line_start_indexes` construction on fresh `Document`s even for ASCII text).[^src-patches]
   - `find_boundaries_of_current_word` (`vith/thai/words.py:508`), `whitespace_before_cursor_on_line`, `_delete_cell_clusters`, `_replace_cell_clusters`, `substitute_cell`, and `reverse_case_cell` (`vith/key_bindings.py`) also access `doc.current_line` / `doc.current_line_before_cursor`.[^src-words][^src-kb]
2. **Unconditional `document.lines` split in `EditorBuffer._on_text_changed`:** `vith/editor_buffer.py:242-251` unconditionally accesses `self.buffer.document.current_line` and `self.buffer.document.lines` (`text.split('\n')`) on every edit just to feed `note_document_text(...)`, even when `text.isascii()` is `True` ($O(1)$ bit check) or `_THAI_GATE.value` is already `True` (making `note_document_text` a no-op).[^src-eb]

## Evidence

Measured on `Python 3.15.2` / `prompt_toolkit 3.0.53`:

| Operation | File size | Current | $O(\text{line length})$ `rfind`/`find` | Speedup |
| :--- | ---: | ---: | ---: | ---: |
| `doc.current_line` | 0.8 MB (20k lines) | 0.024 ms | 0.0002 ms | **118×** |
| `doc.current_line` | 4.1 MB (100k lines) | 0.177 ms | 0.0002 ms | **946×** |
| `doc.current_line` | 8.2 MB (200k lines) | **0.386 ms** | **0.0002 ms** | **1,722×** |
| `get_cursor_left_position(1)` (fresh `Document`) | 8.2 MB (200k lines) | **0.569 ms** | ~0.001 ms | **>500×** |
| `insert_text('x')` on ASCII buffer | 50k lines (1.7 MB) | **1.94 ms/char** (`text.split('\n')` alone: **1.23 ms**) | ~0.7 ms (no eager split) | **~2.7×** |

## Fix Direction

1. Add an $O(\text{line length})$ helper `current_line_and_col(doc) -> tuple[str, int]` using `text.rfind('\n', 0, pos)` and `text.find('\n', pos)` (zero full-file copy, zero `_line_start_indexes` build) and use it across `vith/thai/patches.py`, `vith/thai/words.py`, and `vith/key_bindings.py`.[^src-patches][^src-words][^src-kb]
2. In `_kp_fix_vi_cursor_position`, check `if not (vi_navigation_mode() or vi_selection_mode()): return` *before* extracting the line, and fast-path `doc.text.isascii()`.[^src-patches]
3. In `_doc_get_cursor_left_position` and `_doc_get_cursor_right_position`, fast-path `self.text.isascii()` using `rfind`/`find` without constructing `self.current_line` or `_line_start_indexes`.[^src-patches]
4. In `EditorBuffer._on_text_changed`, skip `current_line` and `document.lines` entirely when `text.isascii()` or the Thai gate is already latched (expose an `is_thai_gate_latched()` helper), and use `text.count('\n') + 1` instead of `document.lines` when unlatched & non-ASCII.[^src-eb]
