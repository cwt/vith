# `:b <pattern>` TypeError with untitled buffers (daily-driver crash)

**Category:** unchecked `None` (Found during the user-requested stem scan 2026-11-08) · **Area:** `vith/window_arrangement.py` (`go_to_buffer`) · **Found at:** stem audit, hg rev 269 · **Fixed at:** hg rev 271

## Summary

The 067-rewritten `go_to_buffer` substring branch (`window_arrangement.py:393`,
pre-fix) ran `buffer_name in eb.location` without a `location is not None` guard.
`EditorBuffer.location` is `None` for the default `[No Name]` buffer, `:tabe`
/`:new` (no argument) and the help buffer — i.e. *almost always present*. Every
`:b` form that missed the exact-match branch raised
`TypeError: argument of type 'NoneType' is not iterable` and escaped the accept
handler into `Application.run` — killing the session. The completer
(`completer.py:43`) and `BufferListOverlay` (`layout.py:262`) both guard
`location is None`; the rewritten resolver did not.

## Evidence

* Repro: `editor.load_initial_files([None])` → `go_to_buffer("zzz")` → TypeError; full command path (`:b zzz` Enter) reproduced through `handler.py:39`; fuzz: 30/400 keyboard sequences hit it.

## Fix

`matches = [eb for eb in ebs if eb.location is not None and buffer_name in eb.location]`.
Test: `tests/test_quit_and_goto.py::test_goto_buffer_pattern_with_untitled_buffers_is_guarded` (`:b zzz` → `E94` message; numeric fallbacks no longer crash).
