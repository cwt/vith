# Thai renderer patches rely on fragile prompt_toolkit internals

**Category:** fragility / hidden coupling · **Area:** `vith/thai.py` (`_install_window_copy_body_patch`, `_install_renderer_patch`) · **Found at:** deep review, hg rev 87de3a3 (2026-11-08)

## Summary

The two renderer patches (added for [062](062.md)) are the most fragile code in the tree. They work against `prompt_toolkit 3.0.53` but encode five private-contract assumptions:

1. **Positional `args[]` with partial signature checks**: `args[1]/[2]/[5]/[7]/[11]` for `output/screen/previous_screen/is_done/size` and `args[6]` for `has_focus`. Checks only `params[2]=="screen"` / `params[5]=="previous_screen"` (renderer) and first-six params (window). One inserted parameter silently reads the wrong arg; `width = size.columns` then mis-derives the autowrap column.
2. **Private `_CHAR_CACHE`** (`thai.py:46,1127`) — not a public API.
3. **`"[ZeroWidthEscape]" not in style`** (`thai.py:1113`) — substring match on a formatted-text style string. A prompt_toolkit token rename silently disables the hide filter and merges escapes into buffer text.
4. **Dict insertion-order mouse hack** (`thai.py:1130-1134`) — `del` + reinsert `(lineno, col)` last so `{v:k}` reverse-lookup resolves `(sy,sx)` to the base character. Relies on an undocumented ordering guarantee.
5. **Per-frame `output.write/write_raw` monkey-patching** (`thai.py:1243-1249`) — instance-attribute swap restored in `finally`. Concurrent `Application` instances (tests, nested `run_in_terminal`) can interleave; `saved_escapes` mutates `screen.zero_width_escapes` rows that may be shared.

Secondary notes: `snap_to_cell_start(line, len(line))` returns `len(line)` (a valid boundary, but the name suggests mid-cluster snap), `prev_row[x-1] = _SARA_AM_POISON` mutates `previous_screen` in place (safe only if prompt_toolkit discards it after diff — uncommented assumption), and `_LibThaiWrapper.find_breaks` snaps raw libthai breaks backward without verifying monotonicity (duplicate check without `<`).

## Evidence

* [`vith/thai.py:1017-1144`](../../vith/thai.py)[^src-thai] — window copy-body patch (signature check lines 1032-1050; `has_focus` line 1099; `_CHAR_CACHE` line 1127; dict-order lines 1130-1134).
* [`vith/thai.py:1147-1261`](../../vith/thai.py) — renderer patch (signature check lines 1159-1170; positional args lines 1173-1177; write-swap lines 1243-1249).

## Impact

A routine prompt_toolkit upgrade can silently disable Thai right-margin/SARA-AM rendering (no hard failure — Thai diagnostics just look wrong), the worst kind of regression.

## Fix direction

Bind arguments by name (`inspect.signature(...).bind(*args, **kwargs)`), import `_CHAR_CACHE` behind a fallback (or construct `Char` directly), check for the escape token object rather than its string, avoid dict-order reliance by confirming prompt_toolkit’s mouse-lookup implementation, and serialize/coalesce the output-write patch per `Application` (or document single-instance assumption). Add a prompt_toolkit-version matrix test that fails loudly on signature drift.
