# `:next` duplicates the tab-bar entry instead of switching tabs

**Category:** Vim semantics · **Area:** `vith/commands/commands.py` · **Found at:** user field report, 2026-11-10 (follow-up to [124](124.md)) · **Fix status:** fixed

## Summary

`vith -p file1 file2`, then `:next`: the tab bar shows `file2.txt` twice and the active tab still points at tab 0. Tab 0's window now shows `file2` — the same `EditorBuffer` object as tab 1.

## Evidence

* Reproduced headlessly: before `:next` the tab bar renders `file1.txt | file2.txt`; after `:next` it renders `file2.txt | file2.txt` with `active_tab_index == 0`, and both tab pages' active windows reference the `file2` buffer.
* Root cause: `_next()` in `vith/commands/commands.py`[^src-cmd] unconditionally calls `go_to_next_buffer()`, which calls `active_tab.show_editor_buffer(...)` — buffer replacement inside the current window. That is correct for a single tab, but with several tab pages it clones one file across tabs instead of stepping to the next tab page.

## Impact

* The `-p` workflow (one file per tab) breaks on first `:next`: duplicate captions, and the tab ↔ file mapping the user arranged is lost.

## Fix

* `_next` / `_previous` in `vith/commands/commands.py` are tab-aware: with more than one tab page they switch tab pages (`go_to_next_tab` / `go_to_previous_tab`, no discard guard — nothing is discarded); single-tab sessions keep the buffer-list cycling with the unsaved-changes guard.
* Regression tests in `tests/test_quit_and_goto.py`: multi-tab `:next` moves `active_tab_index` with distinct per-tab captions, `:previous` moves back, dirty buffers need no force across tabs.
