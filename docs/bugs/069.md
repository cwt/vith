# `current_editor_buffer` returns `None` and file-explorer `open_path` dereferences it

**Category:** wrong logic / unchecked `None` · **Area:** `vith/editor.py`, `vith/key_bindings.py` · **Found at:** deep review, hg rev 87de3a3 (2026-11-08)

## Summary

```python
@property
def current_editor_buffer(self):
    ...
    for b in self.window_arrangement.editor_buffers:
        if b.buffer == current_buffer: return b
    # implicit None
```

If no `EditorBuffer` matches the prompt_toolkit current buffer (transient focus on command/search buffer, layout mid-update), the property returns `None`. `key_bindings.open_path` (file-explorer `<Enter>`) immediately does `editor.current_editor_buffer.location` with no guard, while `layout.ReportMessageToolbar` explicitly handles the same `None`. The `None` case is therefore real but only half-guarded.

## Evidence

* [`vith/editor.py:225-240`](../../vith/editor.py)[^src-ed] — fall-through `None`.
* [`vith/key_bindings.py:188-201`](../../vith/key_bindings.py)[^src-kb] — `os.path.join(editor.current_editor_buffer.location, ...)` unguarded.
* [`vith/layout.py:347-351`](../../vith/layout.py) — guarded counterpart (`if eb is None: return []`).

## Impact

`AttributeError` on `<Enter>` during focus transitions in file-explorer mode; any future caller that assumes non-`None` inherits the same crash.

## Fix direction

Make `open_path` early-return on `None` (and audit other `current_editor_buffer` callers: `commands.substitute`, `commands.compression`), or have the property document/raise a descriptive `NoActiveBuffer` error.
