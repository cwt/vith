# Filetype detection inconsistencies across `EditorBuffer`, `DocumentLexer`, `reporting`, and `completion`

**Category:** filetype / syntax / diagnostics · **Area:** `vith/editor_buffer.py`, `vith/lexer.py`, `vith/reporting.py`, `vith/completion.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** fixed (hg rev 475)

## Summary

Three divergences exist between `EditorBuffer.filetype` and its consumers:

1. **Untitled buffers (`location is None`) never syntax-highlight sniffed content:** `EditorBuffer.filetype` sniffs shebangs/modelines/JSON/Python on untitled buffers (`eb.filetype == 'python'`),[^src-eb] yet `DocumentLexer.lex_document` gates lexing on `if location or getattr(self.editor_buffer, 'filetype_override', None):`, returning unstyled `SimpleLexer` whenever `location is None` and `filetype_override is None`.[^src-lex]
2. **Empty extensionless files permanently cache `_detected_filetype = ''`:** If `eb.filetype` is read while a new extensionless buffer is still empty (for example by `eb.tabstop` on the first keypress), `self._detected_filetype` is assigned `''`. Because `if self._detected_filetype is not None:` treats `''` as cached and `_on_text_changed` never resets it, typing `#!/usr/bin/env python3` or `# vim: set ft=python:` later leaves `eb.filetype == ''` and `eb.tabstop == 8` even though `DocumentLexer` highlights the buffer as Python.[^src-eb]
3. **`pyflakes` reporting and Jedi completion ignore `eb.filetype`:** `reporting.checks_python_file(location)` and `DocumentCompleter.get_completions` check `location.endswith('.py')` rather than `eb.filetype == 'python'`.[^src-rep][^src-comp] Running `:set filetype=text` on `foo.py` still runs `pyflakes` and Jedi, whereas `:set filetype=python` (or a Python shebang/modeline) on an extensionless script activates neither.

## Evidence

Live probes against shipped classes:

| Scenario | `eb.filetype` | Actual behavior |
| :--- | :--- | :--- |
| Untitled buffer (`location=None`) with `"#!/usr/bin/env python3\ndef foo():\n    return 42\n"` | `'python'` | `DocumentLexer` emits `[('', 'def foo():')]` (no highlighting) |
| New empty extensionless `myscript`: read `eb.filetype`, then insert `"#!/usr/bin/env python3\n..."` | `''` (stuck) | `eb.filetype` stays `''` despite shebang |
| `foo.py` containing `"not valid python ==="` + `:set filetype=text` | `'text'` | `checks_python_file` is `True`; `report(...)` still emits 1 syntax error |

## Fix Direction

1. Allow `DocumentLexer.lex_document` to invoke `_ensure_lexer(None)` when `document.text` is non-empty so untitled buffers with shebangs/modelines/JSON highlight consistently with `eb.filetype`.
2. In `EditorBuffer.filetype`, do not permanently memoize `''` across edits when filename lookup missed (or invalidate `_detected_filetype` when `_detected_filetype == ''` and line 1 / modeline changes).
3. Consult `eb.filetype == 'python'` (falling back to `checks_python_file(location)` when only a location string is passed) in `EditorBuffer.run_reporter` and `DocumentCompleter.get_completions`, and re-trigger `eb.run_reporter()` inside `set_filetype`.
