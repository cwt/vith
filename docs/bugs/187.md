# `:d {x}` / `:y {x}` leave the unnamed register stale

**Category:** commands / registers · **Area:** `vith/commands/common.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`store_lines_in_register()` writes the lines only to the explicitly named
register.[^src-common] Vim always updates the unnamed register (`""`) as well
when a named register is supplied to a linewise delete or yank, so a subsequent
plain `p` pastes the most recently yanked/deleted text. Vith leaves
`registers['']` untouched, causing paste-state divergence. The helper is shared
by `:d`, `:y`, and `:g` subcommands.[^src-editing]

## Evidence

Probe on a 3-line buffer:

| Sequence | Expected `registers['']` | Actual |
| :--- | :--- | :--- |
| `:y a` | `'one'` (same as `registers['a']`) | `None` |
| `:d b` | `'one'` (same as `registers['b']`) | `None` |

A normal-mode `p` after either command pastes the previous unnamed content (or
nothing), not the just-yanked/deleted line.

## Fix Direction

1. In `store_lines_in_register()`, when a register name is provided, also set
   `editor.registers['']` to the same linewise payload (preserving register
   type — linewise vs charwise — as Vim does).
2. Add regression tests for `:y a` + `p`, `:d b` + `p`, and `:g/pat/y c` + `p`
   asserting the unnamed register and paste result.
