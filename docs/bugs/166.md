# Secondary I/O, editing, and command hot spots

**Category:** performance / I/O / algorithms · **Area:** `vith/key_bindings.py`, `vith/commands/files.py`, `vith/io/`, `vith/editor_buffer.py`, `vith/commands/editing.py`, `vith/commands/global_cmd.py`, `vith/commands/completer.py` · **Found at:** Round 10 deep performance audit (2026-11-22, `v0.15.1` / rev 392) · **Fix status:** open

## Findings

| # | Location | Issue | Evidence / Impact |
| :-- | :--- | :--- | :--- |
| 1 | `vith/key_bindings.py:227-255` (`_shift_lines`)[^src-kb] | `>>` / `<<` materializes `list(doc.lines)` and runs `'\n'.join(lines)` across the entire file even for a 1-line shift, instead of splicing the shifted rows like `splice_buffer_lines`. | `splice_buffer_lines` on 1 line of 50k takes **1.42 ms** without copying/joining 50,000 untouched lines. |
| 2 | `vith/commands/files.py:263-284` (`_write_append_file`), `vith/io/`[^src-files][^src-io] | `:w >> target` reads the **entire** existing target file into memory, concatenates `old_text + payload`, and rewrites the whole file from byte 0 ($O(\text{target size})$ I/O and 2× memory). | Appending 1 line to a multi-hundred-MB log file reads, duplicates, and rewrites the entire file; `FileIO` can append natively with `open(path, 'a', encoding=...)` in $O(\text{payload})$. |
| 3 | `vith/editor_buffer.py:310-318` (`EditorBuffer._read`)[^src-eb] | Unconditionally runs `text.count('\r\n')`, `text.count('\r')`, `text.replace('\r\n', '\n')`, and `text.replace('\r', '\n')` (4 full-file scans) even on plain Unix files with zero `\r`. | Measured on 3 MB Unix file: **5.41 ms** → **0.05 ms** (~100×) when guarded by `if '\r' in text:`. |
| 4 | `vith/commands/editing.py:381-407` (`sort_lines`)[^src-editing] | `:sort nu` runs `_FIRST_INT_RE.search`, `int()`, and `line.casefold()` **twice** per line (once in `sort_key`, once in the `unique` loop) and builds an $O(N)$ `seen` set even though `sorted_segment` is already sorted. | Measured on 50k lines: **33.87 ms** → **25.76 ms** (**1.31×**) with single-pass key extraction + $O(1)$-space adjacent deduplication. |
| 5 | `vith/io/backends.py:104-116` (`DirectoryIO.read`)[^src-io] | Calls `os.listdir(directory)` followed by `os.path.isdir(os.path.join(...))` for every entry ($N$ extra `stat()` syscalls). | `os.scandir(directory)` uses `d_type` directly without per-entry `stat()` syscalls for non-symlinks. |
| 6 | `vith/commands/global_cmd.py:161-221` (`_global_execute_move_or_copy`)[^src-global] | Only static endpoints `0` and `$` take the $O(n)$ single-pass fast path; static interior numeric destinations like `:g/pat/m 1` or `:g/pat/m 100` fall into `_IndexedLineChunks` ($O(m \sqrt{n})$). | Measured `:g/x/m 1`: 10.7 ms @ 4k, 35.2 ms @ 10k, **92.0 ms @ 20k**. Any static numeric address `k` (`0 <= k <= len(lines)`) can be resolved in a single $O(n)$ partition pass (handling the exact Vim two-pass semantics cleanly), reserving `_IndexedLineChunks` for relative addresses (`.`, `+N`, `-N`, marks). |
| 7 | `vith/commands/completer.py:39-83` (`_filetype_aliases`, `_filetype_display_names`, `FiletypeCompleter`)[^src-completer] | Calls `pygments.lexers.get_all_lexers()` **twice** on first `:set ft=<Tab>` (once per cached helper) and linearly scans all ~1,200 aliases instead of `bisect`. | Unify into one cached `(sorted_aliases, display_names)` helper and binary-search with `bisect_left`. |

## Fix Direction

1. Use `splice_buffer_lines` (or direct character-offset splice) in `_shift_lines` (`vith/key_bindings.py`).[^src-kb]
2. Add an optional `append(location, text, encoding='utf-8')` method on `EditorIO` (defaulting to read-concat-write for non-local/gzip backends, overridden in `FileIO` with `io.open(location, 'a', encoding=encoding)`), and use it in `_write_append_file` with UTF-8 fallback when `UnicodeEncodeError` occurs.[^src-files][^src-io]
3. Guard CR/CRLF counting and replacement in `EditorBuffer._read` with `if '\r' in text:`.[^src-eb]
4. In `sort_lines`, parse numeric/casefolded keys once when `unique=True` and deduplicate adjacent elements in $O(1)$ extra space.[^src-editing]
5. Use `os.scandir` in `DirectoryIO.read` (sorting directory/file names identically).[^src-io]
6. Extend the $O(n)$ static fast path in `_global_execute_move_or_copy` to handle static numeric destinations (`stripped_dest.isdigit()`) while keeping `_IndexedLineChunks` for relative/dynamic destinations, verifying exact equivalence against the chunked reference across move/copy and edge positions.[^src-global]
7. Merge `_filetype_aliases` and `_filetype_display_names` over one shared cached `get_all_lexers()` scan and use `bisect.bisect_left` in `FiletypeCompleter.get_completions`.[^src-completer]
