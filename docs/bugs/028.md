# `:set` option map duplicated between `commands.py` handlers and `preview.py` `_apply` chain

**Category:** duplication · **Area:** `vith/commands/commands.py`, `vith/commands/preview.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* Registry side: `@set_cmd` handlers for 16+ options,
  [`vith/commands/commands.py:435-710`](../../vith/commands/commands.py).
* Preview side: [`vith/commands/preview.py:74-104`](../../vith/commands/preview.py)
  re-implements the mapping as a manual `elif` chain.
* Drift already present: the previewer covers `hlsearch`, `number`, `ruler`,
  `relativenumber`, `cursorline/column` and `colorcolumn`, but **not**
  `tabstop` or `scrolloff`; any newly added set command must be added twice.

## Impact

Feature lag between actual behaviour and live preview; two places to update
for every new option.

## Fix direction

Drive the preview from the real mechanism: snapshot editor state
(`CommandPreviewer.save/restore` already do), traverse the option-table
(small spec table mapping option → attribute/value coercion), or simply
defer to the actual `SET_COMMANDS` handlers in preview mode with the
message side effects disabled.
