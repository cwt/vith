# Vim command semantics deviations: quitting and `:b`

**Category:** wrong logic / Vim semantics · **Area:** `vith/commands/commands.py`, `vith/window_arrangement.py`, `vith/commands/completer.py`, `vith/layout.py` · **Found at:** deep review, hg rev 87de3a3 (2026-11-08) · **Re-validated:** 2026-11-08 at hg rev 251 (tip; code identical to the audit revision)

## A. Quit semantics count buffers, not windows (medium)

### Summary

Vim `:q` closes the current *window* and only exits when that was the last window — hidden buffers are fine. Vith counts `editor_buffers` (every buffer, including hidden ones) and has no window-close step at all:

```python
elif not all_ and len(ebs) > 1: show_message('%i more files to edit')
```

So with one visible window and N buffers in total, `:q` refuses to exit with “%i more files to edit” (N−1 messages), instead of closing the window. `quit` contains no window-close logic whatsoever.

`:wqa` (`write_and_quit_all`) writes only the *active* buffer (`eb.write()`), then delegates to `quit(editor, all_=True, force=False)`, whose dirty check re-scans *all* buffers. With any other dirty buffer the user sees “No write since last change (add ! to override)” and no exit — despite the command name promising “write + quit all”.

### Evidence

* [`vith/commands/commands.py:327-342`](../../vith/commands/commands.py)[^src-cmd] — `quit`: `ebs = editor.window_arrangement.editor_buffers` (`:331`); dirty check over all buffers (`:334-335`); `elif not all_ and len(ebs) > 1:` (`:338`); `editor.show_message('%i more files to edit' % (len(ebs) - 1))` (`:339`); only then `editor.application.exit()` (`:342`).
* [`vith/commands/commands.py:345-351`](../../vith/commands/commands.py) — `qa`/`quit_all` delegate with `all_=True`.
* [`vith/commands/commands.py:390-399`](../../vith/commands/commands.py) — `wqa` writes only the active buffer (`:395-398`) then calls `quit(editor, all_=True, force=False)` (`:399`).

## B. `:b` requires an exact location match while its completer promises substring, and indices are 0-based (medium)

### Summary

Three places disagree about what `:b <name>` means:

* `BufferNameCompleter.get_completions` yields when `text in location` (substring; its own docstring says “appears anywhere in the buffer name”).
* `WindowArrangement.go_to_buffer` jumps only when `eb.location == buffer_name` or a digit index matches — completing a substring and pressing Enter silently does nothing.
* Numeric matching is 0-based (`(buffer_name).isdigit() and int(buffer_name) == i` with `i` from `enumerate(editor_buffers)`), and `BufferListOverlay` displays the same 0-based index (`'%3i ' % info.index`); Vim buffer numbers are 1-based. The overlay's digit filter matches `str(info.index)` too.

### Evidence

* [`vith/commands/completer.py:27-44`](../../vith/commands/completer.py)[^src-comp] — substring completer (`:43-44`).
* [`vith/window_arrangement.py:369-378`](../../vith/window_arrangement.py)[^src-wa] — exact-or-0-based-index `go_to_buffer` (`:376-378`).
* [`vith/layout.py:292`](../../vith/layout.py) — overlay renders `info.index` raw; indices come from `list_open_buffers` (`window_arrangement.py:540`, `enumerate(self.editor_buffers)`).

## Impact

* **A:** daily-driver friction — `:q` appears to “not quit” after closing splits; `:wqa` appears broken whenever more than one buffer is dirty.
* **B:** `:b <substring>` (the documented completion flow) silently fails; `:b <n>` is off-by-one versus Vim muscle memory.

## Fix direction

* **A:** implement Vim's window-vs-app distinction: `:q` closes the active window when `active_tab.window_count() > 1`, exits only from the last window (and only when nothing is dirty, honoring `!`); for `:wqa`, either write *all* buffers as the name promises or abort with a single explicit E-style message — and test both paths.
* **B:** resolve in order: exact location → unique substring (error on ambiguity, as Vim does) → 1-based numeric index. Align `BufferListOverlay` display with the same numbering (or clearly label it as 0-based if kept intentionally).

## Fix record (2026-11-08, hg rev 257)

* **A:** `:q` now closes the current window/tab (Vim semantics) and exits only on the last window (hidden buffers no longer block it); `:qa` exits; `:wqa` writes *every* dirty buffer and exits, aborting (with the write's own message) when any write fails.
* **B:** `go_to_buffer` resolves exact location → unique substring (ambiguous → `E93`, none → `E94`) → 1-based buffer number; `BufferListOverlay` displays 1-based numbers and its digit filter matches the displayed numbering.
* 6 command tests in `tests/test_quit_and_goto.py` + `go_to_buffer` resolution test in `tests/test_window_arrangements.py`.
