# `e`/`E` pass the whole document as a single “line” to `prev_cell_offset`

**Category:** wrong logic (fragile invariant) · **Area:** `vith/key_bindings.py` (`_move_to_end_of_word_cell`) · **Found at:** deep review, hg rev 87de3a3 (2026-11-08)

## Summary

`e`/`E` compute an exclusive word end via `doc.find_next_word_ending`, then step back one cell with `prev_cell_offset(doc.text, absolute_end, 1)`. The function contract is `(line, col)` — a single line and a line-local column. Passing the entire multi-line `doc.text` and an absolute offset only works because combining marks never attach across `\n` ([014](014.md) invariant). If a word ends at column 0 of the next line (empty-line edge), the backward walk crosses `\n` onto the previous line’s last cell.

## Evidence

* [`vith/key_bindings.py:289-295`](../../vith/key_bindings.py)[^src-kb]:
  ```python
  def _move_to_end_of_word_cell(event, WORD):
      end = doc.find_next_word_ending(count=event.arg, WORD=WORD)
      if end:
          buff.cursor_position = prev_cell_offset(doc.text, buff.cursor_position + end, 1)
  ```
* [`vith/thai.py:279-296`](../../vith/thai.py)[^src-thai] — `prev_cell_offset` first checks `line.isascii()` (whole-document scan) and walks `is_combining_char(line[idx])` with no newline stop; correctness depends on `\n` never being combining.

## Impact

* Single-line documents: correct by accident. Multi-line documents with blank-line word ends: cursor can land on the previous line.
* The whole-document `isascii()` in every `e`/`E` also defeats the per-line ASCII fast-path the Thai word motions carefully preserve ([056](056.md)).

## Fix direction

Translate the absolute end to `(row, col)` first (`doc.translate_index_to_position(buff.cursor_position + end)`), then `prev_cell_offset(doc.lines[row], col, 1)`, then `doc.translate_row_col_to_index(row, new_col)`. Add a multi-line regression test with a blank line between words.
