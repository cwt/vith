# Thai patch machinery: `TextObject.operator_range` rollback gap + fragile prompt_toolkit internals

**Category:** wrong logic / partial patching + fragility · **Area:** `vith/thai.py` (`install_prompt_toolkit_thai_patches`, `_install_window_copy_body_patch`, `_install_renderer_patch`) · **Found at:** deep review, hg rev 87de3a3 (2026-11-08) · **Re-validated:** 2026-11-08 at hg rev 251 (tip; code identical to the audit revision)

## A. `TextObject.operator_range` patch escapes the install rollback

### Summary

The installer's `except` rollback iterates `applied` (Document + KeyProcessor triples). The `TextObject.operator_range` wrapper installed inside the same `try` is never appended to `applied`. A failure after that point (for example the self-test at the end of the `try`) restores `Document` yet leaves `TextObject.operator_range` patched — a half-patched state the graceful-fallback contract ([`thai.py:1363-1365`](../../vith/thai.py), referencing [005](005.md)) explicitly forbids.

`Window._copy_body` and `_output_screen_diff` are installed *after* the `try` ([`thai.py:1455-1456`](../../vith/thai.py)), so they are outside rollback entirely; today they fail soft (`warn + return False`), but the asymmetry is load-bearing if they ever raise.

### Evidence

* [`vith/thai.py:1358-1457`](../../vith/thai.py)[^src-thai]:
  * `applied` receives only Document triples, `applied.append((Document, method_name, current))` (`:1385`), and at most two KeyProcessor triples (`:1395`, `:1403`).
  * No `applied.append` anywhere in the `TextObject` block (`:1405-1440`; the assignment at `:1440` is the last step inside the `try`).
  * `except` (`:1449-1453`) loops `applied` only; the raise after `:1440` is the mockable self-test (`:1442-1448`).

## B. Fragile prompt_toolkit internals in the renderer/window wrappers

The two renderer patches (added for [062](062.md)) are the most fragile code in the tree. They work against `prompt_toolkit 3.0.53` but encode five private-contract assumptions (all confirmed at the cited lines):

1. **Positional `args[]` with partial signature checks** — `args[1]/[2]/[5]/[7]/[11]` for `output/screen/previous_screen/is_done/size` and `args[6]` for `has_focus`. Checks only `params[2]=="screen"` / `params[5]=="previous_screen"` (renderer, `:1165-1170`) or the first six params (window, `:1038-1045`); `size`'s name is never checked (`:1173-1177`, mis-derivation at `:1185`). Runtime-corroborated: ptk 3.0.53's actual parameter lists make the indices correct *today*; one inserted positional parameter silently binds the wrong arg and mis-derives the autowrap column.
2. **Private `_CHAR_CACHE`** (`thai.py:46`, `:1127`) — not a public API.
3. **`"[ZeroWidthEscape]" not in style`** (`thai.py:1110-1114`) — substring match on a formatted-text style string; a prompt_toolkit token rename silently disables the hide filter and merges escapes into buffer text.
4. **Dict insertion-order mouse hack** (`thai.py:1130-1134`) — `del` + reinsert `(lineno, col)` last so the `{v: k for k, v in rowcol_to_yx.items()}` reverse-lookup resolves `(sy, sx)` to the base character; relies on an undocumented ordering guarantee.
5. **Per-frame `output.write/write_raw` monkey-patching** (`thai.py:1224-1226`, `:1243-1249`, restored in `finally`) — instance-attribute swap; concurrent `Application` instances (tests, nested `run_in_terminal`) can interleave; `saved_escapes` mutates `screen.zero_width_escapes` rows that may be shared.

Secondary notes (confirmed): `snap_to_cell_start(line, len(line))` returns `len(line)` (a valid boundary the name suggests would never snap; called with `min(column, len(target_line))` at `:827`); `prev_row[x - 1] = _SARA_AM_POISON` mutates `previous_screen` in place (`:989`, `:1009`, and `:1011` also poisons `[x]`) — safe only because ptk discards the old screen reference after the diff (`renderer.py:709-710`), an uncommented assumption; `_LibThaiWrapper.find_breaks` de-duplicates with `!=` only, no `<` monotonicity check (`:370-377`).

### Impact

* **A:** on an incompatible prompt_toolkit build the fallback advertises “unpatched Document” while `TextObject` still applies Thai inclusivity/snapping — the exact hybrid [005](005.md) was filed to prevent, now one patch-site over.
* **B:** a routine prompt_toolkit upgrade can silently disable Thai right-margin/SARA-AM rendering (no hard failure — Thai diagnostics just look wrong), the worst kind of regression. Validated exposure sharpening: today `_output_screen_diff` receives `size` as a kwarg whose name is never checked, so a newly inserted positional parameter mis-binds silently.

### Fix direction

* **A:** append `(_PtkTextObject, "operator_range", _orig_operator_range)` to `applied` before assignment; move window/renderer installs inside the `try` (or wrap them with their own install/rollback pair); bind the closure original via a default argument (latent hardening — see validation).
* **B:** bind arguments by name (`inspect.signature(...).bind(*args, **kwargs)`); import `_CHAR_CACHE` behind a fallback (or construct `Char` directly); check the escape token object rather than its style string; confirm (or avoid) the dict-ordering guarantee; serialize the output-write patch per `Application` (or document the single-instance assumption); add a prompt_toolkit-version matrix test that fails loudly on signature drift.

## Fix record (2026-11-08, hg rev 254)

* **A:** `TextObject.operator_range` is registered in `applied` before installation and the window/renderer installs moved inside the same `try` (each appending its own rollback triple), so any post-patch failure — including the self-test, now factored into `_thai_install_selftest()` — rolls everything back; the closure original is bound via a default argument.
* **B:** both wrappers resolve `has_focus`/`output`/`screen`/`previous_screen`/`is_done`/`size` by parameter **name** against the full 15/13-parameter expected prefixes via `_named_arg_resolver` (fail loudly → patch skipped on drift), `_CHAR_CACHE` has a `Char(...)` construction fallback, the `ZeroWidthEscape` style token is imported from `prompt_toolkit.token` (ptk's own constant, `renderer.py:809`), the mouse dict-order trick cites ptk's `yx_to_rowcol` build at `layout/containers.py:1828`, and the per-frame `output.write/write_raw` swap is guarded against re-entrancy via `output._vith_write_swap_active`.
* 4 tests in `tests/test_thai.py`: TextObject rollback on simulated self-test failure, window/renderer signature-drift fail-loud, and the shared escape token.
