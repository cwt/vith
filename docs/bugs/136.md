# Tab in the search buffer inserts indentation

**Category:** wrong logic / key-binding filter · **Area:** `vith/key_bindings.py` (`insert_indentation`), `vith/editor.py` (`search_buffer`) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** open

## Summary

The custom Insert-mode Tab binding is filtered with:

```python
@kb.add(
    'tab',
    filter=vi_insert_mode
    & ~has_focus(editor.command_buffer)
    & whitespace_before_cursor_on_line,
)
def insert_indentation(event):
    _insert_indentation(editor, event.app.current_buffer)
```

([`vith/key_bindings.py:370-383`](../../vith/key_bindings.py#L370-L383)).

The search toolbar is a separate `Buffer` created with `multiline=False`
([`vith/editor.py:292-298`](../../vith/editor.py#L292-L298)) and the layout enables
Vi mode for it ([`vith/layout.py:622-626`](../../vith/layout.py#L622-L626)).
While it has focus, `vi_insert_mode` is true and only the **command** buffer is
excluded. With an empty search or whitespace before the cursor, the binding
wins and calls `_insert_indentation` on the search buffer.

## Evidence

Probe: focus `editor.search_buffer`, set Vi `INSERT` mode, feed a single
`Tab` key press:

```text
search text after Tab: '        '   (8 spaces = editor.tabstop)
current buffer:        Buffer(name='', text='        ')
```

The layout then renders an eight-space search pattern and incremental search
matches nothing. Pressing `/` again later shows the corrupted text until the
user clears it.

The same binding is intended to be disabled for the command line (and is), but
the search toolbar was forgotten.

## Impact

* One stray Tab while entering a search silently destroys the pattern.
* Because the search buffer is also used for `*`/`#` history and `n`/`N`,
  the corrupted pattern can persist in history if accepted.
* It is especially easy to hit on an empty search line (the filter's
  `not before_cursor` branch).

## Fix direction

* Add `& ~has_focus(editor.search_buffer)` to the binding filter, or replace
  the ad-hoc filters with a shared `in_document_insert_mode` condition that
  excludes both toolbars.
* Add a regression test that feeds Tab in the search buffer and asserts the
  search text is unchanged (or that Tab is treated as a no-op).
