# `tools/bench_plans.py` crashes with `AssertionError` on `U+0EC7`

**Category:** tooling / Unicode drift · **Area:** `tools/bench_plans.py`, `vith/thai/classify.py`, `vith/completion.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** open

## Summary

Finding [191](191.md) removed unassigned codepoint `U+0EC7` (`GC=Cn`) from `_THAI_COMBINING_CPS` in `vith/thai/classify.py`, reducing the set size from 34 to 33 (16 Thai + 17 Lao combining marks).[^src-classify] Three places were left out of sync:

1. **`tools/bench_plans.py` crashes immediately:** `bench_thai_plan()` asserts `len(thai._THAI_COMBINING_CPS) == 34` and loops over `(0x0EBA, 0x0EC7, 0x0ECE)` asserting `is_thai_combining(cp)` and `is_combining_char(chr(cp))`.[^src-bench]
2. **`DocumentWordsCompleter._WORD_RE` still includes `\u0ec7`:** `r'[\w\u0e31-\u0e3a\u0e47-\u0e4e\u0eb1-\u0ebc\u0ec7-\u0ece]+'` treats unassigned `U+0EC7` as a word character (`\u0ec8-\u0ece` are the real Lao tone/combining marks).[^src-comp]
3. **Stale comments in `classify.py`:** Comments at lines 15, 37, and 104 still state `34-codepoint set of Thai (16) and Lao (18)` and `0x0EC7..0x0ECE`.[^src-classify]

## Evidence

Running `poetry run python tools/bench_plans.py`:

```text
Traceback (most recent call last):
  File ".../tools/bench_plans.py", line 221, in <module>
    bench_thai_plan()
  File ".../tools/bench_plans.py", line 47, in bench_thai_plan
    assert len(thai._THAI_COMBINING_CPS) == 34, "Expected 16 Thai + 18 Lao combining marks"
AssertionError: Expected 16 Thai + 18 Lao combining marks
```

## Fix Direction

1. Update `tools/bench_plans.py` to assert `len(thai._THAI_COMBINING_CPS) == 33` (`16 Thai + 17 Lao`) and test `0x0EC8` (and `not thai.is_thai_combining(0x0EC7)`).
2. Narrow `DocumentWordsCompleter._WORD_RE` in `vith/completion.py` from `\u0ec7-\u0ece` to `\u0ec8-\u0ece`.
3. Update the count/range comments in `vith/thai/classify.py` from `34`/`18` to `33`/`17` (`U+0EC8..U+0ECE`).
4. Add a smoke test running `bench_thai_plan()` in `tests/` so future Unicode table updates cannot silently break `tools/bench_plans.py`.
