# `:w` / `:wq` / `:up` / `:x` reject the current file's own path

**Category:** wrong logic / write guard · **Area:** `vith/commands/commands.py` (`write`, `save_as`, `write_command`) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** open

## Summary

The overwrite guard treats *any* existing explicit target as a foreign file. It never compares the target with the active buffer's own `location`. Consequently the most common "write the current file by name" forms fail:

* `:w /path/to/current.txt`
* `:w %`
* `:wq %`
* `:up %`
* `:x %`
* `:sav /path/to/current.txt`

All of these write successfully in Vim without `!`. Vith reports `File exists (add ! to override)` and leaves the file untouched.

## Evidence

* `write()` checks the explicit location before it even resolves the active buffer:

  ```python
  if location and not force and os.path.exists(os.path.expanduser(location)):
      editor.show_message('File exists (add ! to override)')
      return False
  eb = editor.window_arrangement.active_editor_buffer
  ```

  ([`vith/commands/commands.py:772-783`](../../vith/commands/commands.py#L772-L783)).

* `save_as()` duplicates the same guard without a same-file exemption
  ([`vith/commands/commands.py:995-1010`](../../vith/commands/commands.py#L995-L1010)),
  and the partial-range write branch duplicates it a third time
  ([`vith/commands/commands.py:914-922`](../../vith/commands/commands.py#L914-L922)).

* Probe (untitled buffer named by `:w` first, then the same path written again):

  ```text
  :w /tmp/opencode/percent.txt  -> 'File exists (add ! to override)'
  file contents                 -> 'old\n'   (unchanged)
  ```

* Vim comparison on the same file: `:w <same-path>` writes and clears
  `&modified`; `:saveas <same-path>` also succeeds.

## Impact

* Everyday macros and muscle memory (`:w %`, `:wq %`) fail on a named buffer.
* `:wq %`/`:x %` additionally fail to quit because the write returned `False`.
* `:sav <current-path>` cannot re-save under the current name.
* The workaround (`:w!`) is destructive if the user has a typo in the path.

## Fix direction

1. Resolve the target once (`os.path.abspath(os.path.expanduser(target))`) and
   compare it with the buffer's normalized `location` (also compare
   `os.path.realpath` to tolerate symlinks).
2. Exempt the same file from the overwrite guard, or move the guard into
   `EditorBuffer.write()` where both the target and `self.location` are known.
3. Deduplicate the three guards so `write()`, `save_as()`, and the
   partial-range branch cannot drift again.
4. Add regression tests for `:w %`, `:wq %`, `:up %`, `:x %`, and
   `:sav <current-path>`; the existing tests only cover an *untitled*
   buffer writing to an existing path.
