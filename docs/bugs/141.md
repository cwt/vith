# Double-width CJK/emoji break visual-column cursor and block logic

**Category:** wrong logic / display-width model · **Area:** `vith/thai/clusters.py` (`_cell_ordinal`, `_start_of_cell_ordinal`), `vith/cold_text.py` (`_cursor_vertical`), `vith/thai/patches.py` (block selection) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** open

## Summary

`_cell_ordinal(line, col)` returns the index of the cluster in `cell_starts`,
not the terminal column:

```python
starts = cell_starts(line)
...
return max(0, bisect_right(starts, col) - 1)
```

([`vith/thai/clusters.py:124-143`](../../vith/thai/clusters.py#L124-L143)).

Its docstring states "every Thai/Lao cluster is exactly one terminal cell: its
ordinal == its visual column". Thai/Lao base characters are width 1, so this
holds there. CJK ideographs, full-width forms, and most emoji are width 2
(`get_cwidth(ch) == 2`), so cluster ordinal `n` is not visual column `n`.

`ColdTextBuffer._cursor_vertical` uses the ordinal as the remembered visual
column and maps it back with `_start_of_cell_ordinal`
([`vith/cold_text.py:214-262`](../../vith/cold_text.py#L214-L262)).
`_visual_block_ordinal_bounds`/`_thai_selection_ranges` use the same ordinal
space for the block rectangle
([`vith/thai/patches.py:794-912`](../../vith/thai/patches.py#L794-L912)).

## Evidence

Buffer:

```text
你好
abcdef
```

Cursor on `好` (codepoint column 1; visual column 2). Press `j`:

```text
result row=1, col=1   # 'b' (visual column 1)
expected             # 'c' (visual column 2)
```

`_cell_ordinal('你好', 1)` returns `1`, so a vertical move to an ASCII row
lands one column left of where it should. The same skew appears in a visual
block (`<C-v>`) that spans rows with different numbers of CJK characters;
the rectangle is computed in cluster ordinals, not display columns. The
renderer's `TabsProcessor` patch already uses `get_cwidth` for tab expansion
([`vith/thai/patches.py:689-773`](../../vith/thai/patches.py#L689-L773)),
so the rest of the cursor/selection stack is now inconsistent with it.

## Impact

* `j`/`k` drift on files containing CJK, full-width punctuation, or emoji.
* Visual-block selections cover the wrong cells; operators (`d`, `y`, `I`,
  `A`) can act on the wrong range.
* Mixed Thai + CJK files show both correct Thai behavior and incorrect CJK
  behavior, which is hard to diagnose.

## Fix direction

1. Define the cell ordinal in **terminal columns** (or a `(column, start, end)`
   map) rather than cluster indices. Build a prefix array of display widths
   with `get_cwidth` and binary-search it.
2. Update `_cell_ordinal`, `_start_of_cell_ordinal`, `_cursor_vertical`, and
   the block-rectangle helpers together; keep the Thai fast path (all width 1)
   direct.
3. Test `j`/`k`, `<C-v>d`, and `<C-v>I` across Thai, CJK, emoji, and mixed
   rows with an ASCII target row.
