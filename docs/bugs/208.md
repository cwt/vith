# ReDoS guard bypassed by nested groups and outer `{m,n}` repeats

**Category:** commands / regex safety · **Area:** `vith/commands/substitution.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** fixed (hg rev 464)

## Summary

`is_unsafe_regex()` guards `:substitute` and `:global` against catastrophic backtracking using flat single-level group regexes:[^src-unsafe]

* `_UNSAFE_NESTED_QUANTIFIER = re.compile(r'\([^()]*[+*?][^()]*\)[+*]')`
* `_UNSAFE_QUANTIFIED_GROUP = re.compile(r'\(([^()]*)\)([+*])')`
* `_strip_regex_literals` removes character classes via `re.sub(r'\[[^\]]*\]', '', ...)`[^src-strip]

Three flaws result:

1. **Nested group bypass (false negative):** Because `[^()]*` forbids parentheses inside the group body, `((a)+)+$` and `(?:(a+))+$` fail to match either regex (the inner `(a)+` has no internal quantifier, and the outer group contains parentheses), hanging Python's `re` engine in exponential time on `'a' * 30 + 'b'`.
2. **Outer counted-repeat bypass (false negative):** The outer quantifier only matches `[+*]`, missing `{m,n}` / `{m,}` repeats such as `(a+){5,}$`.
3. **Leading-`]` character-class misparse (false positive):** In Python regex syntax, `]` immediately after `[` or `[^` is a literal member of the character class (`[]+(a+)+]`), but `r'\[[^\]]*\]'` stops at the leading `]`, exposing `+(a+)+]` and falsely rejecting a linear character-class match.

## Evidence

Direct probe of `is_unsafe_regex(editor, pattern)`:

| Pattern | True complexity | Expected `is_unsafe_regex` | Actual |
| :--- | :--- | :--- | :--- |
| `((a)+)+$` | Exponential ($O(2^n)$) | `True` | `False` |
| `(?:(a+))+$` | Exponential ($O(2^n)$) | `True` | `False` |
| `(a+){5,}$` | Polynomial/exponential backtracking | `True` | `False` |
| `[]+(a+)+]` | Single character class ($O(n)$) | `False` | `True` |

## Fix Direction

1. Parse regex structure with `re._parser` (`sre_parse`) AST walking — or a lightweight parenthesis-stack scanner — tracking whether *any* descendant of a quantified group (`+`, `*`, or `{m,n}` with `n > 1` or unbounded) carries a variable quantifier or overlapping alternation.
2. In `_strip_regex_literals`, advance past a leading `]` / `^]` inside `[...]` so valid POSIX/Python character classes are stripped intact.
3. Add regression tests covering `((a)+)+$`, `(?:(a+))+$`, `(a+){5,}$`, and `[]+(a+)+]`.
