# Mouse focus does not update `WindowArrangement.active_window`

**Category:** wrong logic / focus state · **Area:** `vith/layout.py`, `vith/window_arrangement.py`, `vith/commands/*` · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** fixed

## Summary

Vith has two notions of the active window:

1. prompt_toolkit's layout focus (`Application.current_buffer`), changed by
   mouse clicks and by `layout.focus(...)`;
2. `WindowArrangement.active_tab.active_window`, changed only by explicit
   window-arrangement operations (`c-w c-w`, splits, tab switches, closes).

`BufferControl` is created with `focus_on_click=True`
([`vith/layout.py:816-824`](../../vith/layout.py#L816-L824)), so a mouse click on
a split changes (1) without changing (2). Ex handlers almost universally use
`editor.window_arrangement.active_editor_buffer`
([`vith/window_arrangement.py:257-262`](../../vith/window_arrangement.py#L257-L262)),
so after a click they act on the old window.

## Evidence

Probe with buffers `A` and `B` in two horizontal splits, `B` active in
`WindowArrangement`, then focus `A`'s `pt_window` as a mouse click would:

```text
application.current_buffer is A.buffer   True
WA.active_editor_buffer is A             False
WA.active_editor_buffer is B             True
```

The next command `:2d` deletes line 2 from **B**, while the screen focus and
cursor are in **A**:

```text
A text  'A1\nA2\nA3'   (unchanged)
B text  'B1\nB3'       (mutated by :2d)
```

The same root cause affects:

* `:w` / `:wq` / `:up` — writes the wrong buffer's file,
* `:e` / `:enew` / `:b` / `:sb` — replaces the wrong window's buffer,
* `:q` / `:close` / `:only` / `:hide` — closes the wrong window,
* `:d` / `:y` / `:pu` / `:m` / `:t` / `:j` / `:s` / `:g` / `:normal`
  — mutates the wrong buffer,
* `:set` / `:setlocal` — changes options on the wrong buffer,
* `CommandPreviewer` — previews and restores the wrong buffer's tabstop and
  filetype overrides ([`vith/commands/preview.py:88-96`](../../vith/commands/preview.py#L88-L96)).

This is a realistic path because mouse support is on by default
(`Editor.enable_mouse_support = True`).

## Impact

* Silent edits/writes to the wrong file; a subsequent `:wq` can write and quit
  with the wrong window's changes.
* `:q`/`:close` can close a window the user did not click.
* Command previews can mutate and restore the wrong buffer's local options.

## Fix direction

1. Observe layout focus changes: either wrap the `focus_on_click` handler or
   add an `on_focus`/`focus_changed` callback that maps the focused
   `BufferControl`/`Window` back to its `window_arrangement.Window` and sets
   `active_tab.active_window`.
2. Alternatively, resolve the target buffer through
   `Editor.current_editor_buffer` (already focus-aware via the
   `_vith_editor_buffer_ref` back-reference) in every Ex handler; keep
   `active_editor_buffer` for non-interactive callers.
3. Add an end-to-end test: two splits, focus the non-layout-active one, run a
   mutating Ex command, and assert only the focused buffer changed.
