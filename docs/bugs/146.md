# Thai gate is not latched by `show_message`

**Category:** rendering / gate completeness · **Area:** `vith/editor.py` (`show_message`), `vith/thai/patches.py` (`_ThaiTextGate`, decay), `vith/layout.py` (`MessageToolbarBar`) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** open

## Summary

The Thai renderer gate is latch-only:

```python
class _ThaiTextGate:
    def note(self, text):
        if self.value or not text or text.isascii():
            return
        if _HAS_THAI_RE.search(text):
            self.value = True
```

([`vith/thai/patches.py:227-233`](../../vith/thai/patches.py#L227-L233)).

Callers report buffer text, locations, command/search text, and scratch info
text. `Editor.show_message()` — which renders in `MessageToolbarBar`
([`vith/layout.py:362-377`](../../vith/layout.py#L362-L377)) — only assigns
`self.message` and appends the history, never calls `note_document_text`
([`vith/editor.py:458-465`](../../vith/editor.py#L458-L465)).

`reset_thai_text_gate_if_all_buffers_ascii()` checks `editor.message` only to
decide whether to **decay** an already latched gate
([`vith/thai/patches.py:277-280`](../../vith/thai/patches.py#L277-L280)).
If the gate was never latched, a Thai message is displayed with the gate off
and the renderer skips `_sanitize_and_invalidate_sara_am`.

## Evidence

Probe on a fresh ASCII session:

```text
gate before show_message                      False
editor.show_message('ข้อความภาษาไทย')          False
editor.sync_with_prompt_toolkit()             False
```

A Thai buffer location does latch the gate (`EditorBuffer.__init__` notes
`self.location`), so the gap is specifically for strings that only reach the
screen through `editor.message` (for example an `E484` message containing a
Thai path that was not opened, or a Thai OS error). If such a message contains
SARA AM or combining marks near the right margin, the differential renderer
does not refresh the neighbor cells.

## Impact

* The documented invariant "strings that reach the screen are reported to the
  gate" is false for the message toolbar.
* Thai messages can render with stale combining marks on an otherwise
  ASCII-only session.
* The decay logic's message check is dead for the never-latched case.

## Fix direction

1. Call `note_document_text(self.message)` inside `show_message()` (and for
   `_messages` history if it can be shown without creating a buffer).
2. Alternatively, note the formatted tokens in `MessageToolbarBar.get_tokens`
   so any future message source is covered.
3. Add a probe that asserts `_THAI_GATE.value` is true after a Thai
   `show_message`, and a render smoke test with SARA AM in the toolbar.
