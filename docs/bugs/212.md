# `:substitute` `~` state corruption and non-slash flag stripping

**Category:** commands / substitute · **Area:** `vith/commands/substitution.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** open

## Summary

Two `:substitute` parsing/state defects were verified in `vith/commands/substitution.py`:

1. **Unexpanded `'~'` overwrites `editor.last_substitute_text`:** In Vim (`:help s/~`), unescaped `~` in a replacement string is replaced by the previous replacement string *before* recording the new "last replacement string". In `vith`, `_vim_replacement_function` expands `~` into `literal_buf` only for the compiled callable/template, while `_record_substitute_state` writes the raw `prepared.replace` (`'~'`) into `editor.last_substitute_text`.[^src-repl][^src-record] As a result, a second `:s/.../~/` (or bare `:s`) expands `~` to literal `'~'`.
2. **`_parse_substitute_flags` unconditionally strips `'/'`:** `parse_substitute_args` already strips `delim` from `fields[2]`,[^src-args] yet `_parse_substitute_flags` additionally runs `clean_flags = flags.replace('/', '')`.[^src-flags] When a non-slash delimiter is used (`:s#a#b#/`), the stray `'/'` is silently ignored instead of reporting `E488: Trailing characters: /`.

## Evidence

Live probe on `"a b c"`:

```python
handle_command(ed, "s/a/X/")
handle_command(ed, "s/b/~/")
handle_command(ed, "s/c/~/")
# Expected: "X X X"
# Actual:   "X X ~"  (ed.last_substitute_text became "~" after step 2)
```

And on `:s#a#b#/`:

* Expected: `E488: Trailing characters: /`
* Actual: succeeds silently (`'/'` stripped by `flags.replace('/', '')`).

## Fix Direction

1. Expand unescaped `~` (preserving `\~` as literal `~`) against `editor.last_substitute_text` when preparing the replacement string, and record that expanded string in `editor.last_substitute_text`.
2. Remove the hardcoded `flags.replace('/', '')` in `_parse_substitute_flags` (and strip at most a single closing delimiter in `parse_substitute_args`, rather than arbitrary repeated delimiters).
3. Add regression tests for chained `:s/.../~/` and `:s#a#b#/`.
