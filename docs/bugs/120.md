# Count before `i` / `a` is ignored

**Category:** Vim semantics · **Area:** `vith/key_bindings.py` (delegated to `prompt_toolkit`) · **Found at:** upstream triage 2026-11-09 (`prompt-toolkit/pyvim#133`) · **Fix status:** fixed

## Summary

`5itest<Esc>` should produce five copies of `test`; `vith` inserted once.

## Evidence

* `vith/key_bindings.py:146-398`[^src-kb] defines `x/X/s/r/~/e/E/$` with `_positive_count(event.arg)` handling, but has no `i`/`a`/`I`/`A` overrides — insert entry is inherited from `prompt_toolkit`, which drops the prefix count.
* Repro from upstream: normal mode `5ithis is just a test<Enter><Esc>` yields one line instead of five.

## Impact

* Breaks a common Vim idiom for repeated text; workaround is `5o...` or macros.

## Fix

* `vith/key_bindings.py` overrides `i` / `a` in navigation mode (excluding `vi_waiting_for_text_object_mode` so operator-pending `iw`/`aw` such as `diw` stays on the `prompt_toolkit` path). Entry records `(cursor, count)` in `buff._vith_insert_repeat` (`a` steps one character right first); the shared `escape` exit replays the typed region `count - 1` more times, then replicates the default cursor-left + selection-exit behavior.
* Regression tests in `tests/test_key_bindings_fixes.py`: `5itest<Esc>` → five copies, `2aX<Esc>` → `aXXbc`, uncounted insert parity, and text-object filter exclusion.
