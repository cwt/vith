# Valid zstd levels 10–22 are rejected by config

**Category:** config / cold text · **Area:** `vith/rc_file.py`, `vith/cold_text.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** fixed
> **Resolution note (2026-11-23):** Widened `cold_text_compression_level` validation from `0..9` to `0..22` to match zstd.


## Summary

`rc_file.py` validates `cold_text_compression_level` with
`0 <= value <= 9`, reporting `"expected an integer in 0..9"` for anything
higher.[^src-rc] The zstd compressor it configures explicitly supports levels
`1..22`.[^src-cold] The two modules disagree on the option's contract, so a
legitimate high-compression setting is skipped and the editor falls back to
level 1 with no sensible explanation.

## Evidence

| Config | Expected | Actual |
| :--- | :--- | :--- |
| `cold_text_compression = "zstd"`, `cold_text_compression_level = 12` | level 12 used | `expected an integer in 0..9`; level stays 1 |

## Fix Direction

1. Widen the validation upper bound to 22 (and the lower bound to 1 for zstd,
   while preserving the 0 meaning used by zlib/lzo if applicable) in
   `rc_file.py`, deriving the bound from the compression backend's declared
   range where practical.
2. Add regression tests for levels 1, 9, 10, 22, and 23 asserting accept/reject
   behavior matches the compressor.
