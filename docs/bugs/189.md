# `reload()` on an untitled buffer raises `TypeError`

**Category:** editor buffer / robustness · **Area:** `vith/editor_buffer.py`, `vith/io/backends.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`EditorBuffer.reload()` calls `self._read(self.location)` without checking
whether the buffer has a location.[^src-eb] For an untitled `[New file]`
buffer, `location is None`; the backend's `can_open_location()` calls
`os.path.expanduser(None)`, raising `TypeError`.[^src-io] The `:e` command path
guards this case,[^src-buffers] so the crash is reachable only through the
public `EditorBuffer.reload()` API (plugins/scripts), which is why the suite
misses it.

## Evidence

| Call | Expected | Actual |
| :--- | :--- | :--- |
| `eb.reload()` on `location=None` buffer | no-op or "No file name" message | `TypeError: expected str, bytes or os.PathLike object, not NoneType` |

## Fix Direction

1. Guard `reload()`: if `self.location is None`, either return early or call
   `self.editor.show_message('E32: No file name')`, matching `:e`'s guard.
2. Add a regression test calling `reload()` on a fresh untitled buffer asserting
   no exception and an unchanged buffer.
