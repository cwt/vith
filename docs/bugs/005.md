# Version-gate rollback is incomplete: KeyProcessor patches survive a failed install

**Category:** correctness · **Area:** `vith/thai.py` (`install_prompt_toolkit_thai_patches`) · **Found at:** deep review, hg rev 164 (2026-11-06)

## Summary

The graceful-fallback path removes the `Document` method patches only; the two
`KeyProcessor` patches that are installed before the self-test are left in
place, producing an inconsistent mixed state (cluster clamping active on top
of unpatched `Document` motion).

## Evidence

* [`vith/thai.py:941-953`](../../vith/thai.py): `_fix_vi_cursor_position` and
  `_start_timeout` are wrapped **before** the startup self-test at
  `vith/thai.py:956-961`.
* The `except Exception` path ([`vith/thai.py:962-966`](../../vith/thai.py))
  iterates only `applied` — the list of `Document` (+method, original) pairs —
  and the `KeyProcessor` originals are never recorded or restored.
* If the self-test fails (e.g. a future prompt_toolkit changes
  `get_cursor_right_position` semantics), `install_prompt_toolkit_thai_patches()`
  still patches `KeyProcessor._fix_vi_cursor_position` (cluster-snap clamp)
  against an unpatched `Document`; the hybrid relies on internal prompt_toolkit
  behaviour that the plan said not to rely on in fallback mode.
* The doc contract: [`thai_support_plan.md §4.1`](../thai_support_plan.md)
  requires "graceful fallback restoring the original function" without
  leaving partial patching.

## Impact

On incompatible prompt_toolkit builds the editor runs in an undefined
half-patched mode instead of the promised clean fallback; hard to reason about
and to debug.

## Fix direction

Record the KeyProcessor originals alongside the Document ones (into `applied`)
and restore them in the except path — or perform the self-test before touching
KeyProcessor at all.
