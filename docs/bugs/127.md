# Tab stop position calculation ignores character display widths (combining marks and CJK)

**Category:** correctness · **Area:** `vith/thai/patches.py`, `vith/layout.py` · **Found at:** user field report with screenshots comparing Vim and vith on `pentax.txt` (2026-11-12) · **Fix status:** fixed

## Summary

In Vim, tab characters advance to the next visual tab stop column (e.g. multiples of `tabstop = 8` on screen). In `vith`, when text preceding a tab contains zero-width combining characters (such as Thai vowels or tone marks) or double-width CJK characters, the tabs expand to incorrect widths, resulting in jagged, misaligned columns.

## Evidence

* User screenshot comparison between `/usr/bin/vim` and `vith` on `/home/cwt/Documents/pentax.txt`:
  * In Vim (`:set tabstop=8`): across all lines, the second column of text (`แม้ดูแปลกมีที่มา`, `พัฒนาเป็นเมาท์เค`, `บ้างอันเดอร์ไม่พอดี`, `ฟุ้งวจีมิตรภาพอวล`, etc.) starts at visual screen column 24.
  * In vith: line 1 text started at column 21, line 2 at column 29, line 6 at column 23, and line 7 at column 19.
* Root cause: `prompt_toolkit.layout.processors.TabsProcessor.apply_transformation` maintains a single `pos` counter:
  ```python
  for i, fragment_and_text in enumerate(fragments):
      position_mappings[i] = pos
      if fragment_and_text[1] == "\t":
          count = tabstop - (pos % tabstop)
          ...
          pos += count
      else:
          ...
          pos += 1
  ```
  `pos += 1` treats every character as having display width 1. For combining characters (e.g. Thai upper/lower vowels, tone marks where `get_cwidth(c) == 0`), `pos` increments by 1 even though the visual terminal column `x` did not advance. Consequently, `count = tabstop - (pos % tabstop)` calculates tab expansion from codepoint count instead of horizontal visual column.
* Similarly, for double-width characters (`get_cwidth(c) == 2`), `pos += 1` under-counts the visual column.

## Impact

* Any tab-delimited text containing Thai script, combining accents, or CJK characters has misaligned tab stops in `vith`.
* Tab stops vary from line to line depending on the number of combining marks rather than their visual width.

## Fix

* Wrap `prompt_toolkit.layout.processors.TabsProcessor.apply_transformation` in `_install_tabs_processor_patch` within `vith/thai/patches.py` (installed automatically during `install_prompt_toolkit_thai_patches()`).
* Track `visual_col` separately from `pos` (where `pos` continues to map fragment indices in `result_fragments` for `position_mappings`, while `visual_col` advances by `get_cwidth(char)`):
  * When `\t` is reached, `count = tabstop - (visual_col % tabstop)`.
  * `visual_col += count` and `pos += count`.
  * For non-tab characters, `visual_col += get_cwidth(char)` (skipping `[ZeroWidthEscape]`).
* Signature verification and rollback support via `_apply_patch` (consistent with `_install_window_copy_body_patch` and `_install_renderer_patch`).
* Regression tests in `tests/test_thai.py`:
  * Verification across all lines of `pentax.txt` aligning to visual column 24 under `tabstop=8` and multiples of 4 under `tabstop=4`.
  * Cursor mapping verification (`source_to_display` and `display_to_source`).
  * Double-width CJK alignment verification.
  * Rollback verification on self-test failure.
