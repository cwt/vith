# 27 lambda usages contradict the project's no-lambda coding rule

**Category:** readability (project style rule) · **Area:** several modules · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* Repo grep: **27** `lambda` occurrences across
  [`vith/layout.py`](../../vith/layout.py) (~16), [`vith/editor.py`](../../vith/editor.py),
  [`vith/commands/commands.py:727`](../../vith/commands/commands.py) (the
  `re.sub` transform callback), [`vith/key_bindings.py:84`](../../vith/key_bindings.py)
  (`save_before=(lambda e: False)`) and [`vith/completion.py`](../../vith/completion.py).
* Dominant pattern: `Condition(lambda: <flag>)` config plumbing —
  convertible to `@Condition`-decorated named functions (the codebase already
  does this e.g. `in_file_explorer_mode` in `key_bindings.py:156-159` and
  `wrap_lines` in `layout.py:532-534`).

## Impact

Violates the documented style rule (AGENTS.md "Coding Style": avoid lambdas
under all circumstances); slightly hurts debuggability and stack traces.

## Fix direction

Mechanical conversion: named module/creation-scope functions for `Condition`
inputs; a named `_substitute_line(line)` def for the `re.sub` callback; named
`_always_false(event)` for `save_before`.
