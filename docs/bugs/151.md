# Unoptimized-algorithm inventory (Round 9)

**Category:** performance / memory · **Found at:** Round 9 deep read-only analysis, 2026-11-20 (re-validated against tip `v0.15.0` / rev 384) · **Fix status:** open.

> **Validation note (2026-11-20):** Items 1–4 are carry-overs from Round 8 ([149](149.md)). Corrected stale line numbers on items 2, 3, and 6; re-scoped item 1 to constant-factor overhead (due to `prompt_toolkit.Buffer`'s single-string model); added re-latch safety constraints to item 4; noted `re._cache` mitigation on item 5; and replaced the flawed prefix-width-table fix direction on item 6.

## Findings

| # | Location | Issue | Evidence / validation notes |
| :-- | :-- | :-- | :-- |
| 1 | `vith/commands/ranges.py:227-264` (`replace_buffer_lines`) | Range edits materialize `list(eb.buffer.document.lines)`, join all lines with `'\n'.join`, and construct a fresh `Document`, even for a one-line change. | **Partially valid (constant-factor only):** `prompt_toolkit.buffer.Buffer` stores text as one immutable `str`, so even `Buffer.insert_text`/`delete` slice-concatenate the full text and build a new `Document` ($O(\text{file size})$). A slice/splice helper cannot change asymptotic complexity, only avoid splitting/rejoining untouched lines into a `list[str]`. |
| 2 | `vith/layout.py:675-717` (`EditorLayout.update`) | Resets `self._frames = {}` and only traverses `active_tab.root`; inactive-tab frames are dropped on every tab switch. | **Confirmed empirically:** switching Tab 0 (`vertical_scroll = 42`) → Tab 1 → Tab 0 recreates `pt_window` (`vertical_scroll` resets to `0`) and recreates `DocumentLexer` (`vith/lexer.py:45-53`), discarding Pygments lexer/sync and `BufferControl._fragment_cache`. |
| 3 | `vith/commands/global_cmd.py:61-109` (`_global_execute_move_or_copy`) | `is_move` runs `tagged.pop(cur_pos)` ($O(n)$), scans all `positions.items()` ($O(m)$), runs `tagged.insert` ($O(n)$), and scans `positions.items()` a second time ($O(m)$); copy runs `tagged.insert` + one `positions.items()` scan. | **Confirmed empirically:** `:g/x/m 0` on an all-`x` buffer took **42.9 ms / 1k**, **185.2 ms / 2k** (4.3×), **765.3 ms / 4k** (4.1×) — $O(m^2 + m \cdot n)$, ~6× slower than pre-rev-379 timings in [149](149.md). |
| 4 | `vith/thai/patches.py:254-279`, `291-339` (`reset_thai_text_gate_if_all_buffers_ascii`, `_sanitize_and_invalidate_sara_am`) | Once `_THAI_GATE` latches, every frame walks `new_screen.data_buffer` (twice per row: `L307-309` and `L319-321`) plus `prev_row`; decay runs only from `Editor.sync_with_prompt_toolkit()` (`vith/editor.py:541`) and checks all open buffers, so a hidden background Thai buffer keeps the gate latched. | **Known trade-off with a re-latch hazard:** switching back to an already-open Thai tab/buffer does not currently call `note_document_text(eb.buffer.text)`. Naive visible-only decay would leave `_THAI_GATE` false and break SARA-AM rendering until the next edit. Also `TabsControl` renders all tabs' short names, `BufferListOverlay` renders all buffer locations, and `command_buffer`/`search_buffer`/`editor.message` can hold Thai. |
| 5 | `vith/layout.py:297` (`BufferListOverlay.get_tokens`) | Calls `re.compile(re.escape(search_string))` on every frame while `:b ` is open. | **Negligible impact:** Python's `re.compile` already caches up to 512 compiled patterns in `re._cache`, so repeated frames do not recompile the automaton. `highlight_location` (`L256-285`) only searches for a literal substring and does not need regex at all. |
| 6 | `vith/commands/editing.py:428-466` (`_retab_line`) | Executes `from prompt_toolkit.utils import get_cwidth` inside the function on every line (`L429`) and calls `get_cwidth(ch)` on every non-whitespace character (`L463`), even on tab-free or pure printable-ASCII lines. | **Single-pass scan:** `_retab_line` already visits each character once; a prefix-width table would still call `get_cwidth` per character plus allocate an $O(L)$ list. |

## Fix direction

1. Optionally add a character-offset range-splice helper (replacing `text[start_idx:end_idx]`) for single/contiguous-range commands to avoid materializing and re-joining all lines; accept $O(\text{file size})$ string/undo cost inherent to `prompt_toolkit.Buffer`.
2. Retain frames in `EditorLayout._frames` for all live `(window, window.editor_buffer)` pairs across `window_arrangement.tab_pages`, pruning entries for closed tabs/windows/buffers on `update()` to prevent leaks.
3. Add an $O(n)$ single-pass fast path in `_global_execute_move_or_copy` for static endpoint destinations (`0` reversing matched lines, `$` preserving order) and use an order-statistic / block-list structure (or Fenwick tree + chunked list) for dynamic/relative addresses (`+N`, `-N`, `.`).
4. Merge the two `new_row.items()` loops in `_sanitize_and_invalidate_sara_am` into one pass. Only decay `_THAI_GATE` on visible buffers if tab/buffer switches re-latch via `note_document_text` and the check still covers all tab captions, overlay locations, `editor.message`, `command_buffer`, and `search_buffer`.
5. Replace `re.compile(re.escape(search_string))` in `BufferListOverlay` with a literal `str.find` loop in `highlight_location` (low priority).
6. In `_retab_line`, hoist `get_cwidth` to module level, fast-return lines with no `\t` when `expand_tab or not force or '  ' not in line`, and fast-path printable ASCII (`' ' <= ch <= '~'` → width `1`).
