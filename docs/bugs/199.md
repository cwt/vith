# CSV landmark quoting mismatch

**Category:** render / scroll-sync · **Area:** `vith/render.py` · **Found at:** Round 17 read-only re-audit (2026-11-23, `v0.16.4`) · **Fix status:** fixed

> **Resolution note (2026-11-23):** Landmark extraction now parses with `csv.reader` (fallback to raw split on `csv.Error`), matching `_render_csv_table`. Pinned with `test_199_csv_landmark_respects_quoting`.

## Summary

The table renderer parses with `csv.reader` (quoting-aware).[^src-table] The landmark extractor for the same `csv`/`tsv` format does `raw.split(delim, 1)[0]` on the stripped source line.[^src-landmark] A first cell containing a quoted delimiter (e.g. `"a,b",c`) is split mid-quote, so the heading anchor disagrees with the displayed table cell and scroll sync can attach to the wrong rendered row.

## Evidence

* `vith/render.py:383` — `reader = csv.reader(io.StringIO(normalized), delimiter=delimiter)`.
* `vith/render.py:511` — `first_cell = raw.split(delim, 1)[0].strip().strip('"').strip("'")`.
* Quoted-comma input yields different `first_cell` values on the two paths by construction.

## Fix Direction

1. Parse the landmark line with `csv.reader([raw], delimiter=delim)` (or `next(csv.reader(...))`) and take field 0, mirroring `_render_csv_table`.
2. Regression test: `"a,b",c` landmark equals `a,b`, not `"a`.
