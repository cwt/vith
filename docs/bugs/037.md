# Project venv lacks pytest/mypy — the doc-claimed verifications are not reproducible in-repo

**Category:** toolchain · **Area:** environment / dependency metadata · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* `pip list` in `/home/cwt/Env/vith` shows no `pytest` and no `mypy`
  (while the documented claims are "68 tests passing" /
  `mypy .` clean — [`speed_latency_plan.md §1.3`](../speed_latency_plan.md),
  [`thai_support_plan.md §5.1`](../thai_support_plan.md)).
* This review reproduced the runs only by mixing interpreters:
  `python3.14 -m pytest tests` with the venv's site-packages on `PYTHONPATH`
  (**68 passed**) and `~/.local/bin/mypy .` (**40 files, no issues**) — a
  fragile, non-reproducible setup.
* No CI config exists that would enforce the claims (see [025](025.md)).

## Impact

Anyone cloning the repo cannot re-verify the OKF bundles' `verified` signal
without improvising an interpreter mix; future drift will not be caught by
any automated hook.

## Fix direction

Pin `pytest` and `mypy` into the project environment (or add a
`requirements-dev.txt` / a `tests` extra in `setup.py`), and wire a CI job
running `pytest` + `mypy` + (optionally) `python tools/bench_plans.py`
against the same interpreter as the bundle figures
([032](032.md) sets the `python_requires` this depends on).
