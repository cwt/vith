# CSV/TSV rendering raises `csv.Error` on a bare `\r`

**Category:** live render / robustness · **Area:** `vith/render.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`_render_csv_table()` feeds the source text directly to
`csv.reader(io.StringIO(text), delimiter=delimiter)`.[^src-render] Python's
`csv` module treats a bare `\r` inside an unquoted field as an illegal newline
and raises `csv.Error`. File loading normalizes CR/CRLF, but a buffer can still
acquire a stray CR from paste, a mixed-endings file, or a shell-read command.
`render_document()` documents only `RenderDependencyError` and
`ParseIncompleteError`, so the escape violates its contract and is caught by
the generic handler ([171](171.md)) as a misleading "stale" condition.

## Evidence

| Input | Expected | Actual |
| :--- | :--- | :--- |
| `render_document('a,b\r1,2', filetype='csv')` | a rendered table (CR treated as line break) | `csv.Error: new-line character seen in unquoted field - do you need to open the file with newline=''?` |
| same for `filetype='tsv'` | — | same error |
| `'name,value\r\nalice,1\n'` | table | works (CRLF is accepted) |

A 250-case random-input fuzz of `render_document` produced 30 unexpected
exceptions, all of this CSV-bare-CR class.

## Fix Direction

1. Normalize line endings before parsing:
   `text = text.replace('\r\n', '\n').replace('\r', '\n')` in
   `_render_csv_table()` (consistent with `ansi_to_render_result()`'s
   normalization), then parse.
2. Add regression tests for bare `\r`, CRLF, and quoted fields containing
   newlines, asserting a table is produced and no exception escapes.
