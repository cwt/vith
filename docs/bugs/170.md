# `:j` / `:join` with a non-numeric argument raises `ValueError`

**Category:** commands / editing · **Area:** `vith/commands/editing.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`join_lines()` reads the optional count from `variables.get('cmd_arg')` and
converts it with a bare `int(cmd_arg)`.[^src-editing] The grammar's join branch
accepts a broad `cmd_arg` token (alphanumeric/`"`),[^src-grammar] so a typo
reaches `int()` unvalidated. Sibling commands validate the same argument:
`:sort` reports `E488`, `:retab` reports `E474` on `ValueError`.[^src-editing]
`handle_command()` has no exception guard,[^src-handler] so the error escapes
into prompt_toolkit's key-processing path instead of showing a Vim-style error.

## Evidence

Probes against `handle_command()` on a 3-line buffer (4 000 randomized command
strings across two seeds isolated this as the only non-quit crash class):

| Command | Expected | Actual |
| :--- | :--- | :--- |
| `:j x` | `E488: Trailing characters` message | `ValueError: invalid literal for int() with base 10: 'x'` |
| `:join foo` | same | `ValueError … 'foo'` |
| `:1,2j abc` | same | `ValueError … 'abc'` |
| `:j "`, `:j 1x` | same | `ValueError … '"'` / `'1x'` |

## Fix Direction

1. Wrap the conversion in `try/except ValueError` and validate the range,
   mirroring `retab_lines`:
   `if not cmd_arg.isdigit() or int(cmd_arg) < 1: editor.show_message('E488: Trailing characters: ...'); return`.
2. Add regression tests for `:j x`, `:join foo`, `:1,2j abc`, `:j 0`, `:j -1`
   asserting a message and an unchanged buffer.
