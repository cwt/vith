# `>>` / `<<` ignore `:set tabstop`

**Category:** Vim semantics · **Area:** `vith/key_bindings.py` · **Found at:** upstream triage 2026-11-09 (`prompt-toolkit/pyvim#102`) · **Fix status:** fixed

## Summary

`:set ts=2` + `>>` still indents by four spaces. `Tab` and `C-t` honor the setting; the shift operators do not.

## Evidence

| Path | Honors `tabstop`? |
| :--- | :--- |
| `Tab` / `C-t` → `_insert_indentation()` in `vith/key_bindings.py:116-123`[^src-kb] (`' ' * editor.tabstop` vs `'\t'`) | yes |
| `>>` / `<<` | no binding in `vith/key_bindings.py:146-398`; falls through to `prompt_toolkit` default indent (hardcoded width) |
| Catalog entry `('tabstop', 'tabstop', ('tabstop','ts'), 1)` in `vith/commands/commands.py:592-596`[^src-cmd]; default `tabstop = 4` in `vith/editor.py:86`[^src-ed] | — |

## Impact

* HTML/config editing with `ts=2` silently produces wrong indentation; contradicts `:set` catalog.

## Fix

* `vith/key_bindings.py` adds `>>` / `<<` chords (`_shift_lines`) honoring `editor.tabstop` / `expand_tab` over `event.arg` lines, with undo support and cursor on the first non-blank. Single `>` / `<` with a motion stays on the default `prompt_toolkit` operator path (residual, documented).
* Regression tests in `tests/test_key_bindings_fixes.py`: `ts=2` spaces, counted tab insert, mixed space/tab unindent, cursor placement, undo restore.
