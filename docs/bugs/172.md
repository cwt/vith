# `_has_good_render` is never reset

**Category:** live render / state leak · **Area:** `vith/render.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`_has_good_render` is set to `True` only in `_apply_result()`.[^src-render]
`_apply_error()` checks `incomplete and self._has_good_render` to decide whether
to retain the last render, but never sets the flag back to `False` when it
replaces the preview with a diagnostic (`RenderDependencyError`, or
`ParseIncompleteError` with no prior good render). Consequently, once *any*
successful render has occurred, the controller permanently believes it has a
good render to fall back to — even when the pane currently shows only an error
line.

## Evidence

Probe against `LiveRenderController`:

1. `_apply_result(...)` with a good Markdown result → `_has_good_render = True`.
2. `_apply_error(2, "Optional package 'rich-rst' is required", incomplete=False)`
   → preview text is the install hint; `_has_good_render` is **still `True`**.
3. `_apply_error(3, 'still broken', incomplete=True)` → stale-retention branch
   taken; title becomes `[Render: … (markdown • stale)]` over the install-hint
   text.

Per `docs/live_render.md` §6.1, the `• stale` badge means "last valid render
retained", which is false in step 3.[^src-doc]

## Fix Direction

1. In `_apply_error()`, set `self._has_good_render = False` in the branch that
   replaces the preview with a diagnostic (i.e. whenever the retention branch
   is not taken), so subsequent classification is correct.
2. Add a regression test for the good-render → dependency-error →
   parse-incomplete sequence asserting the install hint is not labeled stale
   and a subsequent good render clears the diagnostic.
