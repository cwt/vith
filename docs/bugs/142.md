# ReDoS guard still misses overlapping alternations

**Category:** security / regex guard · **Area:** `vith/commands/commands.py` (`_UNSAFE_NESTED_QUANTIFIER`, `_strip_regex_literals`, `substitute`, `global_command`) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** open

## Summary

The guard added for [123](123.md) is:

```python
_UNSAFE_NESTED_QUANTIFIER = re.compile(r'\([^()]*[+*?][^()]*\)[+*]')
```

([`vith/commands/commands.py:47-59`](../../vith/commands/commands.py#L47-L59)).
It only flags a quantified group that contains one of `+`, `*`, or `?`.
That misses two classic catastrophic forms:

* overlapping alternatives: `(a|aa)+$` (no inner quantifier),
* bounded repeats: `(a{1,3})+$`, `(\d{2,4})+$`.

Those patterns pass `_UNSAFE_NESTED_QUANTIFIER` and go straight to
`re.compile()`/`subn` in both `substitute()` and the `:g` path
([`:2224-2229`](../../vith/commands/commands.py#L2224-L2229),
[`:2956-2962`](../../vith/commands/commands.py#L2956-L2962)).

## Evidence

```text
_UNSAFE_NESTED_QUANTIFIER.search(_strip_regex_literals('(a|aa)+$'))    -> False
_UNSAFE_NESTED_QUANTIFIER.search(_strip_regex_literals('(a{1,3})+$'))  -> False
```

Timing for the Python `re` engine on a failing match (`'a'*n + '!'`),
measured in this environment:

| n | `(a|aa)+$` |
| ---: | ---: |
| 26 | 0.034 s |
| 28 | 0.083 s |
| 30 | 0.219 s |

The growth is exponential; 40 characters is already in minutes, and a
multi-megabyte line or an accidental long token can freeze the UI. `:s` and
`:g` both reach this path.

## Impact

* The documented ReDoS protection is bypassable with a common regex shape.
* A malicious or unlucky pattern can freeze the whole editor; no timeout is
  available from Python's `re` API.
* Users may believe [123](123.md) closed the class.

## Fix direction

1. Extend the static check to flag quantified groups whose body contains
   `|` with overlapping alternatives or a `{m,n}` repeat; a conservative
   "quantified group containing any `|` or `{`" rule is acceptable even if it
   over-rejects.
2. Cap pattern length and/or per-line input length before `subn`.
3. Consider running the match in a worker thread/process with a deadline, or
   use a regex engine with timeouts for untrusted patterns.
4. Add tests for `(a|aa)+$`, `(a{1,3})+$`, `(\w+\s?)+`, and `(a|b)+$`
   (the last should remain allowed).
