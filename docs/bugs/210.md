# TOML configuration shadowing and `[tabstop]` validation bugs

**Category:** configuration / TOML · **Area:** `vith/rc_file.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** fixed (hg rev 466)

## Summary

`apply_toml_config()` in `vith/rc_file.py` contains three option-merging and validation defects:[^src-apply]

1. **Top-level `tabstop = N` masks `[filetype_tabstops]`:** Line 366 computes `tabstop_table = toml_data.get('tabstop') or toml_data.get('filetype_tabstops')`. When a config defines top-level `tabstop = 4` (an integer, truthy) alongside `[filetype_tabstops]\npython = 2`, `tabstop_table` evaluates to `4`, `isinstance(tabstop_table, dict)` is `False`, and `[filetype_tabstops]` is completely ignored.
2. **`[tabstop]` / `[filetype_tabstops]` coerces booleans/floats and silently swallows errors:** Line 370 runs `editor.filetype_tabstops[str(ft)] = int(width)` inside `try ... except (ValueError, TypeError): pass`. `int(True)` evaluates to `1` before `FiletypeTabstops.__setitem__` can reject booleans; values above `_MAX_OPTION_INT` (`9999`) are uncapped; and invalid entries (`rust = -5`, `go = "bad"`) neither invoke `_report_rc_error` nor set `all_ok = False`.
3. **Top-level canonical names overwrite `[editor]` short aliases:** Lines 336–344 merge `[editor]` into `editor_table` and then call `editor_table.setdefault(key, value)` for top-level keys. If `[editor]` sets `ts = 2` and top-level sets `tabstop = 8`, both `'ts'` and `'tabstop'` coexist in `editor_table`; iterating `_CONFIG_OPTION_MAP` applies `'ts'` first and `'tabstop'` second, so the top-level fallback overwrites `[editor]`. The same inversion occurs when `[editor]` sets `colo` and top-level sets `colorscheme` (`editor_table.get('colorscheme', editor_table.get('colo'))`).

## Evidence

Live probes of `apply_toml_config`:

| Config payload | Expected | Actual |
| :--- | :--- | :--- |
| `{"tabstop": 4, "filetype_tabstops": {"python": 2}}` | `editor.filetype_tabstops["python"] == 2` | `4` (`[filetype_tabstops]` ignored) |
| `{"tabstop": {"python": True, "rust": -5, "go": "bad"}}` | `ok == False`, 3 errors reported, `python == 4` | `ok == True`, `errors == []`, `python == 1` |
| `{"tabstop": 8, "editor": {"ts": 2}}` | `editor.tabstop == 2` (`[editor]` wins) | `8` (top-level overwrote `[editor]`) |

## Fix Direction

1. Check `toml_data.get('tabstop')` (only when `isinstance(..., dict)`) and `toml_data.get('filetype_tabstops')` (when `isinstance(..., dict)`) explicitly without truthy scalar short-circuiting.
2. Validate per-filetype tabstop widths with the same `not isinstance(width, bool) and isinstance(width, int) and 1 <= width <= _MAX_OPTION_INT` rule used for scalar int options, reporting failures via `_report_rc_error` and setting `all_ok = False`.
3. Track which target `attr_name`s (and colorscheme) were already populated by `[editor]` before merging top-level fallback keys so `[editor]` always takes precedence regardless of alias spelling.
