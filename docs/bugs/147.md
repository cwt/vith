# Low-severity Vim-semantics deviations

**Category:** low wrong logic · **Area:** `vith/commands/commands.py`, `vith/editor.py`, `vith/editor_buffer.py` · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** fixed

## Findings

| # | Location | Deviation | Evidence / notes |
| :-- | :-- | :-- | :-- |
| 1 | `vith/editor.py:501-508` (`use_colorscheme`) | Unknown colorschemes are silently ignored; Vim reports `E185: Cannot find color scheme`. `:colo typo` looks successful and leaves the old style. | The `ClassNotFound` is caught and discarded; `:colorscheme` and the preview both use this method. |
| 2 | `vith/commands/commands.py:678-697` (`file_info`) | `:f {name}` assigns the raw string to `eb.location` without `expanduser`/`abspath` and without updating `is_new`. `:f ~/x` then `:w` writes the expanded path but the buffer/title keep `~/x`; `[New file]` stays stale. | `EditorBuffer.write` already normalizes for I/O; the metadata does not. |
| 3 | `vith/commands/commands.py:839-853` (`_write_append_file`) | `:[range]w >> {file}` bypasses `editor.io_backends` and uses the builtin `open`. Appending to `archive.gz` writes plain text into the gzip stream; an `http://` target becomes a local filename. | Vim uses the buffer's file I/O path; the other write helpers use `_write_payload_to_location`. |
| 4 | `vith/commands/commands.py:2309-2321, 2367-2397, 2400-2462` | `:d [N]`, `:y [N]`, and `:pu N` interpret the numeric argument as a count/error, while Vim treats `[x]` as a register name (`:d 3` deletes the current line into register 3; `:pu 3` pastes register 3). | Named/numbered registers are not implemented at all; the grammar advertises a count (`:[range]d [count]` in help). Either implement registers or reject the numeric form with a clear message. |
| 5 | `vith/commands/commands.py:1516-1564, 770-790` | `:setlocal` only applies local scope to `tabstop`/`shiftwidth`; booleans, `scrolloff`, `colorcolumn`, `filetype`, and `readonly` mutate global/editor or buffer state without a local/global distinction. | `is_local` is threaded only into `_set_int_option`; the other branches ignore it. |
| 6 | `vith/editor.py:488-499` (`should_ignore_case`) | Smartcase scans every character with `isupper()`, including regex escapes/classes. A pattern containing `\S` or `\W` is treated as containing an uppercase literal and disables `ignorecase`. | Vim's smartcase only considers literal uppercase characters; escaped class names should not count. |

## Fix direction

1. `use_colorscheme`: return success/failure and show `E185` (or a vith message) on `ClassNotFound`; keep preview silent.
2. `:file`: normalize through `expanduser`/`abspath`, recompute `is_new`/isdir, and refresh title/reporter consistently.
3. `:w >>`: route through `_write_payload_to_location` (or a backend append API) so gzip/HTTP/encodings behave like `:w`; reject unsupported backends.
4. Registers: implement at least numbered/lettered register storage or treat numeric arguments as invalid and remove the count claim from help.
5. `:setlocal`: either implement per-option local/global semantics or document the limitation and make `:setlocal` reject non-scoped options.
6. Smartcase: strip escaped sequences and bracket classes before checking uppercase, reusing `_strip_regex_literals` from the substitute guard.
