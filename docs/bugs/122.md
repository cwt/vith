# `*` search does not enter search history

**Category:** search · **Area:** key bindings / search state · **Found at:** upstream triage 2026-11-09 (`prompt-toolkit/pyvim#89`) · **Fix status:** fixed

## Summary

`*` jumps to the next match but `/<Up>` shows no recalled pattern, and a bare `:s` cannot reuse the `*` pattern.

## Evidence

* The only writer of `search_state.text` is `substitute()` in `vith/commands/commands.py:664-778`[^src-cmd] (`:778`); no `*`/`#` handler sets it.
* `vith/key_bindings.py:146-398`[^src-kb] has no `*`/`#` override to push the word into `editor.search_buffer` history (`FileHistory` in `vith/editor.py:159-165`[^src-ed]).

## Impact

* Breaks the Vim loop `*` → `/<Up>` → `:s//replacement/g`; users must retype the pattern.

## Fix

* `vith/key_bindings.py` adds `*` / `#` overrides (`_record_word_search`) matching the `prompt_toolkit` movement (word under cursor, forward/backward `apply_search`) and additionally appending to `search_buffer` history, so `/<Up>` recalls it and bare `:s` reuses `search_state.text`. Empty word is a no-op; history write failures degrade silently.
* Regression tests in `tests/test_key_bindings_fixes.py`: forward jump + history, backward jump + direction, blank no-op.
