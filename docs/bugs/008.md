# `tools/bench_plans.py` validates its own duplicated copies rather than the shipped modules

**Category:** verification integrity + duplication · **Area:** `tools/bench_plans.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Summary

The benchmark/verification script that backs both plans re-implements the
shipped code instead of importing it (four parallel copies), and the copies
have already drifted from `vith.thai`/`vith.lexer`. The docs cite this
script as the verifier, so the numbers/tables only ever validate the copy.

## Evidence

Four duplicated blocks in [`tools/bench_plans.py`](../../tools/bench_plans.py):

| Copy | Bench block | Shipped counterpart | Drift found |
| :--- | :--- | :--- | :--- |
| Thai predicates & cell scanners | `39-190` | [`vith/thai.py:77-248`](../../vith/thai.py) | bench `is_combining_char` (`65-71`) does `ord(ch)` directly — raises on `""` and handles multi-char input by type error; shipped version uses `ch[0]` with a guard (``125-137``). `next_cell_offset` `count ≤ 0` → bench returns `n` (`106-107`), shipped returns `n if col >= n else max(0, col)` (`202-203`); `prev_cell_offset` `count ≤ 0` → bench `0` (`121-122`), shipped `min(col, len(line))` (`223`). |
| Streaming lexer | `_PublicStreamingDocumentLexer`, `205-316` | [`vith/lexer.py:37-159`](../../vith/lexer.py) | bench `_ensure_lexer` (`226-228`) re-scans the Pygments registry on cache **misses**; shipped caches misses (`lexer.py:58-61`). |
| Lazy styles dict | `_LazyStylesDict`, `319-347` | [`vith/style.py:17-44`](../../vith/style.py) | loader-injected variant vs self-contained one — equivalent but another copy. |
| Words completer | `_SingletonCachedWordsCompleter`, `350-390` | [`vith/completion.py:14-71`](../../vith/completion.py) | near-identical duplicate. |

* The **speed plan half** already imports the real modules
  ([`tools/bench_plans.py:456-464`](../../tools/bench_plans.py)); only the Thai half
  doesn't.
* [`thai_support_plan.md §1.2/§3.4`](../thai_support_plan.md) states "All
  cell starts … are verified by `tools/bench_plans.py`" — that statement is
  only true of the copies, not of `vith.thai`. The unit tests do cover the
  shipped code (correctly), so this is a docs/tooling fidelity issue.

## Impact

Verification integrity: future drift between bench copies and shipped code
would silently keep the bench green while the shipped behaviour differs;
duplicate logic triples maintenance effort.

## Fix direction

Import `vith.thai`, `vith.lexer`, `vith.style` and `vith.completion` in
the bench exactly like the speed half does; delete the four local copies.
