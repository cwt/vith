# VS16 `_copy_body` re-patch warning and missing rollback registration

**Category:** Thai / `prompt_toolkit` patches · **Area:** `vith/thai/patches.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** open

## Summary

`Editor.__init__()` invokes `install_prompt_toolkit_thai_patches()` on every instantiation:[^src-install]

1. **Idempotency marker masked by outer wrapper:** On the first call, `_install_copy_body_vs16_merge_fix()` replaces `Window._copy_body` with `patched` (`patched._vith_vs16_merge_patched = True`), and `_install_window_copy_body_patch(applied)` immediately wraps `Window._copy_body` in `_patched_copy_body` (`_vith_thai_patched = True`, **without** `_vith_vs16_merge_patched`).[^src-vs16] On every subsequent `Editor()` creation, `_install_copy_body_vs16_merge_fix()` sees `getattr(Window._copy_body, "_vith_vs16_merge_patched", False) == False`, calls `inspect.getsource(_patched_copy_body)` from disk, fails to locate `old_snip`, and logs `WARNING: VS16 merge fix: target snippet not found; skipping.`.
2. **Rollback gap:** Neither `_install_copy_body_vs16_merge_fix()` nor `_install_get_cwidth_patch()` records its mutations in `applied`, so if `_thai_install_selftest()` (called afterwards at line 1493) raises, the `except` rollback block leaves `Window._copy_body` and `get_cwidth` mutated.[^src-cwidth][^src-install]

## Evidence

Instantiating a second `Editor` with a handler attached to `logging.getLogger("vith.thai.patches")`:

* Emits `['VS16 merge fix: target snippet not found; skipping.']` on every `Editor()` after the first.

## Fix Direction

1. Check `getattr(orig, "_vith_vs16_merge_patched", False) or getattr(orig, "_vith_thai_patched", False)` (or walk `_vith_original`) in `_install_copy_body_vs16_merge_fix`, and add an idempotency guard on `_install_get_cwidth_patch` (`_ptk_utils.get_cwidth is _vith_get_cwidth`).
2. Pass `applied` into `_install_copy_body_vs16_merge_fix(applied)` and `_install_get_cwidth_patch(applied)` so any failure before `install_prompt_toolkit_thai_patches()` returns rolls back cleanly.
3. Add a regression test calling `install_prompt_toolkit_thai_patches()` twice and asserting zero warnings are logged.
