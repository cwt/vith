# Counted Insert state leak and slice corruption

**Category:** key bindings / insert mode · **Area:** `vith/key_bindings.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** fixed (hg rev 460)

## Summary

Counted `i` and `a` (`{N}i`, `{N}a`) record `(buff.cursor_position, count)` on `buff._vith_insert_repeat`, and only the `<Esc>` handler (`_leave_insert_with_repeat`) reads and clears that attribute.[^src-repeat] Two distinct failure modes corrupt buffer text:

1. **Stale `_vith_insert_repeat` across non-`<Esc>` exits:** If the user leaves Insert mode without triggering the `in_insert_mode` `<Esc>` binding (for example pressing `<F1>` to open `[Help]`, clicking another split, or resetting mode), `_vith_insert_repeat` stays attached to `buff`. Subsequent Insert entries via `o`, `O`, `A`, `I`, or `s` do not overwrite `_vith_insert_repeat`.[^src-open] When the user eventually presses `<Esc>` further down the file, `buff.text[old_start : buff.cursor_position]` slices every intervening line and inserts `count - 1` copies.
2. **Invalidated `start` offset on `<Backspace>` / cursor motion:** `_leave_insert_with_repeat` slices `buff.text[start : buff.cursor_position]` assuming `start` remained stationary and the cursor only advanced forward. Pressing `<Backspace>` or `<Left>` past `start` shifts earlier offsets or places `cursor_position <= start`, producing truncated or empty replays.

## Evidence

Live `KeyProcessor` probes against shipped `Editor` + `create_key_bindings`:

| Scenario | Initial text (`@cursor`) | Key sequence | Expected | Actual |
| :--- | :--- | :--- | :--- | :--- |
| `<F1>` mid-counted-insert | `"line1\nline2"` (`@0`) | `3iX<F1>` | `_vith_insert_repeat` cleared or isolated | `_vith_insert_repeat == (0, 3)` remains armed on source buffer |
| Stale replay on later `o...<Esc>` | `"first\nsecond\nthird"` (`@0`) | `3iX` → non-`<Esc>` exit → `jjoY<Esc>` | Only `"Y"` inserted on new line | Multi-line prefix from offset `0` duplicated `count - 1` times |
| `<Backspace>` past `start` | `"abcdef"` (`@3`) | `3i<BS><BS>Z<Esc>` | `"aZZZdef"` (or replay of typed insert) | `'aZdef'` (`buff.text[3:2] == ''`) |

## Fix Direction

1. Clear `buff._vith_insert_repeat = None` on all Insert-mode entry bindings (`o`, `O`, `s`, etc.) and whenever `vi_state.input_mode` transitions out of `InputMode.INSERT` (or on `<F1>` / focus loss / `c-c`).
2. Record the actual inserted keystrokes (or track prefix/suffix lengths around the insertion point) rather than slicing raw `buff.text[start : buff.cursor_position]` when edits cross `start`.
3. Add regression tests for `3iX<F1>` followed by `oY<Esc>` and for counted insert with `<Backspace>` before `start`.
