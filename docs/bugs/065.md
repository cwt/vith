# Legacy `DocumentLexer` fallback rebuilds the lexer every frame

**Category:** unoptimized fallback · **Area:** `vith/lexer.py` (`DocumentLexer.lex_document`) · **Found at:** deep review, hg rev 87de3a3 (2026-11-08) · **Re-validated:** 2026-11-08 at hg rev 251 (tip; code identical to the audit revision)

## Summary

`pyproject.toml` permits `prompt_toolkit>=3.0.0,<3.1.0`, and `_STREAMING_AVAILABLE` ([`vith/lexer.py:8-15`](../../vith/lexer.py)) falls back to a legacy branch when its probe import fails. That branch ([`vith/lexer.py:110-114`](../../vith/lexer.py)[^src-lexer]) constructs a fresh `PygmentsLexer.from_filename(location, sync_from_start=False)` on **every** `lex_document` call — i.e., every frame — paying a Pygments registry scan plus a fresh `RegexSync` per keystroke: the exact cost [030](030.md) eliminated for the directory lexer. The streaming branch caches both hits and misses (`_ensure_lexer`, `:75-98`) and degrades to `SimpleLexer` (`:116-120`); the fallback does neither.

## Validation corrections (2026-11-08)

Two of the originally filed claims did not survive the machine re-check, and this finding is demoted from medium to **low**:

1. **`ClassNotFound` leak — refuted.** Prompt_toolkit's own `PygmentsLexer.from_filename` wraps `get_lexer_for_filename` in `try/except ClassNotFound → SimpleLexer` (verified in the installed 3.0.53, `lexers/pygments.py:201-216`, *and* in the 3.0.0 sources): unknown extensions degrade to `SimpleLexer`; nothing escapes to the renderer.
2. **Version-gate premise — doubtful.** `_STREAMING_AVAILABLE` is import-based (`RegexSync` + `pygments_token_to_classname`), and both names already exist in ptk 3.0.0, so the fallback branch is likely dead across the whole pinned range; only hypothetical in-range builds without them would ever take it.

What survives is the per-frame rebuild *if* the branch is ever taken — a defense-in-depth/cost cleanup rather than a live defect.

## Evidence

* [`vith/lexer.py:110-114`](../../vith/lexer.py)[^src-lexer]:
  ```python
  if not _STREAMING_AVAILABLE:
      return PygmentsLexer.from_filename(location, sync_from_start=False).lex_document(document)
  ```
* [`vith/lexer.py:75-98`](../../vith/lexer.py) — `_ensure_lexer` caches hit *and* miss; `:116-120` degrades to `SimpleLexer`.
* [`pyproject.toml:21`](../../pyproject.toml) — `prompt_toolkit>=3.0.0,<3.1.0`.

## Impact

* ~0.6 ms registry scan per frame (the [030](030.md) precedent figure) for all normal files **on the fallback path** — which the supported range probably never takes.
* No crash risk in the pinned range (see validation corrections).

## Fix direction

Unify both branches through `_ensure_lexer` + the cache (or cache the directory-lexer style, `_get_directory_lexer`); keep a `try/except ClassNotFound → SimpleLexer` only as belt-and-braces (harmless).
