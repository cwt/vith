# `TextObject.operator_range` patch escapes the install rollback

**Category:** wrong logic / partial patching · **Area:** `vith/thai.py` (`install_prompt_toolkit_thai_patches`) · **Found at:** deep review, hg rev 87de3a3 (2026-11-08)

## Summary

The installer’s `except` rollback iterates `applied` (Document + KeyProcessor triples). The `TextObject.operator_range` wrapper installed inside the same `try` is never appended to `applied`. A failure after that point (for example the self-test at the end of the `try`) restores `Document` yet leaves `TextObject.operator_range` patched — a half-patched state the graceful-fallback contract explicitly forbids.

`Window._copy_body` and `_output_screen_diff` are installed *after* the `try` (lines 1455-1456), so they are outside rollback entirely (today they fail soft with `warn + return False`, but the asymmetry is load-bearing if they ever raise).

## Evidence

* [`vith/thai.py:1358-1457`](../../vith/thai.py)[^src-thai]:
  * `applied.append((Document, method_name, current))` for Document patches.
  * `applied.append((KeyProcessor, ...))` for KeyProcessor patches.
  * No `applied.append` for `_PtkTextObject.operator_range` (lines 1405-1440).
  * `except` (lines 1449-1453) only loops `applied`.
* [`vith/thai.py:1412-1414`](../../vith/thai.py) — `_thai_operator_range` also captures `_orig_operator_range` by reference (late binding); double-install would observe the new original. Bind it as a default arg.

## Impact

On an incompatible prompt_toolkit build the fallback advertises “unpatched Document” while `TextObject` still applies Thai inclusivity/snapping — the exact hybrid [005](005.md) was filed to prevent, now one patch-site over.

## Fix direction

Append `(_PtkTextObject, "operator_range", _orig_operator_range)` to `applied` before assignment, move window/renderer installs inside the `try` (or wrap them with their own install/rollback pair), and bind the closure original via a default argument.
