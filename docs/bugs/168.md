# `*` / `#` crash in Normal mode

**Category:** key bindings / search · **Area:** `vith/key_bindings.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`_record_word_search()` sets up the search state and calls
`buff.apply_search(search_state, include_current_position=False, count=event.arg)`.[^src-kb]
`KeyPressEvent.arg` in prompt_toolkit is `str | None`; `Buffer._search()`
asserts `count > 0` and then iterates `range(count)`, so both the no-count and
count-prefix cases raise `TypeError`. Every other binding in this module
normalizes the argument via `_positive_count(event.arg)`.[^src-kb]

## Evidence

Direct invocation of the `*` binding handler with `event.arg` set to the values
the real key processor supplies:

| `event.arg` | Expected | Actual |
| :--- | :--- | :--- |
| `None` (plain `*`) | cursor moves to next occurrence of word under cursor | `TypeError: '>' not supported between instances of 'NoneType' and 'int'` |
| `'2'` (`2*`) | two occurrences forward | `TypeError: '>' not supported between instances of 'str' and 'int'` |

The existing tests set `event.arg = 1` manually via `MagicMock`,[^src-tests] so
they pass while exercising a value the production key processor never supplies.

## Fix Direction

1. Normalize with the module's existing helper:
   `count=_positive_count(event.arg)` at `vith/key_bindings.py:219`.
2. Change the `*` / `#` regression tests to use `event.arg = None` and
   `event.arg = '2'` (the real `KeyPressEvent` contract) instead of the
   synthetic integer `1`, and assert the cursor/search-state outcome.
