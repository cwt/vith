# Visual-block highlight disagrees with yank/delete on short rows

**Category:** Thai / visual block · **Area:** `vith/thai/patches.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** fixed
> **Resolution note (2026-11-23):** `selection_range_at_line()` now uses the same visual-column EOL rule as `selection_ranges()`.


## Summary

The two public selection APIs use different rules for rows whose display width
is shorter than the block's visual columns:

* `_thai_selection_ranges()` skips a row when `v_low > total_width`, matching
  Vim (the block is past that line's EOL).[^src-patches]
* `_thai_selection_range_at_line()` instead decides virtual space from the
  **codepoint** interval `col1 <= line_len <= col2`, then returns
  `(line_len, line_len + 1)` whenever `v_low >= total_width`.[^src-patches]

With tab-expanded columns, the codepoint endpoints can bracket a short row's
length even though the visual block begins well past its EOL, so the screen
highlights an EOL cell that `y`/`d` (which consume `selection_ranges()`) will
never act on.

## Evidence

Verified probe with `tabstop`-expanded columns:

```
row 0: "\tABCDEFGHIJ"   anchor at codepoint 5  -> visual col 12
row 1: "abcdef"         short intermediate row, visual width 6
row 2: "\tABCDEFGHIJ"   cursor  at codepoint 10 -> visual col 17
v_low=12, v_high=17, col1=5, col2=10
```

| API | Result for row 1 |
| :--- | :--- |
| `doc.selection_ranges()` | row skipped — no range (correct) |
| `doc.selection_range_at_line(1)` | **`(6, 7)`** — spurious EOL virtual-space selection |

The same mismatch occurs at `v_low == total_width`.

## Fix Direction

1. Make `_thai_selection_range_at_line()` apply the same visual rule as
   `_thai_selection_ranges()`: skip when `v_low > total_width`; produce virtual
   space only when `v_low == total_width` and the block genuinely reaches EOL
   in visual columns, never because codepoint endpoints happen to bracket the
   line length.
2. Add a cross-check regression test that, for a set of tabbed/short-row
   blocks, asserts `selection_range_at_line(i)` is consistent with the ranges
   returned by `selection_ranges()` for every row.
