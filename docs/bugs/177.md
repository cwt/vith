# `:e` reload leaves stale undo/redo history

**Category:** editor buffer / undo · **Area:** `vith/editor_buffer.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** fixed
> **Resolution note (2026-11-23):** `reload()` now calls `ColdTextBuffer.reset()`, clearing undo/redo stacks and version counters with the old document.


## Summary

`EditorBuffer.reload()` assigns a fresh `Document` and resets diagnostics,
filetype, and length caches,[^src-eb] but never clears the underlying
`ColdTextBuffer` undo/redo stacks or resets `_text_version` /
`_non_cursor_version`. `Buffer.set_document()` in prompt_toolkit does not clear
undo state, so snapshots taken before the reload remain live. Vim clears undo
history on reload; `ColdTextBuffer.reset()` already implements the correct
clearing behavior for new buffers.[^src-cold]

## Evidence

Probe: load a file with `old text`, edit to `new text`, call
`save_to_undo_stack()`, overwrite the file on disk with `disk text`, then
`reload()` and `undo()`.

| Stage | Undo stack length | Buffer text |
| :--- | ---: | :--- |
| after edit + snapshot | 1 | `new text` |
| after disk change + `reload()` | **1** (should be 0) | `disk text` |
| after `undo()` | — | **`new text`** (stale content resurrected; buffer becomes dirty) |

## Fix Direction

1. In `EditorBuffer.reload()`, after the document assignment, clear
   `self.buffer._undo_stack` / `_redo_stack` (or call a dedicated
   `ColdTextBuffer.reset_for_reload()` helper) and reset version counters so
   pre-reload snapshots cannot be applied.
2. Add a regression test covering edit → reload → `u` (and `Ctrl-R`) asserting
   the reloaded text is stable and the buffer stays clean.
