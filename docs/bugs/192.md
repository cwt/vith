# Tab cannot be pressed while editing text

**Category:** key bindings / Insert mode · **Area:** `vith/key_bindings.py` · **Found at:** user field report (2026-11-23, `v0.16.0` / rev 431) · **Fix status:** fixed

> **Resolution note (2026-11-23):** Removed the `whitespace_before_cursor_on_line` filter (and the now-unused `Condition`) from the Insert-mode `tab` binding, so Tab inserts an indentation step anywhere in the document buffer. The command/search buffer exclusions from [136](136.md) remain. Also corrected the editor's default `expand_tab` from `True` to `False` (Vim's `noexpandtab`), so an unconfigured Tab now inserts a **literal tab character** rather than `tabstop` spaces; `:set expandtab` still switches to spaces.

## Summary

`create_key_bindings()` registered the Insert-mode `tab` handler with four
filters: `vi_insert_mode`, not the command buffer, not the search buffer, and
`whitespace_before_cursor_on_line`.[^src-kb] The last filter was true only at
the start of a line or immediately after whitespace, so when a user pressed Tab
while typing in the middle of a line, the binding did not match and
prompt_toolkit's default `menu_complete` binding ran instead — invoking
completion rather than inserting a tab. In Vim, Tab always inserts an
indentation step (honoring `expandtab`/`tabstop`) in Insert mode; completion is
a separate mapping (Ctrl-N/Ctrl-P here).

The filter originated with the completion-vs-indentation work in
[071](071.md) and the search-toolbar guard in [136](136.md); the latter is
still needed and was preserved.

## Evidence

Key-processor probe in Insert mode on `hello world`, `expand_tab=False`:

| Cursor | Before fix | After fix |
| :--- | :--- | :--- |
| `0` (line start) | `\thello world` | `\thello world` |
| `5` (mid-line) | falls through to `menu_complete` → `RuntimeError: no running event loop` headless / completion in the running app | `hello\t world` |
| `6` (after space) | same fall-through | `hello \tworld` |

With the corrected Vim-compatible default (`expand_tab=False`) a mid-line Tab
inserts a literal `\t`; `:set expandtab` makes it insert `tabstop` spaces.

## Fix Direction

1. Drop `whitespace_before_cursor_on_line` from the Tab binding and delete the
   unused `@Condition` definition.
2. Keep the explicit `~has_focus(command_buffer)` and
   `~has_focus(search_buffer)` filters, and add regression tests covering
   mid-line insertion (both `expandtab` settings) plus the two prompt exclusions.
