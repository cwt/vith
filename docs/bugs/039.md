# `indent_line` (`<C-t>` in Insert mode) raises `AttributeError` on `event.application`

**Category:** crash · **Area:** `vith/key_bindings.py` (`indent_line`) · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

The `<C-t>` Insert-mode handler `indent_line` accesses `event.application.current_buffer`[^src-kb]. In `prompt_toolkit 3.x`, `KeyPressEvent` exposes `.app` and `.current_buffer` (not `.application`), so pressing `Ctrl-T` in Insert mode raises an uncaught `AttributeError`.

## Evidence

* [`vith/key_bindings.py:70-89`](../../vith/key_bindings.py)[^src-kb]:
  ```python
  @kb.add('c-t', filter=in_insert_mode)
  def indent_line(event):
      """
      Indent current line.
      """
      b = event.application.current_buffer
  ```
* Live verification against `prompt_toolkit 3.0.53`:
  `hasattr(KeyPressEvent, 'application')` is `False`; `hasattr(KeyPressEvent, 'app')` and `hasattr(KeyPressEvent, 'current_buffer')` are `True`.
* All other handlers in `vith/key_bindings.py` (lines 95, 115, 182, 207) use `event.app.current_buffer` or `event.current_buffer`.

## Impact

Pressing `Ctrl-T` to indent a line in Insert mode crashes the editor with `AttributeError: 'KeyPressEvent' object has no attribute 'application'`.

## Fix direction

Replace `b = event.application.current_buffer` with `b = event.current_buffer` (or `event.app.current_buffer`), and use `' ' * editor.tabstop` instead of hardcoded `'    '` (see [054](054.md)).
