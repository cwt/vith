# Quadratic $O(R \cdot N)$ `:norm` line replay and uncached `KeyProcessor` rebuild

**Category:** performance / algorithms · **Area:** `vith/commands/normal.py`, `vith/editor_buffer.py` · **Found at:** Round 10 deep performance audit (2026-11-22, `v0.15.1` / rev 392) · **Fix status:** open

## Summary

`execute_normal_on_rows` (`vith/commands/normal.py:70-163`) exhibits superlinear / $O(R \cdot N)$ scaling across `R` addressed rows in an `N`-line buffer:[^src-normal]

1. `_build_normal_key_processor` (`vith/commands/normal.py:40-59`) calls `load_key_bindings()` from scratch on every `:norm` invocation (**1.62 ms/call**), constructing ~300 default Emacs/Vi/mouse/CPR bindings.
2. Inside `for raw_row in rows:`, every keystroke mutates the full buffer `buff` while `EditorBuffer._on_text_changed` remains active — repeatedly splitting `document.lines`, checking `has_unsaved_changes`, latching the Thai gate, and firing `run_reporter()` on intermediate rows (spawning background pyflakes tasks on `.py` files!).[^src-eb]
3. Each row calls `doc.translate_row_col_to_index(target_row, 0)` and `_leave_insert_with_repeat` → `_doc_get_cursor_left_position`, rebuilding `Document._line_start_indexes` across all $N$ lines on every single iteration.

## Evidence

Measured on `Python 3.15.2` running `:%norm A;`:

| Lines (`N`) | Total time | Per-line cost |
| ---: | ---: | ---: |
| 200 | 26.40 ms | 0.132 ms/line |
| 500 | 63.36 ms | 0.127 ms/line |
| 1,000 | 170.77 ms | 0.171 ms/line |
| 2,000 | **478.15 ms** | **0.239 ms/line** (scales with $N$) |

`cProfile` on 1,000 lines shows ~38% in `KeyProcessor._get_matches` filter evaluation across all merged bindings and ~21% in `_doc_get_cursor_left_position` → `_find_line_start_index`.

## Fix Direction

1. Cache the `load_key_bindings()` default bindings and merged `KeyProcessor` (keyed by `(ignore_user_mappings, len(editor.key_bindings.bindings))`) so `:norm` does not rebuild ~300 bindings on every call.[^src-normal]
2. Add a batch-suppression guard (`_suppress_text_changed`) on `EditorBuffer` analogous to `_suppress_undo_saves` on `ColdTextBuffer`, suppressing per-keystroke `_on_text_changed` / `run_reporter()` during `execute_normal_on_rows` and running a single synchronization in `finally`.[^src-eb]
3. Pair with [157](157.md) (eliminating `doc.current_line` / `_line_start_indexes` inside `_doc_get_cursor_left_position` and `_kp_fix_vi_cursor_position`) and track a running character offset when walking sequential rows instead of rebuilding `_line_start_indexes` on every row.
