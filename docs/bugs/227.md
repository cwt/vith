# Unoptimized algorithms & hot-path bottlenecks (Round 18)

**Category:** performance / latency · **Area:** `vith/lexer.py`, `vith/editor.py`, `vith/render.py`, `vith/commands/ranges.py`, `vith/thai/patches.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Priority:** high (item 1 adds $O(N)$ per-keystroke latency on multi-MB extensionless files) · **Fix status:** fixed (hg rev 483)

## Findings

| :--- | :--- | :--- | :--- |
| 1 | `vith/lexer.py:98,188-200,296-306` (`_filetype_from_modeline`, `DocumentLexer._ensure_lexer`) | Rev `457` added `_filetype_from_modeline(text)` inside `sniff_filetype_from_text(text)`, calling `lines = text.splitlines()` on the **entire** buffer to inspect `lines[:5]` and `lines[-5:]`.[^src-lex] For any named extensionless plain-text file (`CHANGELOG`, `LICENSE`, `syslog`), `_pygments_lexer` stays `None` and `_text_version` increments on every edit, so `_ensure_lexer` runs `text.splitlines()` across the entire file on **every keystroke**. | **5.38 ms / keystroke** on a 4.1 MB (100k-line) extensionless log file on Python 3.15.2 (~54 ms/keystroke at 40 MB). |
| 2 | `vith/editor.py:334,596-608` (`Editor.use_colorscheme`) | `Editor` instantiates `self.styles = generate_built_in_styles()` (`_LazyStylesDict`, which caches compiled `Style` objects in `_loaded`), yet `use_colorscheme(name)` calls `get_editor_style_by_name(name)` directly, recompiling and merging Pygments styles on every `:colorscheme` live-preview keystroke.[^src-ed] | `use_colorscheme("monokai")`: **0.168 ms** vs `editor.styles["monokai"]`: **0.00009 ms** (~**1,780×** slower). |
| 3 | `vith/render.py:199-215,698-719` (`detect_render_format`, `render_document`) | (a) For `fmt == 'json'`, `render_document` runs `json.loads(text)`, discards the parsed object, and passes raw `text` to `rich.json.JSON(text)` (which calls `json.loads(text)` a second time instead of `JSON.from_data(parsed)`). (b) For code buffers without `:set ft`, `detect_render_format` calls `sniff_filetype_from_text(sample)` (`sample = text[:4096]`, which also truncates bottom-of-file modelines on files > 4 KB) and `render_document` calls `sniff_filetype_from_text(text)` a second time.[^src-ren] | 2× full JSON parse per debounced `:render` refresh; 2× content sniff + dropped tail modelines > 4 KB in `detect_render_format`. |
| 4 | `vith/commands/ranges.py:246-257` (`_commit_buffer_text`) | Constructs `Document(new_text)` at `cursor_position=0` (firing `_on_text_changed` with cursor at `0`), materializes `doc.lines` over the entire buffer to locate `target_row`, and assigns `eb.buffer.cursor_position = ...` (constructing a second `Document` and firing `on_cursor_position_changed`).[^src-rng] | 2 `Document` constructions + 1 full-buffer `splitlines()` even when `splice_buffer_lines` avoided splitting untouched rows. |
| 5 | `vith/thai/patches.py:579-598`; `vith/entry_points/run_vith.py:26` + `vith/editor.py:263` | `_install_get_cwidth_patch()` has no idempotency check and iterates all `sys.modules.values()` on every `Editor()` creation; `set_process_name('vith')` runs in `run_vith.run()` and immediately again in `Editor.__init__()`.[^src-pat][^src-run] | Redundant `sys.modules` scan + duplicate `ctypes` `CDLL`/syscall at CLI startup and in test suites. |

## Fix Direction

1. **Bounded $O(1)$ modeline extraction:** Replace `text.splitlines()` in `_filetype_from_modeline(text)` with bounded `str.find('\n')` (first 5 lines) and `str.rfind('\n')` (last 5 lines) scans, never allocating more than 10 line slices regardless of file size.
2. **Cache styles through `self.styles`:** Look up `self.styles[name]` inside `Editor.use_colorscheme` (converting `KeyError` to the existing `E185` error path).
3. **Single-pass JSON & sniff in `:render`:** Pass `parsed = json.loads(text)` to `JSON.from_data(parsed)`, pass full `text` (once) to `sniff_filetype_from_text(text)` once bounded modeline scanning is in place, and thread any resolved lexer name into `render_document` instead of re-sniffing.
4. **Single `Document` in `_commit_buffer_text`:** Compute the byte/char offset of `target_row` and `target_col` on `new_text` before assigning `eb.buffer.document = Document(new_text, cursor_position=pos)` once.
5. **Guard `_install_get_cwidth_patch` & deduplicate `set_process_name`:** Short-circuit `_install_get_cwidth_patch` when already installed, and remove the duplicate `set_process_name('vith')` call in `run_vith.py` (or guard `set_process_name` to no-op when already set to the same name).
