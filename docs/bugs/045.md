# `report_pyflakes` treats `pyflakes` UTF-8 byte `col_offset` as codepoint index and restricts identifiers to ASCII

**Category:** wrong logic · **Area:** `vith/reporting.py` (`report_pyflakes`) · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

In Python 3.8+, `ast.AST.col_offset` (exposed as `message.col` by `pyflakes`) is a **UTF-8 byte offset** from the start of the line, not a Unicode codepoint index. `report_pyflakes` (`vith/reporting.py:79-88`)[^src-rep] passes `message.col` directly to `document.translate_row_col_to_index(message.lineno - 1, message.col)` and stores `start_column=message.col`.

Whenever a Python source line contains multi-byte UTF-8 characters (such as Thai/Lao strings or comments) before a reported symbol, `message.col` exceeds the character column by `len(prefix.encode('utf-8')) - len(prefix)`, shifting or truncating the `pyflakes` error highlight in `HighlightPyflakesErrorsProcessor` (`vith/layout.py:130-156`)[^src-layout].

Additionally, `WORD_CHARACTERS` (`vith/reporting.py:59`)[^src-rep] is hardcoded to `string.ascii_letters + '0123456789_'`, so PEP 3131 non-ASCII Python identifiers (e.g. `ตัวแปร = 1`) stop the `end_index` scan immediately (`end_column == start_column`, highlighting 0 characters).

## Evidence

* [`vith/reporting.py:59, 77-88`](../../vith/reporting.py)[^src-rep]:
  ```python
  WORD_CHARACTERS = string.ascii_letters + '0123456789_'
  ...
  for message in reporter.messages:
      start_index = document.translate_row_col_to_index(
          message.lineno - 1, message.col
      )
      end_index = start_index
      while (
          end_index < len(document.text)
          and document.text[end_index] in WORD_CHARACTERS
      ):
          end_index += 1

      errors.append(
          ReporterError(
              lineno=message.lineno - 1,
              start_column=message.col,
              end_column=message.col + end_index - start_index,
              formatted_text=message.message % message.message_args,
          )
      )
  ```
* **Live probe**:
  ```python
  >>> from prompt_toolkit.document import Document
  >>> from vith.reporting import report_pyflakes
  >>> doc = Document('x = "ที่ดิน" + undefined_var\n')
  >>> err = report_pyflakes(doc)[0]
  >>> (err.start_column, err.end_column, doc.lines[0][err.start_column:err.end_column])
  (27, 28, 'r')
  ```
  `"ที่ดิน"` is 6 codepoints but 18 UTF-8 bytes (`+12` byte offset), so `message.col` is `27` instead of character column `15`. At character index `27`, only the final `'r'` of `undefined_var` remains on the line (`doc.lines[0][27:28] == 'r'`). If the Thai literal is longer, `message.col` overshoots `len(line)` completely and highlights nothing.

## Impact

Pyflakes error highlighting in `.py` buffers highlights the wrong characters (or nothing at all) on any line containing non-ASCII text before the error or non-ASCII variable names.

## Fix direction

1. Convert the UTF-8 byte offset `message.col` on `line = document.lines[row]` to a character column via:
   ```python
   char_col = len(line.encode('utf-8')[: message.col].decode('utf-8', errors='replace'))
   ```
2. Replace `document.text[end_index] in WORD_CHARACTERS` with `(ch == '_' or ch.isalnum())` (or `ch.isidentifier()`) bounded to `line`.
