# Plan and benchmark drift (round 2: corrupted code fence in `thai_support_plan.md`, P2 `bench_plans.py` calculation, stale metadata)

**Category:** documentation / benchmark drift · **Area:** `docs/thai_support_plan.md`, `docs/speed_latency_plan.md`, `tools/bench_plans.py` · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

Four documentation and benchmark drift items remain across `docs/thai_support_plan.md`, `docs/speed_latency_plan.md`, and `tools/bench_plans.py`:

1. **Unclosed code fence / embedded Markdown blockquote in `docs/thai_support_plan.md:466-549`**[^src-thai-plan]:
   In §4.3 (`vith/thai.py` Phase 4 renderer snippet), a ` ```python ` fence opens at line 466 and does not close until line 549, but lines 522–528 insert a prose blockquote directly inside the Python code block:
   ```markdown
   > **Implementation update (hg rev 170, 174)**:
   > * `_sanitize_and_invalidate_sara_am` returns early in $O(1)$ (`if not _THAI_GATE.value: return`) ...
   ```
   followed by `def install_prompt_toolkit_thai_patches() -> bool:` at line 530. This breaks both Markdown rendering and Python syntax highlighting for lines 522–549.
2. **Inaccurate `p2_eager_ms` benchmark in `tools/bench_plans.py:124-131`**[^src-bench]:
   ```python
   t0 = time.perf_counter()
   style_names = list(get_all_styles())
   p2_get_all_ms = (time.perf_counter() - t0) * 1000

   t0 = time.perf_counter()
   styles = generate_built_in_styles()
   p2_eager_ms = p2_get_all_ms + (time.perf_counter() - t0) * 1000
   ```
   Because `generate_built_in_styles()` now returns a lazy `_LazyStylesDict` without compiling any styles, `styles = generate_built_in_styles(); _ = list(get_all_styles())` does **not** compile all 50 Pygments colorschemes (`len(styles._cache) == 0`). Consequently, `cold_eager=0.44 ms` reported by `tools/bench_plans.py` (and cited in `docs/speed_latency_plan.md:80`[^src-speed-plan]) only times `list(get_all_styles())` + dict allocation rather than eager `get_style_by_name` + `Style.from_dict` across all styles (~8.5 ms). To measure true eager style generation, the benchmark must materialize `[styles[name] for name in get_all_styles()]`.
3. **Stale references in `docs/speed_latency_plan.md`**[^src-speed-plan]:
   * Lines 96 and 377 still state `python_version = 3.15` in `mypy.ini`, whereas [`mypy.ini:5`](../../mypy.ini)[^src-mypy] was updated to `python_version = 3.10` in hg rev 190 ([031](031.md)).
   * §2 (`vith/editor_buffer.py` snippet, line 139) still shows `if PTK3: loop = asyncio.get_running_loop()`, whereas `PTK3` was removed in hg rev 182 ([016](016.md)).
   * §6 (`vith/layout.py` snippet, line 322) still shows `errors[0].formatted_text`, whereas `Layout` now joins all errors on the cursor line ([012](012.md)).
4. **Stale references in `docs/thai_support_plan.md`**[^src-thai-plan]:
   * Line 85 cites `prompt_toolkit>=2.0.0,<3.1.0` at `setup.py:20`, whereas [`pyproject.toml:17`](../../pyproject.toml)[^src-setup] now specifies `prompt_toolkit>=3.0.0,<3.1.0`.
   * Lines 26, 347, and 571 cite `"13 unit tests in tests/test_thai.py, 68 total tests passing"`, whereas `tests/test_thai.py` now has 15 tests, `tests/test_thai_motions.py` has 6 tests, and the suite has 100 tests total; `tests/test_thai_motions.py` is also missing from the YAML frontmatter `sources:` list.
