# Renderer gate not latched by `:s` replacements / multi-row edits

**Category:** missed UI invalidation (stem: 002/072-row-11/069) · **Area:** `vith/editor_buffer.py` (`_on_text_changed`), `vith/commands/commands.py` (`substitute`) · **Found at:** stem audit, hg rev 269 · **Fixed at:** hg rev 271

## Summary

Two coupled probes (DEEP scan 2026-11-08):

* `Document(new_text)` assignment fires prompt_toolkit's `on_text_changed`
  *before* vith re-targets the cursor — `Document(new_text)` defaults its
  synthetic cursor to the end of the whole text, so `_on_text_changed`'s
  note observed the buffer's *last empty line*, not the edited rows. With
  `:s/land/ทำ/g` over `'\tTabs\tland\n\tmore\tland\n'`, the gate stayed `False`
  while the new Thai `ำ` renders.
* Every buffer-text mutation path was traced (keystrokes, `:e`, undo/redo,
  paste, `~`, `:s`): buffer *text* coverage is airtight for the **cursor
  line** only.

While the gate is `False`, `vith/thai.py:626` skips `_sanitize_and_invalidate_sara_am`
entirely — stray zero-width cells survive and SARA-AM neighbor refresh is off
(the 002 hazard) — despite the screen showing Thai.

## Fix

`substitute` now calls `note_document_text(new_text)` on the constructed full
text (the paste/undo paths re-latch through their own row-event bodies or are
documented above). Test:
`tests/test_substitute.py::test_substitute_latches_thai_gate` (`:s/land/ทำ/g`
from a clean session → gate `True`).
