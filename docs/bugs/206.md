# `:w!` fails on `~/...` paths and tilde locations bypass buffer deduplication

**Category:** I/O / editor buffer · **Area:** `vith/editor_buffer.py`, `vith/window_arrangement.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** open

## Summary

`EditorBuffer.__init__`, `EditorBuffer.write`, and `WindowArrangement._get_or_create_editor_buffer` normalize locations with `expand_env_vars(location)` rather than `expand_location(location)`, leaving `~` unexpanded.[^src-eb-init][^src-eb-write][^src-wa]

1. **`:w!` (`_write_forced`) always fails on `~/...` files:** Normal reads/writes succeed because `FileIO` internally calls `_expand_location`, but when a `0444` read-only file opened as `~/ro.txt` is force-saved (`:w!`), `FileIO.write` raises `PermissionError` and `_write_forced` calls `os.stat('~/ro.txt')` and `os.chmod('~/ro.txt', ...)` directly on the unexpanded tilde string, failing with `[Errno 2] No such file or directory: '~/ro.txt'`.[^src-forced]
2. **Duplicate buffers for the same file:** Opening `/home/user/foo.py` and then running `:e ~/foo.py` misses `get_editor_buffer_for_location` (`eb.location == location`) and opens a second independent `EditorBuffer` pointing to the same underlying file.

## Evidence

Live probe with `HOME` pointed at a temporary directory containing `0444` `ro.txt`:

* `ed.load_initial_files(["~/ro.txt"])` → `eb.location == '~/ro.txt'`.
* `eb.buffer.text = "updated"; eb.write(force=True)` → returns `False`, `ed.message == "[Errno 2] No such file or directory: '~/ro.txt'"`.

## Fix Direction

1. Expand local filesystem paths in `_write_forced` with `expand_location(target_location)` before calling `os.stat` and `os.chmod`.
2. Use `expand_location` (or canonicalized path comparison via `is_same_write_target`) in `EditorBuffer.__init__`, `EditorBuffer.write`, and `WindowArrangement.get_editor_buffer_for_location` / `_get_or_create_editor_buffer` so `~/foo.py` and `$HOME/foo.py` resolve consistently.
3. Add regression tests for `:w!` on a `0444` `~/...` path and `:e ~/...` buffer deduplication.
