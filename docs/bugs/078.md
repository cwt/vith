# `j`/`k` drift visually across Thai rows (codepoint-based `preferred_column`)

**Category:** wrong logic / Vim semantics (extrapolated from the 076/077 selection-stack classes) · **Area:** `vith/cold_text.py` (`ColdTextBuffer.cursor_up/down`), `vith/thai.py` (`_vertical_cursor_position`) · **Found at:** extrapolation audit 2026-11-08, hg rev 268 · **Fixed at:** hg rev 269

## Summary
`Buffer.cursor_up/cursor_down` (prompt_toolkit `buffer.py:710-728`) record
`preferred_column` as a **codepoint** column of the row it was recorded on, and vi
movements never re-record it (`vi.py` touches nothing). With Thai/Lao rows whose
leading clusters differ, holding that codepoint column across rows zig-zags on screen
and can even land on the line end (each cluster is visually one cell):

* repro (pre-fix): cursor at row 0 cp 5 (`น`, visual axis 2) → after `j` lands row 1
  **cp 12 = end-of-line** ("กำแพง", all base clusters); after the second `j` row 2 cp 17
  — the cursor drifts and rests at line ends instead of visual column 2.
* The old `_vertical_cursor_position` snapped to the *nearest* cell start of the clamped
  codepoint column (029-era heuristic) — that avoids mark-parking but does not keep the
  user's visual column.

## Fix
* `ColdTextBuffer.cursor_up/cursor_down` overrides replace ptk's sticky handling with
  `(cp_col, record_row)` memory (`_vith_cell_column`): the recorded codepoint column is
  interpreted as a **cell-cluster ordinal** of its recording row, then mapped back to
  the target row's codepoint column via `cell_starts` — visual parity, exact Vim
  behavior, including `count` > 1 and ASCII identity.
* `_vertical_cursor_position` (the `Document`-spec path used by vi.py's direct
  callers, e.g. visual-mode `j`/`k` at `vi.py:963/976`) converts the current-row
  codepoint column through `_cell_ordinal` / `_start_of_cell_ordinal` so marks never
  receive the cursor and the visual column tracks.
* The 029-era snap pins in `test_document_jk_vertical_snap` were updated
  from "nearest cell start" to "same visual column" (the visual-column behavior
  was the documented Vim intent; the old pin predates the cell-ordinal model).
  Both directions now assert landing on `'น'` — never a mark.
