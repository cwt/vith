# `:w!` does not force-write read-only files

**Category:** commands / I/O · **Area:** `vith/commands/commands.py`, `vith/io/backends.py` · **Found at:** upstream triage 2026-11-09 (`prompt-toolkit/pyvim#77`) · **Fix status:** fixed

## Summary

Editing a read-only file and running `:w!` reports a permission error instead of forcing the write like Vim.

## Evidence

* `write()` in `vith/commands/commands.py:423-436`[^src-cmd] uses `force` only for the `File exists (add ! to override)` guard; the read-only path is untouched.
* `FileIO.write()` in `vith/io/backends.py:53-60`[^src-io] opens with `io.open(location, 'w')` and returns `False` on `OSError`; no `chmod`/`force` handling.
* `EditorBuffer.write()` in `vith/editor_buffer.py:214-269`[^src-eb] propagates the exception message without a force path.

## Impact

* Vim users expect `:w!` to override the read-only bit; currently the only recovery is a shell `chmod`.

## Fix

* `EditorBuffer.write()` gained a `force` flag (threaded from `:w` / `:wq` / `:wqa`, including the previously dropped `:wqa!` force in `write_and_quit_all`). The UTF-8 fallback moved into `_write_with_backend()` unchanged; on `PermissionError` with `force`, `_write_forced()` grants owner-write, retries once, and restores the original mode.
* Regression tests in `tests/test_write_commands.py`: `:w` fails / `:w!` writes + restores `0o444`, flaky-backend retry accounting, `:wqa` aborts / `:wqa!` exits + writes.
