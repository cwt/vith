# `:e` after a file's external deletion silently blanks the buffer (data loss)

**Category:** data-loss robustness (stem: 070 reload family) · **Area:** `vith/editor_buffer.py` (`reload` ↔ `_read`) · **Found at:** stem audit 2026-11-08 · **Fixed at:** hg rev 271

## Summary (machine repro, pre-fix)

```
watch.txt = 'precious saved content'   # opened via EditorBuffer(editor, path)
watch.txt.unlink()
handle_command ':e'  → ok, no message
buffer text = ''      is_new=True   dirty=False   # ego stack empty
```

The not-exists branch (`_read`) reports `is_new = True, return ''` — designed
for новым files, silently destructive on `:e`.

## Fix

`reload()` captures `existed_before = not self.is_new`; when the read declines
(nonexistent/unknown backend fails) while a saved content existed, it shows
`'E211: File no longer exists: %r'` (Vim talks similarly) and keeps the in-memory
contents + dirty state (test-pinned `::test_reload_vanished_file_keeps_contents`).

Known overlapping behaviors retained: unreadable/unknown-backend reload already
kept contents (070), noting gate-relevant reload text (072 row 11) and the
existed/vanished states.
