# Vertical cursor motion, visual blocks, `{count}|`, and block paste drift after tabs on Thai text

**Category:** correctness · **Area:** `vith/thai/clusters.py`, `vith/thai/patches.py`, `vith/cold_text.py` · **Found at:** user field report comparing `/usr/bin/vim` and `vith` on `pentax.txt` (2026-11-20) · **Fix status:** fixed

## Summary

Although [127](127.md) fixed on-screen tab rendering (`TabsProcessor`) and [077](077.md)/[078](078.md)/[079](079.md)/[141](141.md) fixed visual-column movement and visual-block alignment on Thai/CJK lines without tabs, cursor movement (`j`/`k`, `{count}|`), visual-block selection (`<C-v>` highlight, `y`, `d`, `I`, `A`), and visual-block paste (`p`/`P`) **after `\t` characters** drifted horizontally relative to `/usr/bin/vim`.

## Evidence

Reproduced headlessly against `/usr/bin/vim -Nu NONE -n -es` on `pentax.txt` (9 Thai lines with 1–2 tabs separating stanzas and an empty line 5; default `tabstop = 8`, aligning the second stanza at visual column 25):

| Operation (`tabstop = 8`) | `/usr/bin/vim` | `vith` before fix | `vith` after fix |
| :--- | :--- | :--- | :--- |
| `j` down L1→L9 & `k` up L9→L1 at visual col 29 | Stays on visual col 29 across L1–L4 & L6–L9 (`ป`, `เ`, `ย`, `ส`, `<EOL>`, `น`, `มิ`, `รุ่`, `ห`) | Drifted right/left on every row after `\t` (`get_cwidth('\t') == 0`) | Exact match on all 9 lines (down & up) |
| `j` down L1→L9 at visual col 4 (before tabs) | Stays on visual col 4 (`พ`, `เ`, `ง`, `อ`, `<EOL>`, `า`, `า`, `า`, `ต่`) | Already aligned | Unchanged, exact match |
| `29\|` on every line | Jumps to visual col 29 | Jumped to raw codepoint 28 (up to 4 visual cols off on L2) | Exact match on all 9 lines |
| `<C-v>3j3l` at visual col 29 (`y`, `d`, `I`, `A`, all 4 corner drags) | Highlights/edits vcols 29–32 (`ปลกมี`, `เป็นเ`, `ยดสา`, `สนเก๋`) | Misaligned columns; `y`/`d` also dropped last column (`TextObject` off-by-one) | Exact match with Vim |
| `<C-v>` crossing shorter tabbed line (`\t\t\tABCXYZ`, len 9 < anchor cp 27) | Includes `YZ` at vcols 29–30 | Row dropped (`col1 > len(line)` in `prompt_toolkit`) | Exact match with Vim |
| `<C-v>3j3ly` then `P` / `p` (incl. `p` on `'มิ'`) | Aligns pasted block on display col without splitting `'มิ'` | Indexed raw codepoint column and split `'ม'`/`'ิ'` | Exact match with Vim |

### Root Causes

1. **Zero-width `\t` in visual-column math** (`vith/thai/clusters.py`): `_compute_cell_columns` summed `get_cwidth(char)` (which returns `0` for `'\t'`), and ASCII fast paths (`line.isascii()`) skipped tab expansion completely.[^src-clusters]
2. **No buffer `tabstop` propagation** (`vith/cold_text.py`, `vith/thai/patches.py`): vertical motion and visual-block selection did not query `EditorBuffer.tabstop` (so custom `:set tabstop=N`, `:setlocal ts=N`, per-filetype tabstops, and split-local tabstops were ignored) and did not invalidate cached sticky columns when `tabstop` changed.[^src-cold]
3. **Codepoint-length row filtering in visual blocks** (`vith/thai/patches.py`): `Document.selection_ranges` / `selection_range_at_line` delegated row eligibility to `prompt_toolkit`, which skips any row whose codepoint `len(line)` is smaller than the corner's raw codepoint column even when its tab-expanded visual width spans the block.[^src-patches]
4. **Upstream `TextObject.operator_range` vs `TextObject.cut` off-by-one** (`vith/thai/patches.py`): `prompt_toolkit` omits `end += 1` for `TextObjectType.BLOCK` in `operator_range` while `TextObject.cut` still runs `to -= 1`, shifting the upper block corner 1 codepoint left and dropping the final column on `<C-v>...y`/`d`.[^src-patches]
5. **Raw-codepoint `{count}|` and block paste** (`vith/thai/patches.py`): `Document.get_column_cursor_position` and `Document.paste_clipboard_data` (`SelectionType.BLOCK` and Vi-after `SelectionType.CHARACTERS`) were unpatched and operated on raw codepoint indices.[^src-patches]

## Fix

* **`vith/thai/clusters.py`**:[^src-clusters]
  * Added `DEFAULT_TABSTOP = 8` and expanded `\t` via `visual += ts - (visual % ts)` in `_compute_cell_columns` (matching `TabsProcessor`), keyed `_cell_columns_cached` by `(line, tabstop)`.
  * Guarded ASCII fast paths with `"\t" not in line` so pure-ASCII tabbed lines expand tabs identically.
  * Added `_line_visual_width(line, tabstop)` and `_end_of_visual_col(line, visual_col, tabstop)`.
* **`vith/cold_text.py`**:[^src-cold]
  * Added `ColdTextBuffer._effective_tabstop()` reading `eb.tabstop` via `_vith_editor_buffer_ref` (covering `:set ts=N`, `:setlocal ts=N`, global/filetype defaults, and per-buffer overrides).
  * Extended `_vith_cell_column` to `(src_col, src_row, ordinal, tabstop)` and re-anchored on the current cursor position whenever `tabstop` changes mid-run.
* **`vith/thai/patches.py`**:[^src-patches]
  * Added `_document_tabstop(doc)` matching `doc` against the active buffer and open split buffers (`editor.window_arrangement.editor_buffers`), falling back to the active buffer's `tabstop` (e.g., transient `Document` inside `TextObject.cut`) or `DEFAULT_TABSTOP`.
  * Rewrote the `SelectionType.BLOCK` branches in `_thai_selection_ranges` and `_thai_selection_range_at_line` directly in display columns across `from_line..to_line`, eliminating codepoint-length row drops while preserving `prompt_toolkit`'s EOL-space highlight marker.
  * Added `end += 1` (without crossing `\n`) for `TextObjectType.BLOCK` in `_thai_operator_range` so `TextObject.cut` lands on the exact inclusive upper corner.
  * Added `_doc_get_column_cursor_position` (`{count}|`) and `_thai_paste_clipboard_data` (display-column visual-block `p`/`P` and cluster-safe charwise `p`) to `_DOCUMENT_PATCH_SPECS`.
* **Regression tests**:[^src-tests]
  * Added `tests/test_thai_tabs_motion.py` covering `pentax.txt` (`j`/`k` at visual col 29 and col 4, `29|`, `<C-v>` highlight through `TabsProcessor` + `HighlightSelectionProcessor`, `y`/`d`/`I`/`A`, all 4 drag directions, crossing empty line 5, block `P`/`p` and charwise `p` on `'มิ'`), shorter tabbed lines, pure ASCII with tabs, `:set tabstop=N` / `:setlocal ts=N` across `tabstop` values `2, 3, 4, 6, 8, 12`, mid-run `tabstop` changes, and split buffers with identical text and differing `tabstop`.
  * Updated `tests/test_cold_text.py` for the 4-tuple `_vith_cell_column` and tabstop-change re-anchoring.
