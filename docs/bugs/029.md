# Near-clone implementation pairs across key bindings, thai scanners and set handlers

**Category:** duplication · **Area:** `vith/key_bindings.py`, `vith/thai.py`, `vith/commands/commands.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* `e` vs `E`: [`vith/key_bindings.py:276-300`](../../vith/key_bindings.py) —
  two ~12-line handlers differing only in the `WORD=` argument of
  `doc.find_next_word_ending`.
* `x` vs `X`: [`vith/key_bindings.py:187-213`](../../vith/key_bindings.py) —
  mirrored delete-at/delete-before cluster handlers (delete, clipboard set).
* `get_cursor_up_position` vs `get_cursor_down_position`:
  [`vith/thai.py:696-715`](../../vith/thai.py) — mirrored J/K snap logic.
* `tabstop` vs `scrolloff` value setters:
  [`vith/commands/commands.py:517-552`](../../vith/commands/commands.py) —
  identical int-coercion boilerplate with a *suspicious* semantic divergence:
  tabstop demands `value > 0`, scrolloff accepts `value >= 0` (intended, but
  accidental-looking).

## Impact

Four places where a future fix must be applied twice (clipboard handling in
`x`/`X` is exactly the kind of spot that drifts — see also
[028](028.md) for the `:set` chain).

## Fix direction

Introduce small factories/shared helpers:
`register_word_ending_binding(kb, key, WORD=…)`; a symmetric
`delete_cluster(event, backward=True/False)`; one
`vertical_motion(…)` implementation parameterised by ±count; and a
`set_int_option(min_value)` helper keeping each option's minimum explicit.
