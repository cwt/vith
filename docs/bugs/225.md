# `BufferListOverlay` column padding uses codepoint count instead of display width

**Category:** layout / display width · **Area:** `vith/layout.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** open

## Summary

When rendering the floating buffer list while typing `:b `, `BufferListOverlay.get_tokens()` computes column widths using Python `len(...)` (codepoints) instead of terminal display width (`get_cwidth`):[^src]

```python
max_location_len = max(
    len(info.editor_buffer.get_display_name()) for info in buffer_infos
)
...
(t, ' ' * (max_location_len - len(eb.get_display_name()))),
```

Thai/Lao combining marks (`GC=Mn`, width `0`) make `len(name)` larger than its visual width (under-padding the row), while CJK/wide characters (width `2`) make `len(name)` smaller than its visual width (over-padding other rows), misaligning the trailing `line N` column. It also calls `eb.get_display_name()` three times per buffer per frame.

## Evidence

Live probe opening `".../ก้้้.txt"` (3 zero-width marks) alongside `".../abcd.txt"`:

* Row 1 (`ก้้้.txt`): `len == 55`, terminal display width `== 52` (`line 1` shifted 3 cells left).
* Row 2 (`abcd.txt`): `len == 55`, terminal display width `== 55`.

## Fix Direction

1. Compute `(display_name, get_cwidth(display_name))` once per `info` in `BufferListOverlay.get_tokens()` and pad with `max_width - name_width` spaces.
2. Add a regression test asserting equal display widths across Thai-combining, CJK, and ASCII rows in `BufferListOverlay`.
