# CSV row-cap off-by-one

**Category:** render / csv · **Area:** `vith/render.py` · **Found at:** Round 17 read-only re-audit (2026-11-23, `v0.16.4`) · **Fix status:** fixed

> **Resolution note (2026-11-23):** Changed guard to `idx >= _CSV_MAX_ROWS` so exactly 5000 rows are kept. Pinned with `test_198_csv_row_cap_keeps_exactly_max_rows`.

## Summary

`_CSV_MAX_ROWS = 5000` with `for idx, row in enumerate(reader): if idx > _CSV_MAX_ROWS: break` keeps indices `0..5000` — 5001 rows — before truncating.[^src] The footer then reports `... truncated after 5000 rows ...`, understating the kept row count by one. The landmark sampler correctly uses `range(0, min(n, _CSV_MAX_ROWS), step)` (5000 max).[^src-landmark]

## Evidence

Reproduction of the shipped loop with 6000 input rows:

* `kept == 5001`, `truncated == True` (expected `5000`).

## Fix Direction

1. Change the guard to `if idx >= _CSV_MAX_ROWS: break`.
2. Regression test: 6000-row CSV renders 5000 data rows + truncation note.
