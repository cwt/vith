# Additional unoptimized hot paths outside the P1–P3 sweep

**Category:** performance (low priority) · **Area:** `vith/lexer.py`, `vith/completion.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

| # | Path | Detail | Suggested fix |
| :-- | :--- | :--- | :--- |
| 1 | File-explorer lexing — [`vith/lexer.py:87-88`](../../vith/lexer.py) | `PygmentsLexer(DirectoryListingLexer, …)` is re-constructed (registry scan ~0.6 ms) on **every keystroke** while browsing directories — the one per-keystroke path the P1 cache didn't cover. | Cache the `PygmentsLexer` instance like `_ensure_lexer` does for file buffers. |
| 2 | To-EOF text join — [`vith/lexer.py:106-108`](../../vith/lexer.py) | `'\n'.join(document.lines[start_lineno:])` materializes a string to EOF each time a generator is (re)created from a sync point; cheap vs. old eager lexing, but grows with distance to EOF. | Cap the join tail at (`i + visible_lines + margin`) — visible height is known via `render_info`. |
| 3 | jedi API introspection — [`vith/completion.py:159`](../../vith/completion.py) | `inspect.signature(jedi.Script)` runs on **every** completion call though the answer is process-constant. | Hoist to a module-level lazy constant (compute on first use). |
| 4 | Cache-key slices — [`vith/completion.py:41-43`](../../vith/completion.py) | The P3 cache key holds/copies `text[:line_start]` + `text[line_end:]` per keystroke (asymptotically O(file) even on cache hits). Measured 0.005 ms @ 340 KB — acceptable, noted for awareness only. | Key on `(len(doc_lines), row, line text)` + a cheap text hash/version if ever needed. |

## Impact

Individually small; item 1 is the most user-visible (directory buffers), the
others are asymptotic notes.
