# `:setlocal all` is rejected

**Category:** commands / `:set` · **Area:** `vith/commands/options.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`_apply_set_option()` rejects every option not in `_LOCAL_SET_OPTION_NAMES`
with `E518: all is not a buffer-local option` before the `opt == 'all'` branch
is evaluated.[^src-options] Vim's `:setlocal all` lists all options (showing
local values where applicable). Query forms such as `:setlocal number?`
correctly bypass the guard, so only the `all` convenience form is broken.

## Evidence

| Command | Vim | vith |
| :--- | :--- | :--- |
| `:set all` | option listing | option listing (works) |
| `:setlocal all` / `:setl all` | same listing with local values | `E518: all is not a buffer-local option` |

## Fix Direction

1. Move the `opt == 'all'` check ahead of the buffer-local guard (or allow
   `'all'` through the guard) so `:setlocal all` routes to the same option
   listing as `:set all`.
2. Add regression tests for `:set all`, `:setlocal all`, and `:setl all`
   asserting the listing is produced.
