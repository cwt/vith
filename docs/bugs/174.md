# `:set ff?` / `:set fileformat?` report "Unknown option"

**Category:** commands / `:set` · **Area:** `vith/commands/options.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`_query_set_option()` handles the catalog's queryable options but has no branch
for `fileformat` / `ff`,[^src-options] even though the value setter is
registered for both names and processed by the generic branch. Vim reports
`fileformat=unix` for `:set ff?`. The only way to observe the value today is
the bare `:set ff`, which routes to `set_fileformat(editor, None)` and prints
via a different path. Multi-token queries such as `:set ts? ff?` fail too.

## Evidence

| Command | Vim | vith |
| :--- | :--- | :--- |
| `:set ff?` | `fileformat=unix` | `Unknown option: ff` |
| `:set fileformat?` | `fileformat=unix` | `Unknown option: fileformat` |
| `:setlocal ff?` | `fileformat=unix` (local) | `Unknown option: ff` |

## Fix Direction

1. Add `fileformat`/`ff` to the query dispatch in `_query_set_option()`,
   returning `fileformat=<effective value>` from the active editor buffer
   (respecting `:setlocal`). Ensure the generic catalog snapshot used by bare
   `:set` is the single source of truth ([152](152.md) precedent).
2. Add regression tests for `:set ff?`, `:set fileformat?`, `:setl ff?`, and a
   multi-token `:set ts? ff?`.
