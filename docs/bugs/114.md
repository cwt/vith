# Unoptimized algorithms and memory-growth inventory (Round 6)

**Category:** performance / memory · **Found at:** Round 6 read-only deep audit, 2026-11-09 · **Fix status:** open

## Inventory

| # | Location | Issue | Notes |
| :-- | :-- | :-- | :-- |
| 1 | `vith/lexer.py:22` | Unbounded `_STYLE_TOKEN_CACHE`. | Memory growth risk. |
| 2 | `vith/thai/clusters.py:87-101` | `cell_starts` LRU cache has no size guard. | Large distinct lines can pin memory. |
| 3 | `vith/thai/words.py:213-220` | `find_thai_word_breaks` rescans entire text for `all_thai`/`has_thai_base` on every call. | Repeated work. |
| 4 | `vith/thai/patches.py:328-332` | SARA-AM loop builds `all_xs` from every column, then filters per `x`. | O(columns log columns) per row. |
| 5 | `vith/thai/patches.py:457-474` | Window copy-body patch iterates every visible row even without combining marks at right margin. | Candidate fast path only after scan. |
| 6 | `vith/editor.py:254-272` | `current_editor_buffer` O(n) scan on every access. | Hot path. |
| 7 | `vith/layout.py:101-110` | `TabsControl.tab_handlers` never cleared/pruned. | Lifetime cache. |
| 8 | `vith/window_arrangement.py:53-59` | `TabPage.windows()` rebuilds full split tree on every call. | Repeated by many callers. |

## Fix direction

Bound caches, add fast paths, and cache/reuse traversal results where safe.
