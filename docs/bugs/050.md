# `EditorBuffer.write` and `:w` mutate `location` before validation, skip `expanduser` on overwrite check, and miss reporter/lexer refresh

**Category:** wrong logic · **Area:** `vith/editor_buffer.py`, `vith/commands/commands.py`, `vith/lexer.py` · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

Three related issues affect `:w <location>` and `EditorBuffer.write`:

1. **Premature mutation of `self.location` and misleading error message** ([`vith/editor_buffer.py:155-165`](../../vith/editor_buffer.py)[^src-eb]):
   `EditorBuffer.write(location)` executes `if location: self.location = location` *before* checking whether any backend can open `location` or whether `io.write(...)` succeeds. If `:w /nonexistent_dir/file.py` or `:w ftp://host/file` fails, `self.location` remains permanently mutated to the invalid path. Furthermore, if no backend matches on a subsequent `:w` (where `location=None`), line 164 raises `OSError(f'Unknown location: {location}')` — formatting the parameter `None` instead of `self.location` (`Unknown location: None`).
2. **Overwrite protection bypassed for `~/...` paths** ([`vith/commands/commands.py:333`](../../vith/commands/commands.py)[^src-cmd]):
   `_write` checks `if location and not force and os.path.exists(location):` without `os.path.expanduser(location)`. Running `:w ~/existing_file.txt` evaluates `os.path.exists('~/existing_file.txt')` (`False`) and silently overwrites `~/existing_file.txt` without requiring `:w!`.
3. **Missing lexer invalidation, `run_reporter()`, and `note_document_text` after saving to a new filename**:
   * When an unnamed buffer (or `.txt` buffer) is saved as `foo.py` via `:w foo.py`, `EditorBuffer.write` neither calls `self.run_reporter()` nor `note_document_text(self.location)`[^src-eb].
   * `DocumentLexer` (`vith/lexer.py:34`)[^src-lex] inherits `Lexer.invalidation_hash(self) -> Hashable: return self`, so `BufferControl._fragment_cache` (keyed by `(document.text, lexer.invalidation_hash())`) is not invalidated when `editor_buffer.location` changes without a text edit.

## Evidence

* [`vith/editor_buffer.py:155-165`](../../vith/editor_buffer.py)[^src-eb]:
  ```python
  def write(self, location=None):
      "Write buffer to I/O backend."
      # Take location and expand tilde.
      if location:
          self.location = location

      # Find I/O backend that handles this location.
      for io in self.editor.io_backends:
          if io.can_open_location(self.location):
              break
      else:
          raise OSError(f'Unknown location: {location}')

      io.write(self.location, self.buffer.text, self.encoding)
      self.has_unsaved_changes = False
  ```
* [`vith/commands/commands.py:333-336`](../../vith/commands/commands.py)[^src-cmd]:
  ```python
  if location and not force and os.path.exists(location):
      editor.show_message(
          'File exists (add ! to override)'
      )
  ```

## Impact

* Failed `:w <new_path>` calls corrupt the buffer's `location`.
* `:w ~/existing` silently overwrites existing files in the user's home directory without `!`.
* Saving an unnamed buffer as `foo.py` leaves existing lines unhighlighted (until edited) and does not run `pyflakes` until the next edit.

## Fix direction

1. In `commands.py:_write`, check `os.path.exists(os.path.expanduser(location))`.
2. In `EditorBuffer.write`, resolve `target_location = location or self.location`, validate the backend (raising `OSError(f'Unknown location: {target_location}')` on failure), perform `io.write(target_location, ...)`, and only update `self.location = target_location` after `io.write` succeeds. When `self.location` changes, trigger `self.run_reporter()`.
3. Implement `DocumentLexer.invalidation_hash(self)` returning `(self.editor_buffer.location, self.editor_buffer.in_file_explorer_mode)`.
