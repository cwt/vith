# `EditorBuffer.reload()` fails to clear `read_only` when an unreadable file becomes readable

**Category:** editor buffer / reload · **Area:** `vith/editor_buffer.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** open

## Summary

During `EditorBuffer.__init__`, if `_read(self.location)` returns `None` (for example `PermissionError` on a `0000` file or a transient network error), `unreadable` is set to `True` and `ColdTextBuffer` is constructed with `read_only=self.isdir or unreadable` (`True`) so the user cannot accidentally overwrite unseen content.[^src-init]

When permissions or connectivity are fixed externally and the user runs `:e` / `eb.reload()`, `_read()` succeeds and returns the file text, but `reload()` only enforces `read_only = to_filter(True)` when `self.isdir` is true — it never clears the `unreadable`-induced `read_only` flag (or clears `read_only` when a directory was replaced on disk by a regular file), leaving the reloaded buffer permanently uneditable unless the user manually runs `:set noro`.[^src-reload]

## Evidence

Live probe with a `0000` file `secret.txt`:

1. Create `secret.txt` (`"top secret\n"`), `os.chmod(p, 0o000)`, `ed.load_initial_files([p])` → `eb.buffer.read_only() == True`.
2. `os.chmod(p, 0o644)`, `eb.reload()` → `eb.buffer.text == 'top secret'`, **but `eb.buffer.read_only() == True`**.

## Fix Direction

1. Track whether `read_only` was set automatically (`_auto_read_only` for `isdir` or `unreadable`, distinct from explicit user `:set ro`), and update `self.buffer.read_only = to_filter(self.isdir)` on a successful `reload()` unless user `:set ro` was explicitly enabled.
2. Add a regression test reloading a `0000` → `0644` file and asserting `eb.buffer.read_only()` becomes `False`.
