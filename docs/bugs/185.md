# `docs/live_render.md` config table drifts from implementation

**Category:** docs / render config · **Area:** `vith/rc_file.py`, `docs/live_render.md` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

The configuration table in `docs/live_render.md` §8 describes:

* `[render].debounce_ms` as a "Non-negative `int`" with no upper bound;
* `[render].default_split` as `'vertical' or 'horizontal'`.

The implementation is stricter and more permissive in different places:
`rc_file.py` rejects `debounce_ms > 10000` with
`"expected an integer in 0..10000"`,[^src-rc] and accepts the aliases
`v`/`vert`/`h`/`horiz` for `default_split`.[^src-rc] A user following the doc
and setting `debounce_ms = 20000` gets an error the doc says should be accepted.

## Evidence

| Documented | Implemented |
| :--- | :--- |
| `debounce_ms`: non-negative int (no max) | `0..10000`, values above reported and skipped |
| `default_split`: `vertical`/`horizontal` only | also `v`, `vert`, `h`, `horiz` |

## Fix Direction

1. Update `docs/live_render.md` §8 to state the `0..10000` bound and list the
   accepted aliases, matching `rc_file.py`.
2. Add a doc-consistency test or note in the config-validation tests so future
   bound changes keep the reference accurate.
