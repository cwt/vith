# `DocumentWordsCompleter` reads nonexistent `editor_buffer._text_version` (stale in prod) and defeats P3 if wired to `_text_version`

**Category:** correctness / caching performance · **Area:** `vith/completion.py`, `vith/cold_text.py`, `vith/editor_buffer.py` · **Found at:** Round 10 deep performance audit (2026-11-22, `v0.15.1` / rev 392) · **Fix status:** fixed (2026-11-22)

**Resolution note (2026-11-22):** Added `_non_cursor_version` and `_single_line_edit_start` tracking on `ColdTextBuffer` (`vith/cold_text.py`), bumping `_non_cursor_version` on any multi-line edit, edit on a line other than `_single_line_edit_start`, or direct `text`/`document`/`undo`/`redo` replacement while keeping `_non_cursor_version` unchanged for consecutive single-line edits on the active cursor line. Wired `DocumentCompleter.get_completions` (`vith/completion.py`) to anchor `buf._single_line_edit_start` to the completion line and pass `buf._non_cursor_version` (falling back to `editor_buffer._text_version` for synthetic stubs). Verified by `test_164_completer_invalidates_non_cursor_edits_and_preserves_p3_cursor_line_cache` in `tests/test_round10_perf.py`.

## Summary

Round 8 ([149](149.md) item 4) added a `version` parameter to `DocumentWordsCompleter.get_completions` to prevent stale non-cursor words after same-length edits on another line, and wired `DocumentCompleter.get_completions` (`vith/completion.py:143-145`) to pass `getattr(editor_buffer, '_text_version', None)`.[^src-comp]

This has two compounding flaws:

1. **Stale-cache bug still reproduces in production:** `_text_version` is an attribute of `ColdTextBuffer` (`editor_buffer.buffer`), **not** `EditorBuffer` (`hasattr(eb, '_text_version') == False`).[^src-cold][^src-eb] Every production completion passes `version=None`, so replacing `'beta'` with `'zzzz'` on line 1 while completing `'be'` on line 2 still yields the stale word `'beta'`.
2. **Naive fix breaks P3 caching:** Passing `editor_buffer.buffer._text_version` increments `version` on **every keystroke**, including edits on the cursor line itself — forcing a full-document regex scan and sort on every Tab press while typing on the same line and defeating P3 (`docs/speed_latency_plan.md`).

## Evidence

Measured on `Python 3.15.2`:

| Check | Result |
| :--- | :--- |
| `hasattr(eb, '_text_version')` / `hasattr(eb.buffer, '_text_version')` | `False` / `True` |
| Production `DocumentCompleter` after same-length non-cursor edit (`beta\nbe` → `zzzz\nbe`) | Offers **`['beta']`** (stale!) |
| 4,000-line typing on cursor line: `version=None` vs incrementing `version` | **0.455 ms** → **2.888 ms** (**6.4× slower**) |

## Fix Direction

1. Track a `_non_cursor_version: int` counter on `ColdTextBuffer` (or `EditorBuffer`) that increments whenever an edit modifies lines other than the previous cursor-line edit — specifically, when `insert_text`/`delete`/`delete_before_cursor` inserts/deletes a newline, when the edit row differs from the last single-line edit row, or on any whole-document assignment (`document = ...`, `undo`, `redo`, `reset`).[^src-cold][^src-eb]
2. Pass `getattr(editor_buffer.buffer, '_non_cursor_version', getattr(editor_buffer, '_text_version', None))` from `DocumentCompleter.get_completions` so same-length edits on other lines always invalidate immediately while consecutive edits on the cursor line keep a 100% cache hit rate.[^src-comp]
