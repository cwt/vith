# Miscellaneous Vim-semantics deviations (`r` count, file-explorer whole-line open, `is_combining_char` multi-char, cold-text version, private `_search`)

**Category:** wrong logic (grouped lows, as in [054](054.md)) · **Area:** `vith/key_bindings.py`, `vith/thai.py`, `vith/cold_text.py`, `vith/commands/commands.py` · **Found at:** deep review, hg rev 87de3a3 (2026-11-08)

## Summary

| # | Location | Defect |
|---|---|---|
| 1 | `key_bindings.py:115-130` | `autocomplete_or_indent` docstring says “do autocompletion, otherwise indent” — code only inserts a tab/space (filter is `whitespace_before_cursor_on_line`). Name + docstring lie; no completion is wired. |
| 2 | `key_bindings.py:242-256` | `2rX` inserts `event.data * event.arg` (`"XX"`) and backs up one cell. Vim `r` semantics with count (replace N chars with one char) do not match. |
| 3 | `key_bindings.py:188-201` | File-explorer `<Enter>` opens the whole `current_line`, not the word under cursor. Filenames with spaces open as one path. |
| 4 | `thai.py:173-193` | `is_combining_char(ch: str)` reads only `ch[0]` but suggests a string API. Cluster strings silently ignore the suffix. Assert `len(ch)==1` or document. |
| 5 | `cold_text.py:192-206` | “Cursor-only” optimization (`top_version == _text_version → update_top_cursor`) never hits if `_text_version` bumps on history-index changes before `save_to_undo_stack`, so duplicate snapshots are pushed. Undocumented, untested invariant (see also `cold_text.py:208-217` undo-discard loop). |
| 6 | `commands.py:834` | `substitute` calls private `buffer._search(...)`. Breaks on prompt_toolkit rename (same class of fragility as [080](080.md)). |
| 7 | `thai.py:604-651`, `705-735` | `find_previous_word_ending(count=-1)` delegates to `find_next_word_ending` without `include_current_position` — negative `ge`/`gE` counts have no correct counterpart. |

## Impact

Each is cosmetic or edge-case; together they are the “Vim-parity paper cuts” a daily driver feels.

## Fix direction

Rename/document (1); align `r` count with Vim + test; open word-under-cursor in file explorer; assert `len==1` in (4); add a cursor-only test for (5) or drop the optimization; use public search API in (6); remove or implement negative-count paths in (7).
