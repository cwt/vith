# `:norm` text-change check uses `is not`

**Category:** commands / normal · **Area:** `vith/commands/normal.py` · **Found at:** Round 17 read-only re-audit (2026-11-23, `v0.16.4`) · **Fix status:** fixed

> **Resolution note (2026-11-23):** Replaced identity with `buff.text != start_text`. Pinned with `test_norm_noop_does_not_fire_text_changed_200`.

## Summary

After replaying keys, the `:norm` epilogue decides whether to notify the buffer with `buff.text is not start_text` (combined with a `_text_version` check).[^src] `is` tests object identity, not string value. When the text is unchanged `Buffer.text` currently returns the same stored object so the check happens to pass, but any path that materializes an equal-valued copy (copy/join/slice round-trip) yields `is not == True` despite no semantic change and fires a spurious `_on_text_changed()` (Thai-gate note, preview refresh). String equality must use `!=`.

## Evidence

* `vith/commands/normal.py:263` — `getattr(buff, '_text_version', None) != start_version or buff.text is not start_text`.
* `''.join(['he', 'llo']) == 'hello'` is `True` while `is` is `False`, so the shipped expression reports “changed” for equal text.

## Fix Direction

1. Replace with `buff.text != start_text`.
2. Regression test: no-op `:norm` (e.g. `l` at EOL-clamped row) does not bump `_on_text_changed` / version side effects.
