# `DocumentLexer` unbounded `line_generators` memory leak, out-of-range EOF drain, and 215-module `guess_lexer` freeze

**Category:** memory leak / performance · **Area:** `vith/lexer.py`, `vith/editor_buffer.py` · **Found at:** Round 10 deep performance audit (2026-11-22, `v0.15.1` / rev 392) · **Fix status:** fixed (2026-11-22)

**Resolution note (2026-11-22):** Added an $O(1)$ `if i < 0 or i >= num_lines: return []` guard and bounded `line_generators` to `MAX_LINE_GENERATORS = 2` (LRU-evicting and `.close()`ing the oldest generator so its `document.text[start_index:]` slice is released immediately) in `DocumentLexer.lex_document`, cached filename lookup misses per location in `_ensure_lexer`, and replaced `pygments.lexers.guess_lexer()` in both `vith/lexer.py` and `vith/editor_buffer.py` with the shared lightweight deterministic `sniff_filetype_from_text()` helper (0 Pygments lexer modules imported on plain extensionless or unnamed buffers). Verified by `test_162_*` in `tests/test_round10_perf.py`.

## Summary

Three performance and memory defects exist in lexer creation and streaming:

1. **Unbounded generator & substring slice leak (`vith/lexer.py:219-275`):** `DocumentLexer.lex_document` stores every created generator in `line_generators: dict[Any, int]` and never evicts old entries.[^src-lexer] Each generator closure pins `text = document.text[start_index:]` (up to the full file size). Scrolling upward or jumping backward (`Ctrl-B`, `?search`, `:100`) accumulates live generators and multi-MB slices until the next edit invalidates `BufferControl._fragment_cache`.
2. **Out-of-range EOF drain (`vith/lexer.py:262-274`):** Calling `get_line(i)` with `i >= len(document.lines)` runs `for num, line in generator:` all the way to EOF before returning `[]`.[^src-lexer]
3. **215-module `guess_lexer()` freeze (`vith/lexer.py:75-99`, `vith/editor_buffer.py:157-176`):** Both `DocumentLexer._sniff_lexer_for_location` and `EditorBuffer.filetype` call `pygments.lexers.guess_lexer(sample)`.[^src-lexer][^src-eb] `guess_lexer` dynamically imports **all 215+ `pygments.lexers.*` modules** (~580 lexers) and evaluates `analyse_text()` on every one. This triggers not only when opening extensionless/unknown-extension files (`README`, `LICENSE`, `notes`, `.log`), but also on the **first `>>`, `<<`, `Tab`, `j`, or `k`** in a non-empty unnamed buffer (`eb.tabstop` → `eb.filetype` → `guess_lexer`), and frequently misclassifies plain prose/numbers (e.g., `"12345\n67890\n"` → `CbmBasicV2Lexer`; plain logs → `TeraTermLexer`).

## Evidence

Measured on `Python 3.15.2` / `Pygments 2.21.0`:

| Probe | Measured cost |
| :--- | :--- |
| 45 backward scroll jumps on a **642 KB** (20k-line) `.py` file (`tracemalloc`) | **+18.44 MB retained** (**29× file size**) |
| Cold `DocumentLexer._ensure_lexer` on extensionless text file | **66.83 ms**, **+216 imported modules** (`215` `pygments.lexers.*`) |
| `>>` (`_shift_lines`) on 1 line of an unnamed buffer (cold `guess_lexer`) | **89 ms** (profiled importing `ErlangLexer` + 215 modules) |
| `get_line(len(doc.lines) + 5)` on 20k-line `.py` file | Tokenizes to EOF instead of $O(1)$ bounds check |

## Fix Direction

1. In `DocumentLexer.lex_document`, short-circuit `if i < 0 or i >= len(document.lines): return []`, and cap `line_generators` to a small bounded window (e.g., at most 2 active generators, closing and evicting the oldest entry before adding a new one so old `document.text[start_index:]` slices are freed immediately).[^src-lexer]
2. Replace `pygments.lexers.guess_lexer()` with a lightweight, deterministic content sniffer shared by `vith/lexer.py` and `vith/editor_buffer.py`:
   - Shebang detection (`#!/...` including `#!/usr/bin/env <interp>` for `python`/`python3`, `bash`/`sh`/`zsh`/`dash`/`ksh`, `node`/`deno`/`bun`, `ruby`, `perl`, `lua`, `php`, `awk`, `Rscript`, `pwsh`).
   - High-confidence structural headers (`<!DOCTYPE html`/`<html`, `<?xml`, `<?php`, `diff --git` / unified diff, JSON `{`/`[` heuristic, Python `def `/`class `/`import ` + `:` heuristic matching [121](121.md) and [149](149.md) tests).
   - Never import all 215 Pygments lexer modules on plain text or unnamed buffers.
