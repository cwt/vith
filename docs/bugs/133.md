# `:e` reload crashes on read-only buffers and leaves stale diagnostics

**Category:** crash / reload contract · **Area:** `vith/editor_buffer.py` (`reload`), `vith/commands/commands.py` (`buffer_edit`) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** fixed

## Summary

`EditorBuffer.reload()` calls `self.buffer.document = Document(text, ...)`
without considering `buffer.read_only`. prompt_toolkit's `Buffer` document
setter rejects writes while `read_only()` is true, raising
`prompt_toolkit.buffer.EditReadOnlyBuffer`. The `:e` / `:e!` handler calls
`reload()` directly, so the exception escapes the command handler and kills
the interaction.

This affects several ordinary states:

* a directory listing opened by `:e <dir>` or the file explorer
  (`EditorBuffer.isdir` forces `read_only`),
* a file that could not be read and was intentionally made read-only
  (docs/bugs/070.md),
* any named buffer after `:set ro` / `:set readonly`.

A successful reload also leaves stale state: pyflakes errors for the old text
remain in `report_errors`/`report_errors_by_line`, and `_detected_filetype`
is not cleared when the content changes. A directory that replaces a file
during reload sets `isdir=True` but leaves `buffer.read_only` false.

## Evidence

* Reload implementation:

  ```python
  def reload(self):
      ...
      text = self._read(self.location)
      ...
      self.buffer.document = Document(text, cursor_position)
      self._file_content = text
      self._has_unsaved_changes = False
      note_document_text(text)
  ```

  ([`vith/editor_buffer.py:294-319`](../../vith/editor_buffer.py#L294-L319)).
  There is no `read_only` guard, no `run_reporter()`, and no reset of
  `_detected_filetype`.

* Probe, directory buffer (`load_initial_files(['/tmp/opencode'])`):

  ```text
  isdir=True, read_only=True
  :e  -> EditReadOnlyBuffer
  :e! -> EditReadOnlyBuffer
  ```

* Probe, named file after `:set ro`:

  ```text
  :set ro -> read_only=True
  :e      -> EditReadOnlyBuffer
  ```

* Probe, stale diagnostics on a `.py` file:

  ```text
  eb.report_errors = ['stale']; eb.report_errors_by_line = {0: ['stale']}
  eb.reload()  # file content changes on disk
  -> text 'y=2', errors ['stale'], by_line {0: ['stale']}
  ```

* Vim reloads a read-only buffer (`:e`), a directory (opens the explorer /
  reports E17 depending on settings), and a file after `:set ro` without
  crashing.

## Impact

* A single `:e` on a directory or read-only buffer aborts the TUI.
* Users who mark a file read-only and then reload lose the session.
* Even when reload succeeds, the report toolbar and lexer can continue to
  describe the previous file content until the next edit.

## Fix direction

1. Reload through a helper that temporarily clears `buffer.read_only`
   (or uses a document assignment API that bypasses the read-only check),
   then restores the filter.
2. After assigning the new document, call `run_reporter()` and reset
   `_detected_filetype` / `_last_text_len` / `_last_line_count`.
3. If `_read()` switches the path to a directory, update `isdir` and the
   read-only filter consistently.
4. Add regression tests for `:e`/`:e!` on a directory, on an unreadable
   read-only buffer, and on a named file after `:set ro`; assert the reporter
   refresh.
