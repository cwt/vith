# `:s` moves the cursor to the end of the range even when that line had no substitution

**Category:** correctness (inherited) · **Area:** `vith/commands/commands.py` (`substitute`) · **Found at:** deep review, hg rev 164 (2026-11-06)

## Summary

When a range is given (`:1,3s/…`), the cursor always lands on the **last line
of the range**, even if no line in it matched — vim places it on the last
line that *changed*. The deviation is already acknowledged in the test file.

## Evidence

* [`vith/commands/commands.py:744-745`](../../vith/commands/commands.py):
  `new_cursor_position_row = line_index_iterator[-1]` — no tracking of which
  lines actually changed.
* [`tests/test_substitute.py:57-63`](../../tests/test_substitute.py): a `FIXME`
  comment documents exactly this:
  "vim would have set the cursor position on last substituted line but we set
  the cursor position on the end_range even when there is not substitution
  there".

## Impact

Cursor jumps unexpectedly on no-op ranges (`:1,3s/nothing/else`) and on
ranges whose tail lines don't match; small but daily-driver annoyance.

## Fix direction

Track the last line whose transformed text differs from the original inside
the transform callback and use that row for the cursor (fallback to the first
range line when nothing changed). Cheap, local change to the existing
`transform_lines` loop.
