# Word spans slice mixed-script clusters (`iw`/`aw`/`*`/`#`/`w`-family)

**Category:** wrong span model (stem: cell-cluster contract, docs/bugs/thai.py header) · **Area:** `vith/thai_words.py` (`_WORD_CHUNK_RE`, `_word_spans_for_line`) · **Found at:** stem audit 2026-11-08 · **Fixed at:** hg rev 271

## Summary

The chunk regexes classify by codepoint class, so pure Thai runs are fine but a
Latin (or any non-Thai-base) cluster base with a Thai/Lao/generic `Mn` mark
becomes two adjacent spans:

```python
probes:
  "x abั de"  → touches `ั` orphaned onto the next span
  "ab́c"      → span (0,2)=`ab` + span (2,4)=`́c` — the accent `́` sliced from `b`
  iw col2     → returns (0, 2) → an `iw`/`daw` deletes the orphaned mark into
                a separate unpaired codepoint
```

Violates the module contract `vith/thai.py:5-12` ("edits never slice a cluster
in half") for cross-script mixed clusters; Thai-Thai lines were clean.

## Fix

`_word_spans_for_line` now normalizes through `_cluster_aligned_spans`: span
starts that sit on a combining mark walk back via `snap_to_cell_start`; span
ends extend over following combining marks; overlapping results merge
(**strictly** — spans that merely touch are Vi word boundaries and stay
separate; the first draft's `>=` merge collapsed adjacent Thai word spans and
regressed the motion fixtures).

## Tests
`tests/test_thai.py::test_word_spans_never_slice_clusters` — sweep over
mixed-script lines (`x abั de`, `ab́c`, `ที่ดิน`, `กังวล abc`) asserting no span
boundary lands on a combining mark. All pre-existing motion fixtures pass.
