# Unoptimized algorithms and state-loss inventory (Round 8)

**Category:** performance / memory · **Area:** `vith/commands/commands.py`, `vith/completion.py`, `vith/lexer.py`, `vith/layout.py` · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** fixed

## Findings

| # | Location | Issue | Evidence / impact |
| :-- | :-- | :-- | :-- |
| 1 | `commands.py:2881-2916` (`_global_execute_move_or_copy`) | `for line_id in marked_rows: cur_pos = next(...)` scans the growing list for every marked line, then `list.insert` shifts elements: O(m·n) for `:g/pat/m` and `:g/pat/t`. | Measured `:g/x/m 0` on an all-`x` buffer: **9 ms / 1k**, **30 ms / 2k**, **123 ms / 4k** lines (roughly quadratic); 20k lines is multi-second. Track `(id -> position)` or perform one stable partition instead. |
| 2 | `commands/ranges.py:227-265` (`replace_buffer_lines`) | Every range edit (`:s`, `:d`, `:y`, `:pu`, `:m`, `:t`, `:j`, `:sort`, `:retab`, `:g`) joins all lines and constructs a fresh `Document`, O(file size), even for a one-line change. | A `:s` on one line of a multi-MB file rebuilds the full text and invalidates all line caches; Vim edits the affected rows. Consider `Buffer.insert_text`/`delete` slices or a line-splice helper. |
| 3 | `commands.py:1226-1230` (`_format_register_preview`) | Runs three `str.replace` passes over the **entire** register text before truncating to 200 chars. A multi-MB yank copies/rewrites it three times for `:reg`. | Slice to `max_len` first, then escape; preserve the `...` marker. |
| 4 | `completion.py:63-80` (`DocumentWordsCompleter`) | Cache key `(len(lines), row, line_start, len(text)-len(line))` does not include non-cursor text. Two different documents (or edits on another line) with the same lengths collide; the completer can offer stale words. The docstring claims a text-around-cursor key, but only lengths are used. | Type a same-length replacement on a non-cursor line while keeping the cursor row/length; completions stay from the old line. Add a text hash/version for misses. |
| 5 | `lexer.py:112-122` (`_ensure_lexer`) | A failed content sniff (`_pygments_lexer is None`) is cached for the location. An initially empty extensionless file that the user then types Python into never gets highlighting until the location or `filetype_override` changes. | The cache condition short-circuits on `_STREAMING_AVAILABLE` and returns `False` without re-sniffing. Retry when the text version changes, or key the cache on a text hash. |
| 6 | `layout.py:651-693` (`EditorLayout.update`) | `_frames` is cleared and only the active tab's frames are recreated. Switching tabs discards the other tab's `Window`/`BufferControl` objects, losing vertical scroll position and re-lexing/re-rendering from scratch. | Keep a per-tab frame cache or key frames by `(tab, window, buffer)` and retain inactive tabs. |
| 7 | `thai/patches.py:292-340` (`_sanitize_and_invalidate_sara_am`) | Once the sticky Thai gate is latched, every frame scans every cell of every row even after all Thai text is gone; `reset_thai_text_gate_if_all_buffers_ascii` only decays on commands, not on a per-frame basis. | Already a known residual ([072](072.md), [082](082.md)); a buffer-set-aware decay on close/switch would avoid the full-screen scan in mixed sessions. |

## Fix direction

1. Replace the `:g` move/copy `next()` scan with an id→index map updated on insertion, or a single stable partition preserving Vim's order.
2. Add a row-splice helper to `ColdTextBuffer`/`Document` integration and use it for line-oriented commands; keep the full `Document` rebuild only for text replacement commands that actually change the whole buffer.
3. Truncate register previews before escaping.
4. Include a cheap text digest/version in the completer cache key; invalidate on `_text_version` changes.
5. Re-run `_sniff_lexer_for_location` when the buffer text version changes after a cached miss.
6. Preserve per-tab frames across tab switches; add a scroll-position regression test.
7. Consider decaying the Thai gate when all *visible* buffers become ASCII, and re-latch on message/search/focus changes (see [146](146.md)).
