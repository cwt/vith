# `TabPage._close_window` closes `active_window` instead of target `window` and mutates splits during iteration

**Category:** wrong logic / state corruption · **Area:** `vith/window_arrangement.py` (`TabPage.close_editor_buffer`, `TabPage._close_window`) · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

`TabPage._close_window(self, window)` has a broken `else:` branch for closing any window that is not currently `self.active_window`: it saves `original_active_window = self.active_window`, calls `self.close_active_window()` **without** setting `self.active_window = window` first, and then restores `self.active_window = original_active_window`[^src-wa]. In addition, `TabPage.close_editor_buffer` iterates the live generator `self._walk_through_windows()` while `_close_window` mutates the underlying split lists in place.

## Evidence

* [`vith/window_arrangement.py:148-166`](../../vith/window_arrangement.py)[^src-wa]:
  ```python
  def close_editor_buffer(self, editor_buffer):
      """
      Close all the windows that have this editor buffer open.
      """
      for split, window in self._walk_through_windows():
          if window.editor_buffer == editor_buffer:
              self._close_window(window)

  def _close_window(self, window):
      """
      Close this window.
      """
      if window == self.active_window:
          self.close_active_window()
      else:
          original_active_window = self.active_window
          self.close_active_window()
          self.active_window = original_active_window
  ```
* When `window != self.active_window`:
  1. `self.close_active_window()` removes `self.active_window` (`original_active_window`) from its parent split, leaving `window` (the window that was supposed to be closed) untouched in the split tree.
  2. `self.active_window = original_active_window` then sets `self.active_window` back to the window that was just deleted from the split tree, so later calls to `_get_active_split()` raise `Exception('active_window not found. Something is wrong.')`.
* In `close_editor_buffer`, `self._walk_through_windows()` yields directly from `for c in split:`. When `_close_window` deletes an element from `split` (`del active_split[index]`) or collapses a single-item split into its parent (`parent[index] = active_split[0]`), the list iterator skips the next sibling in `split`.

## Impact

Running `:bd` / `:bw` when another split (in the current tab or another tab) displays the closed buffer deletes the wrong window, leaves the closed buffer visible, and corrupts `TabPage.active_window` so subsequent split/close operations raise `Exception('active_window not found. Something is wrong.')`.

## Fix direction

1. In `TabPage._close_window(self, window)`: set `self.active_window = window` before calling `self.close_active_window()`, and only restore `original_active_window` if it is still present in `self.windows()`.
2. Materialize `list(self._walk_through_windows())` in `TabPage.close_editor_buffer` before mutating splits.
