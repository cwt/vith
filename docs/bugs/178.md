# Malformed `cold_text_compression` config crashes startup

**Category:** config / TOML / startup · **Area:** `vith/rc_file.py`, `vith/cold_text.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** open

## Summary

`apply_toml_config()` routes every typed option through `_validated_option`,
which reports and skips invalid values, but `cold_text_compression` falls
through to a bare `return value`.[^src-rc] The consumer,
`make_cold_text_compressor()`, immediately calls
`(name or DEFAULT).strip().lower()`,[^src-cold] so any non-string supplied in
`config.toml` (e.g. `cold_text_compression = 5`) raises `AttributeError` when
the first `EditorBuffer` is constructed — the editor cannot open any file.
This contradicts the config layer's documented "invalid values are reported,
never raised".

## Evidence

| Probe | Expected | Actual |
| :--- | :--- | :--- |
| `apply_toml_config(editor, {'editor': {'cold_text_compression': 5}})` | `False` + message (or coerced string) | returns `True`, sets `editor.cold_text_compression = 5` |
| `editor.load_initial_files([None])` afterwards | buffer created | `AttributeError: 'int' object has no attribute 'strip'` |

## Fix Direction

1. Validate `cold_text_compression` with `_validated_option` against the known
   backend names (`auto`/`zstd`/`zlib`/`lzo`/`none` — whatever the catalog
   declares), reporting and skipping invalid values like other string options.
2. Optionally harden `make_cold_text_compressor()` to coerce `str(name)` and
   fall back to the default on unknown types (defense in depth).
3. Add config-parsing regression tests for each invalid type (int, bool, list).
