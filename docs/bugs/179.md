# `fileformat` from config is a no-op

**Category:** config / file I/O · **Area:** `vith/rc_file.py`, `vith/editor_buffer.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** fixed
> **Resolution note (2026-11-23):** `EditorBuffer.__init__` now inherits the configured `editor.fileformat`.


## Summary

`apply_toml_config()` validates `[editor] fileformat` and assigns
`editor.fileformat`,[^src-rc] but `EditorBuffer.__init__` hardcodes
`self._fileformat = 'unix'`.[^src-eb] The `:set ff=dos` handler explicitly
updates both the editor and the active buffer,[^src-options] so config — which
is applied before any buffer exists — can never influence a buffer's line
endings. `:set ff?` is separately broken ([174](174.md)).

## Evidence

| After `apply_toml_config(... {'fileformat': 'dos'})` and `load_initial_files` | Expected | Actual |
| :--- | :--- | :--- |
| `editor.fileformat` | `dos` | `dos` |
| `active_editor_buffer.fileformat` | `dos` | **`unix`** |
| written file line endings | CRLF | LF |

## Fix Direction

1. Initialize `EditorBuffer._fileformat` from `editor.fileformat` (with a
   fallback to `'unix'` when no editor is attached), keeping the existing
   content-based auto-detection in `_read()` able to override it for real files.
2. Add a regression test that sets config `fileformat='dos'`, opens an untitled
   buffer, writes it, and asserts CRLF output; also assert `:set ff?` reflects
   the same value once [174](174.md) is fixed.
