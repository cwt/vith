# Cell-cluster edits bypass read-only

**Category:** key bindings / read-only · **Area:** `vith/key_bindings.py` · **Found at:** Round 17 read-only re-audit (2026-11-23, `v0.16.4`) · **Fix status:** open

## Summary

Within one module the edit guards are inconsistent:[^src]

* guarded: `s` (`vi_navigation_mode & ~is_read_only`), `>>`/`<<`, `o`/`O`, Insert `enter`.
* unguarded: `x`/`X` (`vi_navigation_mode` only), `~` (`vi_navigation_mode & ~tilde_operator_enabled`), counted `i`/`a` (`in_navigation_mode & ~vi_waiting_for_text_object_mode`).

`in_navigation_mode` is `vi_navigation_mode & vi_buffer_focussed` with no read-only component, so the unguarded bindings fire in read-only buffers (help, explorer, `:set ro`). The `s` precedent shows the intended pattern.

## Evidence

* `vith/key_bindings.py:484-496` — `x`/`X` vs `s` filters side by side.
* `vith/key_bindings.py:545-546` — `~` filter has no `~is_read_only`.
* `vith/key_bindings.py:514-526` — `i`/`a` counted-entry filters have no `~is_read_only`.

## Fix Direction

1. Add `& ~is_read_only` to the `x`/`X`/`~`/`i`/`a` filters (keeping the existing `vi_waiting_for_text_object_mode` / `tilde_operator_enabled` terms).
2. Regression test: in a read-only buffer the handlers do not fire (focus a `read_only=True` buffer and feed `x`, `~`, `i`).
