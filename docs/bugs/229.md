# Readability, coding-style (`lambda`), and `mypy --check-untyped-defs` inventory (Round 18)

**Category:** readability / static typing · **Area:** `vith/layout.py`, `mypy.ini`, `vith/window_arrangement.py`, `vith/completion.py`, `vith/editor.py`, `vith/editor_buffer.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** fixed (hg rev 485)

## Findings

| # | Location | Issue | Evidence |
| :--- | :--- | :--- | :--- |
| 1 | `vith/layout.py:886` (`EditorLayout._create_buffer_control`) | Passes `on_focus=on_focus if on_focus is not None else lambda: None`, using an anonymous `lambda` instead of a named no-op function (or making `_on_focus` optional on `_FocusSyncingBufferControl`).[^src-layout] | Only `lambda` in `vith/` (`rg '\blambda\b' vith`). |
| 2 | `mypy.ini`, `vith/window_arrangement.py:48,209`, `vith/completion.py:138,153`, `vith/editor.py:308,331,484`, `vith/editor_buffer.py:612`, `vith/layout.py:129,148` | `mypy .` prints `note: By default the bodies of untyped functions are not checked, consider using --check-untyped-defs` because `mypy.ini` omits `check_untyped_defs = True`.[^src-mypy] Enabling `--check-untyped-defs` on `vith/` uncovers **9 type errors across 5 files**, notably: (a) `TabPage.active_window` is annotated `Window` rather than `Window | None`, masking `self.active_window = None` in `close_active_window` (`L209`) and unguarded `tab.active_window.editor_buffer` access in `TabsControl` (`vith/layout.py:109`); (b) `completer` in `DocumentCompleter.get_completions` is narrowed to `_PythonCompleter` before assigning `DocumentWordsCompleter`, whose 3-arg `get_completions(document, complete_event, version=None)` also conflicts with `Completer`.[^src-wa][^src-comp][^src-ed][^src-eb] | `poetry run mypy --check-untyped-defs vith` → `Found 9 errors in 5 files (checked 46 source files)`. |
| 3 | `vith/window_arrangement.py:99,106,189` (`_get_active_split`, `_get_split_parent`, `close_active_window`) | Compares `Window` and `HSplit`/`VSplit` container nodes using value equality (`window == self.active_window`, `child == split`, `active_split != self.root`) instead of identity (`is` / `is not`). Because `HSplit` and `VSplit` subclass `list`, `list.__eq__` compares element contents and ignores subclass type (`HSplit([]) == VSplit([])` is `True`).[^src-wa] | Structural identity checks in tree traversal should use `is` / `is not`. |

## Fix Direction

1. Make `on_focus: Callable[[], None] | None = None` optional in `_FocusSyncingBufferControl` (or define `def _noop() -> None: pass`) and remove `lambda: None` from `vith/layout.py:886`.
2. Fix the 9 type issues across `window_arrangement.py` (including guarding `tab.active_window` in `TabsControl`), `completion.py`, `editor.py`, `editor_buffer.py`, and `layout.py`, and enable `check_untyped_defs = True` in `mypy.ini`.
3. Replace `==` / `!=` with `is` / `is not` when matching `Window` and `HSplit`/`VSplit` nodes by identity in `TabPage`.
