# `:substitute` runs a per-match char-by-char Python callback even for literal replacements and plain backreferences

**Category:** performance / regex · **Area:** `vith/commands/substitution.py` · **Found at:** Round 10 deep performance audit (2026-11-22, `v0.15.1` / rev 392) · **Fix status:** fixed

> **Resolution note (2026-11-22):** Updated `_vim_replacement_function` in `vith/commands/substitution.py` to coalesce literal text runs and emit a C-level `re.sub` template string (`\\`, `\g<n>`) whenever no case operators (`\u`/`\U`/`\l`/`\L`/`\e`/`\E`) are present, and to apply chunk-level `.upper()`/`.lower()` without nested closures when case ops are used. Also replaced `_has_overlapping_alternatives`'s $O(A^2)$ pairwise scan with $O(A \log A)$ sorted adjacent-prefix checking. Verified with `tests/test_round10_perf.py`.

## Summary

`_vim_replacement_function` (`vith/commands/substitution.py:170-252`) unconditionally returns a Python callable `expand(match)` for `pattern.subn(...)`:[^src-sub]

1. Plain replacement strings (95%+ of real `:s` commands) are tokenized into **1-character `('text', ch)` tuples** (`'replacement_value'` → 17 tuples).
2. On **every regex match**, `re.subn` leaves C, invokes `expand(match)`, constructs a nested `emit()` closure, loops character-by-character testing four case-mode branches (`\u`/`\l`/`\U`/`\L`), appends 1-character strings to `pieces`, and joins them.
3. Separately, `_has_overlapping_alternatives` (`vith/commands/substitution.py:33-40`) compares all $O(A^2)$ pairs of alternation branches instead of sorting and checking adjacent pairs in $O(A \log A)$.[^src-sub]

## Evidence

Measured on `Python 3.15.2`:

| Workload | Current callback | C-level `re.subn(template_str)` | Speedup |
| :--- | ---: | ---: | ---: |
| `:%s/foo/replacement_value/g` (10k lines, 50k matches) | 85.49 ms | 2.32 ms | **36.8×** |
| `:%s/foo/replacement_value/g` (50k lines, 250k matches) | **428.03 ms** | **11.26 ms** | **38.0×** |
| `:%s/(\w+)/[\1]/g` (20k lines, backreference) | **103.88 ms** | **18.11 ms** | **5.7×** |

## Fix Direction

1. When parsed replacement tokens contain **no** `'case'` operators (`\u`/`\U`/`\l`/`\L`/`\e`/`\E`), compile directly into a Python `re.sub` template string (`\` escaped as `\\`, `('group', n)` emitted as `\g<n>` — noting that unmatched optional groups in Vim expand to `''`, whereas `\g<n>` on an unmatched optional group raises `re.error` in Python `re` when `pattern.groups > 0`; therefore use a template string directly for zero-group/whole-match-only `\g<0>` replacements and fall back to a coalesced fast callable when numbered groups `1..9` are present so unmatched optional groups remain `''`!).
2. For callable replacements (case ops or optional numbered groups), coalesce adjacent `'text'` tokens into single strings at parse time and apply whole-chunk `.upper()`/`.lower()` when `one_shot is None` instead of iterating character-by-character with a nested `emit()` closure per match.
3. Sort alternatives in `_has_overlapping_alternatives` and check only adjacent pairs ($O(A \log A)$).
