# `:wq` / `ZZ` exit the application instead of closing a window

**Category:** wrong logic / data loss · **Area:** `vith/commands/commands.py` (`write_and_quit`, `quit`, `close_window`), `vith/key_bindings.py` (`ZZ`) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** open

## Summary

The quit family has three divergences:

| Command | Vith | Vim |
| :--- | :--- | :--- |
| `:wq` with several windows | writes the active buffer, then `application.exit()` — **all other windows and their unsaved changes are discarded** | writes the active buffer and closes the current window; other windows remain |
| `ZZ` | bound to `write_and_quit` (always writes) | equivalent to `:x`: write only if modified, quit/close |
| `:q` with a dirty buffer visible in two windows | blocks with `E37` | closes the current window because the buffer remains visible in the other window |
| `:close` with the same dirty buffer | correctly closes one window (visible-count check) | same |

The first row is a **data-loss path**, not just a UX difference.

## Evidence

### `:wq` bypasses `quit()`

```python
@location_cmd('wq', accepts_force=True)
def write_and_quit(editor, location, force=False):
    if write(editor, location, force=force):
        editor.application.exit()
```

([`vith/commands/commands.py:1044-1050`](../../vith/commands/commands.py#L1044-L1050)).

`quit()` is the function that implements the multi-window rule
([`:730-760`](../../vith/commands/commands.py#L730-L760)), but
`write_and_quit()` never calls it. `:x` does call it
([`:1031-1041`](../../vith/commands/commands.py#L1031-L1041)), which is why
`:x` behaves correctly while `:wq` does not.

Probe: two windows with two dirty buffers (`A`, `B`), active `A`, then `:wq`:

```text
windows before :wq     2
application.exit()     called once
B.is_dirty             still True (in-memory only; process exits in a real session)
```

Vim closes window `A` and leaves `B` open; vith exits and loses `B`.

### `ZZ` always writes; `:x` writes only when modified

`ZZ` is bound to `write_and_quit`
([`vith/key_bindings.py:428-436`](../../vith/key_bindings.py#L428-L436)).
Probe on a clean named file: `ZZ` still calls `EditorBuffer.write()`
(observed as one `write(None, force=False)` call). Vim's `ZZ` is `:x` and
does not touch an unmodified file.

Probe on a clean **unnamed** buffer:

```text
ZZ -> no exit, message 'No file name'
```

Vim's `ZZ` exits. This also breaks the symmetric `ZQ` behavior.

### `:q` over-blocks a dirty buffer that is visible elsewhere

`quit()` checks only the active buffer's dirty flag
([`:747-753`](../../vith/commands/commands.py#L747-L753)), while
`close_window()` computes a cross-tab `visible_count`
([`:351-364`](../../vith/commands/commands.py#L351-L364)).

Probe (same modified buffer shown in two splits):

```text
:close -> windows 2 -> 1, no message   (correct)
:q     -> windows 2 -> 2, 'No write since last change (add ! to override)'
```

Vim allows `:q` here because closing one window does not lose the buffer.

## Impact

* `:wq` / `ZZ` can silently discard unsaved changes in every other window,
  tab, or hidden buffer.
* `ZZ` changes the modification time of clean files and cannot quit an
  unnamed clean buffer.
* `:q` refuses an operation that Vim permits, forcing `:close` or `!`.

## Fix direction

1. Extract a shared `close_or_exit(force)` helper used by `:q`, `:wq`, `:x`,
   and `ZZ`, reusing `:close`'s `visible_count` rule.
2. Bind `ZZ` to `write_if_modified_and_quit` (`:x`), not `write_and_quit`.
3. Before `application.exit()`, run the same all-buffer dirty check that
   `:qa` uses; `:wq` must never bypass it.
4. Add tests for: two windows with two dirty buffers, the same dirty buffer in
   two windows, `ZZ` on a clean named file, and `ZZ` on a clean unnamed buffer.
