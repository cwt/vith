# Environment variables (`%VAR%` / `$VAR`) not expanded in file paths

**Category:** I/O & Ex commands / Windows compatibility · **Area:** `vith/io/backends.py`, `vith/editor_buffer.py`, `vith/window_arrangement.py`, `vith/commands/`, `vith/rc_file.py`, `vith/editor.py` · **Found at:** user field report on Windows 11 + PowerShell (`v0.16.2` / rev 438) · **Fix status:** fixed

> **Resolution note (2026-11-23):** Added `expand_env_vars` and `expand_location` in `vith/io/backends.py` (wrapping `os.path.expandvars` + `os.path.expanduser` while leaving `scheme://...` URLs untouched) and routed all path-handling sites through them: `FileIO`/`GZipFileIO`/`DirectoryIO`, `EditorBuffer` creation/writes/`normalize_write_target`, `WindowArrangement._get_or_create_editor_buffer` (pre-deduplication), Ex commands (`:e`, `:w`, `:w >>`, `:r`, `:cd`, `:so`, `:sp`, `:vsp`, `:tabe`, `:sav`, `:f`, and `%:p`), command-line path completion (`_EnvPathCompleter`), `rc_file.py` (`-u`/`:so`/hooks/config discovery), and `Editor.config_directory`. Added `_match_windows_env_var` in `vith/commands/handler.py` so `%VAR%` for defined Windows environment variables expands cleanly in Ex location arguments (and passes through literally in `:!` shell commands) without breaking Vim's `%`/`%:p` filename tokens. Verified live against `%APPDATA%\alacritty\alacritty.toml` (27 lines) and pinned with unit/integration tests in `tests/test_io_backends.py`.

## Summary

Running `vim %APPDATA%\alacritty\alacritty.toml` on Windows PowerShell opens `C:\Users\<user>\AppData\Roaming\alacritty\alacritty.toml`, whereas `vith %APPDATA%\alacritty\alacritty.toml` opened an empty `[New file]` buffer with the literal path `%APPDATA%\alacritty\alacritty.toml`.[^src-backends]

Two separate gaps caused this behavior:

1. **No environment-variable expansion in I/O and path helpers.** PowerShell (`pwsh`) uses `$env:VAR` and passes `%VAR%` tokens verbatim in `sys.argv` (as does Git Bash; inside Ex commands and TOML config files no shell is involved at all). `vith` only expanded `~` via `os.path.expanduser` and never called `os.path.expandvars`.
2. **Ex command `%` filename token collision on Windows.** In `vith/commands/handler.py:expand_command_filenames`, every unescaped `%` was treated unconditionally as Vim's current-buffer filename token, so `:e %APPDATA%\alacritty\alacritty.toml` either failed with `E499: Empty file name for '%'` on an untitled buffer or substituted the current filename in place of both `%` delimiters.[^src-handler]

## Evidence

* Verified against installed Vim 9.2 on Windows 11: `vim %APPDATA%\alacritty\alacritty.toml` and `vim $APPDATA\alacritty\alacritty.toml` expand the environment variable and store the resolved path on the buffer.
* Live probe on `vith` after the fix:
  * `Editor.load_initial_files([r'%APPDATA%\alacritty\alacritty.toml'])` → `eb.location == 'C:\\Users\\cwt\\AppData\\Roaming\\alacritty\\alacritty.toml'`, `eb.is_new is False`, 27 lines loaded.
  * `handle_command(editor, r':e %APPDATA%\alacritty\alacritty.toml')` from an untitled buffer → opens the same file (27 lines) without `E499` and deduplicates against the existing buffer.
  * `expand_env_vars('https://example.com/$VITH_TEST_ROOT')` and `expand_location('http://example.com/%VITH_TEST_ROOT%/a')` preserve URLs untouched.
  * `expand_command_filenames(r'echo %VITH_TEST_APPDATA% %', editor, shell_escape=True)` preserves `%VITH_TEST_APPDATA%` for the shell while still expanding the trailing Vim `%` token.

## Fix Direction

1. Export `expand_env_vars(location)` and `expand_location(location)` from `vith/io/backends.py` (re-exported in `vith/io/__init__.py`, keeping `_expand_location = expand_location`), skipping expansion whenever `'://' in location`.
2. Apply `expand_env_vars` / `expand_location` consistently in `EditorBuffer`, `WindowArrangement._get_or_create_editor_buffer`, `vith/commands/files.py`, `vith/commands/completer.py` (`_EnvPathCompleter`), `vith/rc_file.py`, and `vith/editor.py`.
3. In `vith/commands/handler.py`, recognize `%VAR%` on Windows (`os.name == 'nt'`) via `_match_windows_env_var` when `VAR` is present in `os.environ` (and contains no `/`, `\`, or `:`), expanding it for path arguments and passing it through literally for shell arguments (`shell_escape=True`), plus calling `expand_env_vars` on location variables in `_expand_variables` and `:p`.
4. Add unit and integration tests in `tests/test_io_backends.py`.[^src-tests]
