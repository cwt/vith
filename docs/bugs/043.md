# Inclusive Vi motions (`dge`, `dgE`, `df`, `dt`, `dT`) slice Thai/Lao cell clusters and fuse combining marks

**Category:** wrong logic / Thai support · **Area:** `vith/thai.py`, `vith/key_bindings.py` · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

While `vith/key_bindings.py` overrides `e` and `E` in Normal mode (`vi_navigation_mode`) and `de`/`dE`/`ce`/`cE`/`ye`/`yE` in operator-pending mode (`vi_waiting_for_text_object_mode`)[^src-kb], other `TextObjectType.INCLUSIVE` motions in `prompt_toolkit/key_binding/bindings/vi.py` remain unpatched and rely on single-codepoint `+ 1` / `- 1` arithmetic:

1. **Backward word-end (`ge`, `gE`)**: `_ge` and `_gE` (`prompt_toolkit/key_binding/bindings/vi.py:1303-1324`) compute `TextObject(prev_end - 1, type=TextObjectType.INCLUSIVE)` where `prev_end` comes from `Document.find_previous_word_ending`[^src-thai]. Because `prev_end - 1` lands on the last combining mark of the previous word and `TextObject.operator_range` (`vi.py:165-166`) adds `end += 1` codepoint at the starting cursor, `dge` / `dgE` / `cge` / `cgE` slice both the target cluster and the starting cluster in half.
2. **Character search (`f`, `t`, `T`)**: Forward `f<char>` (`vi.py:1405`) returns `TextObject(match, type=TextObjectType.INCLUSIVE)`, whose `operator_range` (`end += 1`) includes only the matched base consonant and orphans its combining marks. Forward `t<char>` (`vi.py:1426`) returns `TextObject(match - 1, type=TextObjectType.INCLUSIVE)` (works only because `end += 1` cancels `- 1`, whereas in Normal mode `t<char>` lands on `match - 1` before `_kp_fix_vi_cursor_position` snaps it), and backward `T<char>` (`vi.py:1443`) returns `TextObject(match + 1)` which lands on the first combining mark of the matched base character.

## Evidence

* **Live probe (`dge` on `"ที่ ดิน"` from `'ด'` at index 4)**:
  ```text
  Initial buffer: "ที่ ดิน" (['ท', '◌ี', '◌่', ' ', 'ด', '◌ิ', 'น']), cursor_position = 4 ('ด')
  Keys fed:       'd', 'g', 'e'
  Result buffer:  "ทีิน" (['0xe17', '0xe35', '0xe34', '0xe19'])
  ```
  `_ge` computes `start = -2` (index 2, `'◌่'` of `"ที่"`) with `TextObjectType.INCLUSIVE`. `TextObject.operator_range` returns `(-2, 1)`, deleting slice `[2:5]` (`'◌่'`, `' '`, `'ด'`) and fusing `'ท' + '◌ี'` with `'◌ิ' + 'น'` into the invalid sequence `'ทีิน'`.
* **Live probe (`dfด` on `"ที่ดิน"` from `'ท'` at index 0)**:
  * `find_next_matching_line_character('ด')` returns `match = 3` (index 3, `'ด'`).
  * `TextObject(3, type=TextObjectType.INCLUSIVE).operator_range(doc)` returns `(0, 4)`, deleting `"ที่ด"` and leaving orphaned `'◌ิน'` (`['0xe34', '0xe19']`) at the start of the buffer.

## Impact

Using `dge`, `dgE`, `cge`, `cgE`, `df<c>`, `cf<c>`, `dT<c>`, or `cT<c>` on Thai or Lao text splits cell clusters and leaves orphaned or fused combining marks.

## Fix direction

1. Patch `TextObject.operator_range` in `vith/thai.py` (when `_THAI_GATE.value` is active) so that `TextObjectType.INCLUSIVE` advances the upper bound (`end`) to the end of the cell cluster at `end` (`next_cell_offset(line, col, 1)`) rather than `end += 1`, and snaps the lower bound (`start`) to the cell-cluster start (`prev_cell_offset`) if it falls on a combining mark.
2. Override or adjust `ge` / `gE` and `T<char>` so their target offset is the start of the cell cluster (`prev_cell_offset` / `next_cell_offset`) rather than `prev_end - 1` or `match + 1`.
