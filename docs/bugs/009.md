# Command-line grammar regex built from an unordered set

**Category:** determinism · **Area:** `vith/commands/grammar.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Summary

`COMMAND_GRAMMAR` interpolates `%(commands_taking_locations)s` with a
`'|'.join(...)` over a **set** of command names; Python set iteration order
varies per interpreter, so the compiled grammar differs between runs.

## Evidence

* [`vith/commands/grammar.py:46-48`](../../vith/commands/grammar.py):
  `% { 'commands_taking_locations': '|'.join(get_commands_taking_locations()) }`.
* `get_commands_taking_locations()` returns the module-level **set** verbatim
  ([`vith/commands/commands.py:41-42`](../../vith/commands/commands.py), set at
  `commands.py:17`).
* Semantics are usually rescued by backtracking (prefix pairs like
  `sp`/`split`, `o`/`open`, `w`/`write` still match correctly because the
  follow-up `\s+` forces a re-match), but with an unordered alternation any
  future addition of a command that is a strict prefix of another can change
  precedence between runs.

## Impact

Non-reproducible command parsing across interpreter runs; debugging grammar
issues is needlessly hard.

## Fix direction

`'|'.join(sorted(get_commands_taking_locations()))` — one-word fix making the
alternation deterministic.
