# Split-brain registers between Normal mode and Ex commands

**Category:** commands / registers · **Area:** `vith/commands/common.py`, `vith/commands/editing.py`, `vith/commands/info.py` · **Found at:** Round 18 full-project audit (2026-11-24, `v0.16.5`, hg rev `458:d2d313328875`) · **Fix status:** fixed (hg rev 461)

## Summary

Named registers live in two disconnected dictionaries: `editor.application.vi_state.named_registers` (used by `prompt_toolkit` Normal/Visual `"ay`, `"ad`, `"ap`) and `editor.registers` (used by Ex `:d {reg}`, `:y {reg}`, `:put {reg}`).[^src-store][^src-put][^src-editor] This split causes five user-visible defects:

1. **Normal yank → Ex `:put` fails:** Yanking into `"a` in Normal mode populates `vi_state.named_registers['a']`, after which `:put a` checks only `editor.registers.get('a')` and fails with `E353: Nothing in register a`.
2. **Ex `:y` / `:d` → Normal `"ap` misses content:** `:y a` writes `editor.registers['a']` without updating `vi_state.named_registers['a']`, so Normal-mode `"ap` pastes nothing or stale content.
3. **Duplicate rows in `:registers`:** `registers_lines()` iterates `vi_state.named_registers` and then `editor.registers` without deduplicating, displaying two conflicting `"a` lines simultaneously.[^src-info]
4. **Explicit unnamed register `:put "` fails:** `_register_name()` explicitly permits `"` (`name in ('"', '0')`),[^src-reg] returning `register == '"'`. `put_lines()` tests `if register:` and looks up `editor.registers.get('"')` instead of reading `editor.application.clipboard.get_data()`, failing with `E353: Nothing in register "`.
5. **Uppercase register append (`A`–`Z`) missing:** `:y A` / `:d A` creates a separate `'A'` key instead of appending linewise to register `'a'` (Vim convention).

## Evidence

Live probe against shipped `Editor`, `handle_command`, and `registers_lines`:

| Step | Action | Expected | Actual |
| :--- | :--- | :--- | :--- |
| 1 | Populate `vi_state.named_registers['a'] = ClipboardData('normal yanked', LINES)` then `:put a` | Inserts `'normal yanked'` | `'E353: Nothing in register a'` |
| 2 | Run `:1y a` on `"line one\nline two"`, then call `registers_lines(editor)` | Single `"a` entry (`'line one'`) | Two `"a` rows: `'  l  "a   normal yanked'` and `'  l  "a   line one'` |
| 3 | Run `:put "` after `:1y a` | Inserts `'line one'` from unnamed clipboard | `'E353: Nothing in register "'` |

## Fix Direction

1. Unify named-register storage on `editor.application.vi_state.named_registers` (`ClipboardData(..., SelectionType.LINES)`) and retire the separate `editor.registers` dict (or keep it purely as a view/fallback when `application` is absent).
2. In `store_lines_in_register`, map `'A'..'Z'` to append onto `'a'..'z'`, and map `'"'` to the unnamed clipboard only.
3. In `put_lines`, treat `register in ('', '"')` as the unnamed clipboard (`clipboard.get_data()`), and read named registers from `vi_state.named_registers`.
4. Deduplicate `registers_lines()` so each register name appears at most once.
