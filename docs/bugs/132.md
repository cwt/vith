# `:only` / `:tabonly` / `:tabclose` ignore scope and dirty guards

**Category:** wrong logic / window and tab lifecycle · **Area:** `vith/commands/commands.py`, `vith/window_arrangement.py` · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** fixed

## Summary

Three related commands mutate the tab/window arrangement with the wrong scope:

| Command | Vith | Vim |
| :--- | :--- | :--- |
| `:only` | replaces `tab_pages` with one new `TabPage`; **all other tab pages disappear** | closes other windows **in the current tab only**; other tab pages stay |
| `:only` with a dirty buffer in another window | silently closes it | `E445: Other window contains changes` unless `!` |
| `:tabonly` | `tab_pages = [active_tab]`, force ignored, no dirty check | `E37` if another tab contains a modified buffer unless `!` |
| `:tabclose` | removes the active tab, force not accepted, no dirty check | `E37` when the tab's buffer is modified and it is the last window for it |

No buffer contents are destroyed by `:only`/`:tabonly`/`:tabclose` in vith —
the buffers stay in `editor_buffers` — but tab layout and window state are
discarded without the Vim warnings, and `:only` loses entire tabs that were
not in scope.

## Evidence

### `:only` closes tab pages

```python
def keep_only_current_window(self):
    if self.active_tab is None or self.active_tab.active_window is None:
        return
    self.tab_pages = [TabPage(self.active_tab.active_window)]
    self.active_tab_index = 0
```

([`vith/window_arrangement.py:336-343`](../../vith/window_arrangement.py#L336-L343);
called by `only()` at [`vith/commands/commands.py:327-333`](../../vith/commands/commands.py#L327-L333)).

Probe:

```text
tabs before :only  2
tabs after  :only  1      # tab 2 was discarded
```

Vim with two tabs and a split in the active tab keeps **both** tab pages and
closes only the other window in the active tab.

### `:tabonly` and `:tabclose` skip the dirty guard

`keep_only_current_tab()` and `close_tab()` only rewrite `tab_pages`
([`vith/window_arrangement.py:302-354`](../../vith/window_arrangement.py#L302-L354)).
`tab_only()` accepts `force` but never forwards it
([`vith/commands/commands.py:1393-1399`](../../vith/commands/commands.py#L1393-L1399));
`tab_close()` accepts no force at all
([`:1366-1372`](../../vith/commands/commands.py#L1366-L1372)).

Probe with a modified buffer in a second tab:

```text
:tabonly  -> tabs 2 -> 1, message None, modified buffer still dirty in memory
:tabclose -> tab removed,      message None, modified buffer still dirty in memory
```

Vim reports `E37: No write since last change` for both unless `!` is supplied.
The modified content is not lost because the buffer remains loaded, but the
user is given no warning and loses the tab layout.

## Impact

* `:only` unexpectedly destroys unrelated tab pages (common after opening
  several `-p` tabs).
* `:tabonly` / `:tabclose` silently close windows around unsaved work.
* Tests only assert the happy-path window count for `:only`
  ([`tests/test_ex_commands.py:113-119`](../../tests/test_ex_commands.py#L113-L119))
  and never cover other tabs or dirty buffers.

## Fix direction

1. Implement `:only` per tab: collapse `self.active_tab.root` to the active
   window (or a one-window `TabPage`) while preserving `self.tab_pages` for
   other tabs.
2. Reuse `_confirm_unsaved_changes` for `:only`/`:tabonly`/`:tabclose`, and
   report `E445`/`E37` when a modified buffer would lose its last visible
   window/tab.
3. Forward `force` from `tab_only()` and add `accepts_force=True` to
   `:tabclose`/`:tabc`.
4. Add tests with two tabs, splits in each, and a dirty buffer in the
   non-active tab.
