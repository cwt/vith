# Second `find_closest_generator` scan in `DocumentLexer.get_generator` is unreachable

**Category:** dead code · **Area:** `vith/lexer.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* [`vith/lexer.py:125-141`](../../vith/lexer.py):
  `get_generator(i)` first calls `find_closest_generator(i)` (line 126) and,
  when it returned `None`, computes the sync position and then calls
  `find_closest_generator(i)` **again** (line 134) before creating a
  generator.
* Between the two calls nothing inserts into `line_generators`
  (`syntax_sync.get_sync_start_position` reads only the document), so the
  second scan always returns `None` when the first one did.

## Impact

Dead scan inside the hot render path; confusing for readers of the P1
streaming implementation.

## Fix direction

Remove the second call and the `if not generator:` check, or intentionally
populate `line_generators` around the sync step if a future reuse plan
warrants it.
