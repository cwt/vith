# `:sort n` breaks ties lexicographically

**Category:** commands / sort · **Area:** `vith/commands/editing.py` · **Found at:** Round 11 deep correctness audit (2026-11-23, `v0.16.0` / rev 410) · **Fix status:** fixed
> **Resolution note (2026-11-23):** Removed the line-text component from numeric sort keys (stable ties) and reversed the whole sorted list for `!` before deduplication.


## Summary

`sort_lines()` builds its numeric-sort key as `(1, int(match.group(0)), part)`
and `(0, 0, part)` for lines with no leading number.[^src-editing] Including the
whole line as a final key means equal-numbered lines are alphabetized, and all
non-numeric lines are alphabetized too. Vim's `:sort n` uses a *stable* numeric
comparison: ties keep their original relative order. Python's `sorted()` is
stable, so the fix is to omit the final text component.

## Evidence

| Buffer before | Vim `:sort n` | vith `:sort n` |
| :--- | :--- | :--- |
| `b2, a2, c2` | `b2, a2, c2` (unchanged) | `a2, b2, c2` |
| `c, a, b` | `c, a, b` (unchanged) | `a, b, c` |

Verified by direct `handle_command()` probe against the shipped 3-line buffer.

## Fix Direction

1. Change the numeric key to `(1, int(match.group(0)))` and the non-numeric
   key to `(0,)`, relying on Python's stable sort for ties.
2. Add regression tests for numeric ties, non-numeric lines, mixed lines, and
   the `!`/`u` flag combinations to pin Vim parity.
