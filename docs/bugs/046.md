# `ReporterError` lacks `__eq__`, defeating `report_errors != self.report_errors` deduplication in `run_reporter`

**Category:** wrong logic / performance · **Area:** `vith/reporting.py`, `vith/editor_buffer.py`, `tests/test_editor_buffer.py` · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

`EditorBuffer.run_reporter` (`vith/editor_buffer.py:242-245`)[^src-eb] compares `if report_errors != self.report_errors:` with the explicit comment `"only invalidate the UI when the errors actually changed"`. However, `ReporterError` (`vith/reporting.py:32-42`)[^src-rep] is a plain class without `__eq__` (logged as a known deviation in [`docs/speed_latency_plan.md §1.4`](../speed_latency_plan.md)).

Because `report()` constructs fresh `ReporterError` instances on every run, `report_errors != self.report_errors` evaluates to `False` **only** when both lists are empty (`[] == []`). Whenever a `.py` buffer has at least one `pyflakes` warning anywhere in the file, every keystroke produces new `ReporterError` instances that compare unequal (`is`-identity fallback), rebuilding `report_errors_by_lineno` and firing `get_app().invalidate()`.

Furthermore, `test_run_reporter_no_flicker_keeps_old_errors` (`tests/test_editor_buffer.py:153-184`)[^src-test] purports to test that `report_errors` are not republished unnecessarily, but line 176 resets `eb.report_errors = []` before the second run, testing only that the old list isn't cleared *before* the executor finishes rather than testing unchanged errors.

## Evidence

* [`vith/editor_buffer.py:241-245`](../../vith/editor_buffer.py)[^src-eb]:
  ```python
  # Swap errors in atomically and only invalidate the UI when the
  # errors actually changed.
  if report_errors != self.report_errors:
      self._set_report_errors(report_errors)
      get_app().invalidate()
  ```
* [`vith/reporting.py:32-42`](../../vith/reporting.py)[^src-rep]:
  ```python
  class ReporterError:
      def __init__(self, lineno, start_column, end_column, formatted_text):
          self.lineno = lineno
          self.start_column = start_column
          self.end_column = end_column
          self.formatted_text = formatted_text
  ```
* **Live probe**:
  ```python
  >>> from vith.reporting import ReporterError
  >>> [ReporterError(0, 0, 1, 'u')] == [ReporterError(0, 0, 1, 'u')]
  False
  ```

## Impact

In any `.py` file with $\ge 1$ `pyflakes` message, every keystroke triggers a background `get_app().invalidate()` and rebuilds `report_errors_by_lineno` even when the set of errors and their line/column positions did not change.

## Fix direction

Implement `__eq__` (or decorate `ReporterError` with `@dataclass` / value equality on `(self.lineno, self.start_column, self.end_column, self.formatted_text)`) in `vith/reporting.py`, and add a unit test in `tests/test_editor_buffer.py` verifying that `get_app().invalidate()` is not called when `run_reporter` produces identical `ReporterError` values.
