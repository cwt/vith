# Miscellaneous low-severity defects (Round 5)

**Category:** wrong logic / robustness · **Found at:** Round 5 audit, 2026-11-09, hg rev 256 · **Fix status:** open

## Findings

| # | Location | Defect | Evidence |
| :-- | :-- | :-- | :-- |
| 1 | `vith/commands/commands.py:650` | `buffer = editor.current_editor_buffer.buffer` — no `None` guard, while every sibling handler (`write`, `buffer_edit`, `cold_text_compression`, `_confirm_unsaved_changes`) uses `window_arrangement.active_editor_buffer`. | Probe: `handle_command(':s/foo/bar/i')` dispatched without a prior `sync_with_prompt_toolkit()` → `AttributeError: 'NoneType' object has no attribute 'buffer'`. `Editor.current_editor_buffer` (`editor.py:247-263`) returns `None` implicitly when `application.current_buffer` matches no editor buffer. Normal TUI focus restoration masks it; any programmatic/API dispatch is affected. |
| 2 | `examples/config/vithrc:70-86` | F9 handler: `if editor_buffer is not None:` guards only the `write()` block, but `run_in_terminal(execute)` is called unconditionally; `execute()` then dereferences `editor_buffer.location`. Also ignores `editor_buffer.write()`'s boolean return, so python3 runs even after a failed save. | With `editor.current_editor_buffer is None` → `AttributeError` inside the terminal callback. `[074](074.md)` rewrote this example and "verified it to compile", but not to run in this state. |
| 3 | `vith/style.py:42-45` | `_LazyStylesDict.__getitem__` caches `get_editor_style_by_name(name)`, which raises `pygments.util.ClassNotFound` (not `KeyError`) for an unknown name. `collections.abc.Mapping.__contains__` catches only `KeyError`, so `name in editor.styles` would raise instead of returning `False`. | Latent: current callers only iterate `__iter__` (`commands/completer.py:59`) or index known names. Any future membership check breaks. |
| 4 | `vith/editor_buffer.py:215` | `io.write(target_location, self.buffer.text + '\n', self.encoding)` always appends a trailing newline, even for a file that had none. No `:set noeol` / `:set fixeol` parity. | `_read` strips one trailing newline on load (`:149-150`), so round-tripping a no-EOL file silently changes it. |

## Fix direction

1. Use `editor.window_arrangement.active_editor_buffer` (with an explicit `None` guard) in `substitute`.
2. Move `run_in_terminal(execute)` inside the `is not None` branch and honour `write()`'s return value.
3. Have `__getitem__` raise `KeyError` for unknown names, or override `__contains__` to catch `ClassNotFound`.
4. Track the original EOL state on `EditorBuffer` and write accordingly (Vim `'endofline'`).
