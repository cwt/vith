# `EditorBuffer.write()` writes via the last I/O backend after its own 'Unknown location' message

**Category:** correctness · **Area:** `vith/editor_buffer.py` (`write`) · **Found at:** deep review, hg rev 164 (2026-11-06)

## Summary

`write()` scans editor I/O backends with a `for/else`; when no backend claims
the location it shows `Unknown location: …` **and then keeps executing**,
calling `io.write(...)` where `io` still binds the *last* backend from the
loop.

## Evidence

* [`vith/editor_buffer.py:160-177`](../../vith/editor_buffer.py): the `for … else`
  block (`editor.show_message('Unknown location: %r' % location)` in the
  `else`, line 164) has **no `return`/`raise`**; execution continues to
  `io.write(self.location, …)` on line 168.
* With the default backends from [`vith/editor.py:86-91`](../../vith/editor.py)
  (DirectoryIO, HttpIO, GZipFileIO, FileIO), any unrecognized scheme such as
  `ftp://host/file.txt` ends with `FileIO.write` creating a file literally
  named `ftp://host/file.txt` (slashes replaced by dir separators depending on
  `os.path`) in the current working directory.
* `EditorIO.can_open_location` returns `False` for unknown schemes
  ([`vith/io/backends.py:26-28`](../../vith/io/backends.py)), so the loop
  never breaks.

## Impact

Misleading message + unintended side effect file; the "Unknown location"
error message does not actually stop the operation the user attempted.

## Fix direction

`return` (or `raise`) inside the `for/else` fallthrough before the write.
