# `:s` replacement text uses Python `re` syntax

**Category:** wrong logic / Vim replacement semantics · **Area:** `vith/commands/commands.py` (`substitute`, `_global_execute_substitute`) · **Found at:** Round 8 full re-audit, 2026-11-19, hg rev 358 (`ff583fcf26ba`) · **Fix status:** fixed

## Summary

`substitute()` calls `pattern.subn(replace, original, ...)` directly
([`vith/commands/commands.py:2266-2278`](../../vith/commands/commands.py#L2266-L2278)).
`replace` therefore follows Python `re` replacement syntax, not Vim's:

| Input | Vim result | Vith result |
| :--- | :--- | :--- |
| `:s/foo/&X/` | `fooX` (`&` = whole match) | `&X` (literal ampersand) |
| `:s/foo/\&X/` | `&X` (escaped literal) | `\&X` (keeps backslash) |
| `:s/foo/a\r b/` | splits the line at `\r` | Python treats `\r` as a carriage return |
| `:s/foo/a\n b/` | `a` + NUL + ` b` | inserts a real newline and splits the line |

The same issue exists in the `:g`/`:v` substitute path because it shares the
`re.subn` call.

## Evidence

Probe on `foo bar`:

```text
:s/foo/&X/       -> '&X bar'      (Vim: 'fooX bar')
:s/foo/\&X/      -> '\\&X bar'    (Vim: '&X bar')
:s/foo/a\nb/     -> 'a\nb bar'    (Python newline; Vim: NUL, no line split)
```

The third case is not just cosmetic: it changes the document's line count
inside `replace_buffer_lines`, which can shift cursor/marks and is outside the
line-oriented model of `:s`.

Vim's replacement also supports `~` (previous replacement), `\u`/`\U`/`\l`/`\L`/
`\e`/`\E` case operators, and `\0`..`\9`/`&` backreferences. None of these are
implemented, while Python-only `\g<name>` syntax is accepted.

## Impact

* Common Vim idioms (`&`, `\&`, `\r`) silently produce wrong text.
* A user can accidentally split a line with `\n` and corrupt column/mark
  expectations.
* `:g/pat/s/.../` inherits the same deviations.

## Fix direction

1. Add a Vim-replacement-to-Python translator (or a small evaluator) before
   `subn`:
   * `&` → `\g<0>`, `\&` → literal `&`,
   * `\r` → `\n` (line split must be handled by the substitute row logic,
     not inside a single line),
   * `\n` → NUL/literal per Vim,
   * `~` → `editor.last_substitute_text`,
   * `\u`/`\U`/`\l`/`\L`/`\e`/`\E` case operators.
2. Decide and document how a replacement that introduces a newline is applied
   to the line model; preferably support `\r` as a proper line split and
   reject unsupported escapes with a message.
3. Add parity tests for `&`, `\&`, `~`, `\r`, `\n`, and case operators in both
   `:s` and `:g/.../s`.
