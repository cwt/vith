# TOML configuration format with modular hook registration

**Category:** feature / configuration modernization · **Area:** `vith/rc_file.py`, `vith/entry_points/run_vith.py`, `examples/config/` · **Found at:** user proposal to adopt declarative TOML configuration and modular hooks (2026-11-12) · **Fix status:** fixed

## Summary

`vith` originally inherited `pyvim`'s approach of executing an imperative Python script (`~/.vithrc`) defining a `configure(editor)` callback. While flexible for writing arbitrary Python logic, setting standard options (e.g. `number = true`, `colorscheme = "emacs"`, `tabstop = 4`) required writing Python code.

This improvement introduces full TOML configuration as the primary format, adhering to XDG standards (`~/.config/vith/config.toml`) with fallback to `~/.vithrc`, while cleanly separating declarative settings from imperative logic through an explicit hook registration mechanism (`[hooks] enabled = [...]`).

## Evidence

* Previously, `vith/rc_file.py` compiled and executed the file directly with `exec()`:
  ```python
  with open(rc_file, 'r', encoding='utf-8') as f:
      code = compile(f.read(), rc_file, 'exec')
      exec(code, namespace, namespace)
  ```
* Standard XDG path `~/.config/vith/config.toml` was not checked; only `~/.vithrc` and `~/.pyvimrc` were checked.
* Custom keybindings or helper callbacks could not be modularized into independent files.

## Fix

1. **Config File Discovery (`vith/rc_file.py:find_config_file`)**:
   * Evaluates configuration files in priority order:
     1. `$XDG_CONFIG_HOME/vith/config.toml` (or `~/.config/vith/config.toml`)
     2. `~/.vith/config.toml`
     3. `~/.vithrc` (TOML or Python)
     4. `~/.pyvimrc` (legacy Python fallback)
   * Command-line `-u <path>` takes precedence when provided.
2. **Dual-Format Parser (`vith/rc_file.py:run_rc_file`)**:
   * When loading a `.toml` file, it parses strictly via `tomllib` (or `tomli` on Python 3.10), reporting any syntax issues with human-friendly diagnostics.
   * For non-`.toml` filenames (e.g. `~/.vithrc`), it attempts TOML parsing first; if `TOMLDecodeError` occurs (e.g. `def configure(editor):`), it falls back to Python execution for 100% backward compatibility.
3. **Declarative Option Application (`vith/rc_file.py:apply_toml_config`)**:
   * Maps all Vim options and Python attributes under `[editor]` (or top-level): `number`, `relativenumber`, `hlsearch`, `incsearch`, `ignorecase`, `paste`, `ruler`, `wildmenu`, `expandtab`, `tabstop`, `scrolloff`, `list`, `wrap`, `breakindent`, `mouse`, `jedi`, `cursorline`, `cursorcolumn`, `colorcolumn`, `colorscheme`, `cold_text_compression`.
   * Maps per-filetype tabstops under `[tabstop]` / `[filetype_tabstops]`.
4. **Registered Hook Architecture (`vith/rc_file.py:run_hook_file`, `_resolve_hook_path`)**:
   * Python scripts placed in `~/.config/vith/hooks/` (or `<config_dir>/hooks/`) are only loaded if explicitly registered under `[hooks] enabled = [...]`.
   * Hooks run in an isolated namespace containing `editor` and can define `configure(editor)` to register custom key bindings (e.g. F9 terminal runners).
   * Unregistered hook files remain inactive.
5. **Examples & Documentation**:
   * Added `examples/config/config.toml` showcasing full TOML configuration.
   * Added `examples/config/hooks/build-and-run.py` demonstrating Python hook registration.
   * Updated `README.md` and `pyproject.toml`.
6. **Regression Tests (`tests/test_toml_config.py`)**:
   * 11 tests verifying search order, option mappings, colorcolumn formats, per-filetype tabstops, hook execution, registration enforcement, and backward compatibility.
