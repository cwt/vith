# Quadratic $O(K^2)$ whole-document join in `:render` HTML fallback (`_Renderer._ensure_block`)

**Category:** performance / algorithms · **Area:** `vith/commands/info.py` · **Found at:** Round 10 deep performance audit (2026-11-22, working tree `:render`) · **Fix status:** fixed

> **Resolution note (2026-11-22):** Replaced `_Renderer._ensure_block()`'s `''.join(self.parts)` with an $O(1)$ amortized backward scan over the last 2 non-empty characters, replaced block-tag tuple scans with module-level `frozenset`s, and precompiled Markdown/reStructuredText regexes and heading character sets in `vith/commands/info.py`. Verified with regression tests in `tests/test_round10_perf.py`.

## Summary

In `_render_html` (`vith/commands/info.py:591-603`), the pure-Python `HTMLParser` fallback `_Renderer` defines `_tail(self)` (`''.join(self.parts[-3:])`) to inspect trailing newlines, **never calls it**, and instead runs `tail = ''.join(self.parts)` inside `_ensure_block()` on **every block start tag** (`<p>`, `<div>`, `<li>`, `<tr>`, `<h1>`–`<h6>`, etc.).[^src-info] When `lynx`, `w3m`, and `html2text` are not installed (standard environment, and also reached from `_render_markdown` when the `markdown` package converts to HTML), every block element re-joins the entire output accumulated so far ($O(K^2)$).

Additionally, `_strip_markdown_inline`, `_render_markdown`, `_strip_rst_inline`, and `_render_rst` (`vith/commands/info.py:290-535`) call uncompiled `re.sub`/`re.match` inside per-line loops and repeatedly reconstruct `set('=-~^_*+#:."\'')` and `lines[i + 1].strip()` five times per line.[^src-info]

## Evidence

Measured on `Python 3.15.2` (fallback `HTMLParser` path, `lynx`/`w3m`/`html2text` absent):

| `<p>` elements (`K`) | Input size | `_render_html` time | Scaling ratio |
| ---: | ---: | ---: | :--- |
| 500 | 29 KB | 4.96 ms | baseline |
| 1,000 | 58 KB | 8.68 ms | 1.8× |
| 2,000 | 118 KB | 26.79 ms | 3.1× |
| 4,000 | 237 KB | **97.64 ms** | **3.65×** ($O(K^2)$) |

## Fix Direction

1. Use `self._tail()` (or track trailing newline count in $O(1)$) inside `_Renderer._ensure_block()`, and use a `frozenset` for block tag checks instead of linear tuple scans.[^src-info]
2. Pre-compile module-level regexes and character sets for the Markdown and reStructuredText renderers, and bind `next_stripped = lines[i + 1].strip()` once per line in `_render_rst`.[^src-info]
