# `Ctrl-[` does not exit insert mode

**Category:** Vim semantics · **Area:** `vith/key_bindings.py` · **Found at:** upstream triage 2026-11-09 (`prompt-toolkit/pyvim#134`) · **Fix status:** fixed

## Summary

In Vim, `Ctrl-[` is equivalent to `Esc`. In `vith` document buffers it does nothing.

## Evidence

* `create_key_bindings()` in `vith/key_bindings.py:146-398`[^src-kb] binds `escape` only for `has_focus(editor.command_buffer)` (`:232-242`); document insert-mode exit relies on `prompt_toolkit` defaults, which do not map `c-[`.
* No `c-[` (or `c-c`) binding exists for document buffers.

## Impact

* Terminal / Vim muscle-memory break; `Esc` is harder to reach on many layouts.

## Fix

* `Ctrl-[` and `Esc` emit the same byte (`\x1b`); `prompt_toolkit` exposes no separate `c-[` key (registering one raises `ValueError: Invalid key`), so the `escape` binding in `vith/key_bindings.py` is the correct fix point. The new `leave_insert_with_repeat` override (filter `in_insert_mode`) leaves insert mode for that byte, replicating the default cursor-left + selection-exit behavior.
* Regression test in `tests/test_key_bindings_fixes.py` pins the insert-mode `escape` override.
