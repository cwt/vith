# `reverse_case_cell` (`~`) overrides `:set tildeop` unconditionally and ignores `event.arg`

**Category:** wrong logic · **Area:** `vith/key_bindings.py` (`reverse_case_cell`) · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

`vith/commands/commands.py:673-685`[^src-cmd] implements `:set tildeop` (`:set top` / `:set notildeop`), which sets `editor.application.vi_state.tilde_operator = True` so that `~` acts as a Vi operator taking a motion (e.g. `~w`, `~e`, `~$`) via `prompt_toolkit/key_binding/bindings/vi.py:1138-1142`.

However, `reverse_case_cell` (`vith/key_bindings.py:265-280`)[^src-kb] binds `'~'` with `filter=vi_navigation_mode` without excluding `vi_tilde_operator`. Because `create_key_bindings` is merged after `load_vi_bindings()`, `reverse_case_cell` unconditionally shadows upstream's operator binding even when `:set tildeop` is active.

In addition, `reverse_case_cell` hardcodes `next_cell_offset(line, col, 1)` instead of `next_cell_offset(line, col, event.arg)`, so a count prefix like `3~` only toggles the case of 1 cell cluster instead of 3.

## Evidence

* [`vith/key_bindings.py:265-280`](../../vith/key_bindings.py)[^src-kb]:
  ```python
  @handle('~', filter=vi_navigation_mode)
  def reverse_case_cell(event):
      """Reverse case of the cell cluster under cursor and move one cell right."""
      buff = event.current_buffer
      doc = buff.document
      line = doc.current_line
      col = doc.cursor_position_col
      if col >= len(line):
          return
      span = next_cell_offset(line, col, 1) - col
      if span > 0:
          substr = line[col : col + span]
          buff.insert_text(substr.swapcase(), overwrite=True)
  ```
* [`vith/commands/commands.py:673-678`](../../vith/commands/commands.py)[^src-cmd]:
  ```python
  @set_cmd('tildeop')
  @set_cmd('top')
  def enable_tildeop(editor):
      "Enable the tildeop option."
      editor.application.vi_state.tilde_operator = True
  ```

## Impact

1. `:set tildeop` / `:set top` is broken (`~w` toggles the character under the cursor and moves one word forward instead of toggling the word's case).
2. Counted `~` (e.g. `5~`) ignores the count `5`.

## Fix direction

1. Gate `reverse_case_cell` on `vi_navigation_mode & ~Condition(lambda: get_app().vi_state.tilde_operator)` (using a named helper function per project style).
2. Replace `next_cell_offset(line, col, 1)` with `next_cell_offset(line, col, event.arg)`.
